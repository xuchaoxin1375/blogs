## MHTML 格式



 **MHTML ** 是一种**网页存档文件格式**，它将一个网页的 **HTML 代码**以及所有**伴随资源**（如图片、CSS 样式表、Flash 动画、Java 小程序等）封装并存储在**一个单一文件**中。

- **全称：** **MIME Encapsulation of Aggregate HTML Documents**（聚合 HTML 文档的 MIME 封装）。
- **用途：** 主要用于**离线浏览**。它解决了普通 HTML 页面保存时，资源文件（如图片）分散存储在单独文件夹中的问题。
- **文件扩展名：** 通常为 `.mht` 或 `.mhtml`。
- **技术基础：** 它采用与 **HTML 电子邮件**相同的 **MIME (Multipurpose Internet Mail Extensions)** 技术，使用 `multipart/related` 内容类型来组织文件中的各个部分。
  - 文件的第一部分通常是**电子邮件头信息**（包含元数据，如日期、URL 等）。
  - 第二部分通常是**HTML 代码**。
  - 后续部分是网页中引用的**外部资源**，这些资源通常使用 **Base64 编码**嵌入在文件中。
- **优势：** 方便管理和分享，因为所有的网页内容都包含在一个文件中。

## MHTML 和 HTML 格式的可转换性

既然mhtml封装的内容是网页资源,那么有理由相信其可以转换到html格式,主要在包含图片等非文本资源转换后,存储形式会和直接网页源码有较大不同(这些外部资源被编码成一长串的字符序列嵌在文件中,从mhtmlz转换为html后也是如此)

MHTML 和 HTML 格式之间具有**高度的可转换性**



### HTML 到 MHTML



- **原理：** 将一个标准的 HTML 页面（通常有独立的图片、CSS 文件等）转换为 MHTML 需要将这些分散的资源**聚合**并**嵌入**到单一文件中。
  1. **收集** HTML 文件及其所有引用的外部资源。
  2. 对所有资源进行 **Base64 编码**。
  3. 将 HTML 代码和编码后的资源按照 **MIME `multipart/related` 结构**进行封装，创建 MHTML 文件。
- **实现方式：** 现代浏览器（如 Chromium 内核的浏览器）在执行 "保存网页为... -> 网页，单一文件" 的操作时，实际上就是将 HTML 及其资源打包成 MHTML 格式。

### MHTML 到 HTML（易于转换）



- **原理：** MHTML 文件本质上是一个带有特定 MIME 封装结构的文本文件。HTML 内容和 Base64 编码的资源都包含在其中。将 MHTML 转换为 HTML 的过程主要包括：
  1. **解析** MHTML 文件的 MIME 结构。
  2. **提取**主要的 **HTML 代码**。
  3. **解码**并**保存** Base64 编码的资源（如图片）到本地文件系统（通常是单独的文件夹）。
  4. **修改** HTML 代码中的资源引用链接，使其指向新保存的本地资源文件。
- **实现方式：** 存在许多工具、库和在线服务可以轻松实现 MHTML 到 HTML 的转换

### 借助浏览器转换mhtml->html

- 最简单的方式是把chrome或则edge浏览器保存的mhtml用浏览器打开,然后查看源码(ctrl+u)或者右键页面查看源码(`view-source://file:///...`)
- 然后全选内容,复制(得到的就是html代码)
- 创建一个空文本文件,比如`a.txt`,或者直接取名`a.html`,粘贴内容并保存
- 根据需要将文本文件后缀重命名为`.html`



## 应用案例

例如,bash的在线帮助页面内容很长,并且是英文编写的

我希望借助浏览器的翻译插件将文本翻译,得到诸如双语对照的版本

现在要保存这个翻译好的页面,的一个推荐的方式是保存成mhtml格式,虽然可以打印保存输出为pdf,但是会被分页,连贯性不佳,且pdf格式不够灵活,不同窗口的内容自适应不如html,文本拷贝也不如html(web浏览器内拷贝)方便,还包括样式保留还原度方面也是html格式占优

> 如果保存成html,那么插件翻译的部分(即译文)就会丢失,而保存成mhtml就不会丢失译文

这种mhtml一般chrom和edge都可以打开,也可以按上述方法转换为html,供其他浏览器打开
