## 开发目标

> 先填写**开发目标**，再将开发目标至交付报告的内容交给agent；按项目范围删除不适用的可选要求。
>
> 从零构建且尚未明确产品方案时，可先结合[技术学习与信息调研方案探索提示词](技术学习@信息调研方案探索Prompt.md)明确需求与选型。

---

本模板用于从零构建Web应用、实现参考图，或改进已有页面。

实现参考图时，应同时说明需要还原的部分、允许改进的部分和交互预期；图片无法说明的状态需要补齐。

请根据以下信息构建应用，未填写的非关键项可以采用合理默认值，并说明假设。

| 项目 | 填写内容 |
| --- | --- |
| 应用目标 | <话题或开发目标，以及应用要解决的问题> |
| 用户与主流程 | <目标用户；从进入页面到完成任务的步骤；成功后应看到什么> |
| 必须实现 | <页面、功能、输入输出和关键状态> |
| 范围边界 | <暂不实现的功能；已有项目中允许修改和必须保留的部分> |
| 数据与能力 | <真实接口/本地数据/演示数据；是否需要保存、导入、导出或登录> |
| 参考与风格 | <参考图或页面；品牌约束；希望呈现的气质和避免的风格> |
| 运行与适配 | <已有技术栈或平台限制；目标浏览器；最窄视口或组件容器宽度> |

**默认目标是交付能运行、能操作、能验证的应用。**演示模式也要有完整的交互结果；真实接入所需条件不足时，明确说明当前范围，不把演示数据或模拟结果描述为真实服务能力。

## 执行方式

1. **先确认任务与范围**：用一句话概括用户、主要任务和下一步操作；列出主流程、关键状态及可观察的验收条件。只有影响核心结果、数据行为或范围的缺失信息才需要澄清，普通设计选择自行决定并记录假设。
2. **先定主张与线框，再写样式**：明确一处视觉记忆点，给出简短布局说明和设计令牌。未要求多方案确认时，自行选择推荐方向并继续实现，不停在计划或等待线框批准。
3. **按完整用户流程实现**：先打通进入、输入、执行、结果与失败恢复，再完善视觉细节；不要逐页堆出无法连通的空壳。改已有项目时，先理解原功能并保护有效行为，不为美化擅自替换框架或删除功能。
4. **边实现边验证**：优先解决操作无效、状态错误、焦点与窄屏问题，再打磨构图、层级、文案和动效。修改共享容器时，检查其中每种内容模板和关键状态。
5. **完成实际检查后再交付**：能运行的构建、静态检查和浏览器测试应实际执行；发现范围内缺陷后修复并重验。工具受限时继续完成不依赖工具的工作，并如实标注验证缺口。

## 交付内容

交付规模随目标调整，避免为了形式生成重复文档或无关功能。

### 文档

给出与项目规模相称、结构清楚且可操作的文档。

- 实践指南应区分必须、推荐、可选和避免的做法，配合应用中的完整案例说明。
- 产品文档应说明设计思路、功能与数据边界、运行和部署方式，以及主流程的使用方法。
- 运行说明给出与项目实际一致的依赖安装、启动、构建和验证命令；需要环境配置时提供示例及字段说明，不包含真实凭据。
- 文档较多时组织目录并提供文档地图；小应用可以合并到 `README.md`，设计令牌和关键决策记录在 `DESIGN.md` 或已有同类文件中。

### Web程序

- 页面围绕目标主题组织内容，优先用一个完整综合案例覆盖关键场景、最佳实践和常见问题，呈现形式通俗易懂。
- 所有可见操作都应有符合名称的结果。例如，筛选要改变列表，复选框要影响选择计数，保存要给出成功或失败反馈；不要用同一个通用提示代替不同功能。
- 演示类应用可提供视口或容器宽度调节、长文本和数据量切换、加载/失败模拟；方案对比可提供原方案、改进方案(**默认**)和并排模式。可以设置一个滑条,可以手工调节,也可选地支持自动调节宽度的播放演示需可暂停(注意性能,尽量做到流畅跟手)，并尊重减弱动效偏好。
- 预览控件改变局部容器宽度时，不将其等同于真实视口或移动设备测试；页级媒体查询、触控与软键盘行为另行验证。
- 默认支持浅色、深色和跟随系统，初始为跟随系统；主题切换后保留用户选择。
- 有较多章节或控制项时，可使用可折叠侧栏、目录、吸附操作栏或按需浮层(典型方案是收纳到一个悬浮图标按钮,宽屏默认展开,窄屏则默认收纳起来)；是否使用取决于任务和空间，不为了展示效果强行添加。
- 字体、行高、间隔与边距应清楚舒适，文字与背景对比度足够高。展示代码片段时提供语法高亮、行号和复制入口；复制内容不含行号，长代码只在代码区域内滚动。
- 某些页面和工具程序可能需要适当填充演示和模拟数据,但是不默认填充,而可以通过开关填充.
- 注意状态设计和标识的合理性.例如,对于web测试某个请求如果尚未执行则不应该用失败标识.

### 其他产物

按开发目标提供其他必要产物，例如示例数据、导入模板、导出文件或配置样例；只交付本次范围内确实实现的内容。

## 前端设计要求

### 任务与视觉主张

- **任务优先**：首屏聚焦主要任务，主操作不超过3个；低频功能逐级披露，空状态提供明确的下一步。危险操作与常规操作分开，并说明对象和后果。
- **主张具体**：用一句话说明视觉方向及其与内容的关系，不只写“现代、简洁、高级”。小工具保留一处记忆点即可；落地页或整体重设计可比较2–3个在布局、信息组织或交互上不同的方向，再选择一套实现。
- **装饰有依据**：渐变、卡片和动效应服务层级、内容或视觉主张；删除无作用的装饰，不默认使用满屏毛玻璃、标题表情符号和多层卡片嵌套。
- **参考有取舍**：借鉴参考的构图、层级和节奏，不照搬身份与素材。局部修复保留有效设计；需要整体重设计时重新定主张，并说明关键保留项的理由。

### 布局与设计令牌

- 工具类页面优先选择仪表盘、单列任务表单、列表与详情、设置页等成熟布局；后台控制台按其导航、数据管理与设置流程组织，文章或落地页按内容需求定布局。
- 先写**设计令牌(Design Tokens)**再写组件样式：定义颜色、字体、间距、圆角、阴影和动效。间距优先使用4/8/12/16/24/32/48px，64px仅用于页面级留白；字号不超过7档、圆角不超过4档、阴影不超过3级，同一应用使用一套图标语言。
- 组件优先复用语义令牌和成熟控件，避免散落硬编码与多套样式。图标语义统一；重要操作保留文字，纯图标操作有可访问名称，不能让用户猜。
- 可能增长的列表、日志和弹窗内容须有滚动或分页策略，避免数量翻倍后撑开页面骨架；列表换页、筛选和浏览器返回之间保持一致。

### 交互与状态闭环

- **异步状态完整**：覆盖待机、加载、成功、空、错误和重试；刷新已有内容时保留旧数据，避免整页退回骨架。错误说明发生了什么、用户能做什么，并保留已填内容。
- **忙态立即生效**：请求开始即防重入，结束或失败后恢复；等待指示可以延迟，不能因此允许重复提交。例如，保存中再次点击不会发出第二次请求。
- **状态决定可用性**：缺少前置状态时，隐藏无意义的操作，或真实禁用并给出可见原因；不要看着可点、点击后才说不可用。字段校验错误仍允许提交，由提交动作定位首错。
- **浮层可关闭**：弹窗、抽屉和下拉支持可见关闭入口及适用的Esc操作；打开时焦点合理进入，关闭后回到有效触发源或后备入口，隐藏内容不可继续被Tab访问。普通展开区不要误用菜单角色；真正菜单实现对应键盘模型。
- **状态可解释**：筛选、选择和批量操作的数量与实际目标一致，空选不擅自执行全部；需要跨页保留选择时说明规则。同一操作的不同入口保持结果一致。
- **导航与数据稳定**：适用时让URL反映页码、筛选或详情；后退、前进、刷新行为符合预期。声明哪些数据会保存、哪些只在当前会话有效；不要先显示错误默认状态再跳到已保存状态。

### 过渡、动画与等待反馈

**动效解释状态变化、空间关系或等待过程；业务结果与交互语义不依赖动画。**时长与缓动集中在项目令牌中维护，组件不各写一套规则。

| 场景 | 默认反馈或预算 |
| --- | --- |
| 按压、开关、轻提示 | 120–200ms |
| 下拉、菜单 | 约150ms进入，约120ms退出 |
| 列表载入、分组开合 | 约200ms，不逐行拖延大量内容显示 |
| 页面切换、抽屉、弹窗 | 200–320ms，退出通常更快 |
| 短等待 | 约300ms内不闪等待指示，不为动画人为延迟结果 |
| 较长等待 | 约300ms后给局部指示；超过2s给阶段说明、已用时间与取消/离开出口 |

- 基础时长令牌可用120/200/320ms，基础缓动可用 `cubic-bezier(0.2,0,0,1)`；常规过渡默认不超过320ms，必要例外说明收益。工具界面避免弹跳与无限循环装饰。
- **进入和退出都覆盖**：正常模式下，弹窗、抽屉、下拉有双向反馈；列表和骨架切换保持结构连续，避免硬闪。关闭不能只删节点而丢失退出反馈，也不能为了退出动画延迟业务关闭或焦点管理。
- **优先简单、原生实现**：通常选显式属性的CSS过渡，避免 `transition: all`；需要运行时控制再用Web动画API(WAAPI)，不为按钮引入大型动效引擎。优先透明度和变换；小区域高度展开可按实测使用Grid过渡，但它仍可能触发布局。
- **打断后也正确**：快速开、关、再开，以最后命令为准；动画完成、取消、零时长和组件卸载都有收尾路径。不单靠 `transitionend` 隐藏内容，也不用极短时长保证事件。
- **减弱与回退仍可用**：尊重 `prefers-reduced-motion`，关闭非必要位移、缩放与循环，保留静态图标和文字；JS创建的动画也检测偏好并处理运行中变化。不支持所用特性时直接呈现正确终态。
- **等待诚实**：未知总量不伪造百分比，阶段说明来自真实任务状态。可以停止请求时提供取消；不可中止时说明离开是否继续处理，不把停止等待说成撤销任务。适用时给缩小处理范围的入口。

### 响应式与操作收纳

- **按内容定断点**：页面按视口调整导航与列数，可复用组件按容器空间调整。先保证自然换行、Flex/Grid收缩与媒体自适应，必要时再用媒体或容器查询。
- 基础验证覆盖320/390/768/1440px，并检查布局切换阈值两侧；重点关注平板、窄桌面和短视口。需要300px或更窄容器时，明确支持下限和退让策略，不承诺任意宽度下保留完整桌面布局。
- **操作收纳不靠挤压**：优先完整文字、整颗按钮换行或纵向排列；有明确主次时保留主操作，其余进“更多”。纯图标只用于语义稳定的低频或密集操作，并提供可访问名；不能用省略号、极小字号或隐藏唯一入口来假装适配。
- 页面无非必要横向滚动；表格和代码可在自身区域内滚动，表格也可按任务降为卡片或提供列显隐。Flex/Grid内容项保留收缩能力，例如 `min-width: 0`；长URL、错误和文件名可断行或恢复全文。
- 图片预留尺寸或比例，避免载入时布局跳动；移动端弹窗内容可滚动，关闭和主操作始终可达，考虑软键盘、短视口及底部安全区。
- 极窄模式先保住主要内容、状态和关键操作，再收纳低优先级信息；收纳后的功能仍可发现。不要给页面整体加 `overflow-x: hidden` 来掩盖布局缺陷。

### 无障碍与表单

- 使用语义按钮和链接；全键盘可达，焦点可见且不被遮挡，不使用无替代的 `outline: none`、点击 `div`、仅悬停可用的功能或 `window.alert()` 代替页面反馈。
- 以Web内容无障碍指南(WCAG)2.2 AA为底线：一般点击目标至少24×24 CSS像素，触屏设计目标44×44px；正文对比度至少4.5:1，大文字及非文字控件至少3:1。错误、成功和加载不能只靠颜色表达。
- 默认在320px下可回流，200%缩放后仍可操作；不禁用缩放或粘贴。中文页面设置正确语言，正文行高建议不低于1.6。
- 每个表单字段有可见标签，正确设置输入类型、`inputmode` 与 `autocomplete`；失焦检查单字段，提交时汇总校验，错误关联字段并定位首错，保留已填值。
- 表单超过7项时分组或分步；自定义控件实现对应键盘行为。关键状态可用礼貌的读屏播报，不逐帧播报计时或动画。

### 主题、吸附与浮层

- 主题使用语义颜色令牌，深色模式重新检查文字、边框、禁用状态和图表；跟随系统时响应系统变化，手动选择不被系统变化覆盖。
- **所属区域内停留用sticky，全局悬浮用fixed**。吸附元素设置有效阈值、合理层级和清晰背景，确认滚动容器及父级空间；不要用高频滚动监听模拟已有CSS能力。
- 多层吸顶共用实际高度基线；页内锚点和Tab焦点预留让位，避免标题或控件被遮挡。窄屏和短视口下减少次级吸附区域，保住主要内容。
- 浮层独立验证位置、关闭、焦点和遮挡；限制内容高度并提供滚动，不能只检查页面尺寸就认定浮层不溢出。

## 运行与工程要求

- 优先复用已有框架、组件库和项目命令；新项目按任务规模选择简单、可维护的实现，不无故叠加依赖。
- 区分前端预览、完整运行和真实服务接入；明确后端、存储或环境配置的前置条件，不能用页面成功提示代替真实写入结果。
- 清理组件卸载后的监听、观察器、计时器和动画；并发请求避免迟到结果覆盖新选择。大列表、图片、滚动和演示播放按实际数据量检查性能。
- 功能与文档一致；交付前清理临时探针、调试样式和无效入口，不把真实凭据写进前端代码或交付文件。

### 技术栈

- 主要针对数据库: 如果项目用到了数据库,没有特殊要求的情况下,那么考虑使用轻量的sqlite;

## 验收

### 执行原则

**构建成功只证明能够构建，不证明功能或界面合格。**有可用浏览器自动化工具(如Playwright)时，应实际运行主流程和适用边界检查；工具不可用时记录原因和未覆盖范围，不编造执行结果。

先执行能自动断言的用户操作和结果，再截取关键态并实际查看图像。截图用于检查呈现，不代替行为断言；只保存截图文件、只看DOM状态或只检查元素有尺寸，都不能证明操作有效。

### 必查场景

| 范围 | 场景与判定 |
| --- | --- |
| 主流程 | 从用户入口完成任务，核对实际列表、结果、保存值或导出内容，不只看成功提示 |
| 状态与恢复 | 加载、空、错误、成功、重试；长任务连点不重入，失败后能继续操作 |
| 表单与选择 | 空值、非法值、长文本、数量边界、筛选与批量选择一致；校验不丢输入 |
| 弹窗与下拉 | 打开、关闭、Esc、快速反复开关；焦点合理回归，隐藏内容不可访问，无遮罩残留 |
| 动效 | 正常模式双向反馈；减弱、取消、零时长和特性回退的终态正确；静态截图通过不能证明正常动画有效 |
| 布局与主题 | 约定视口及阈值边界、窄容器、短视口、长内容、浅/深主题；无挤压、遮挡或非必要横向滚动 |
| 键盘与导航 | Tab/回车/空格和适用快捷键可用；后退、刷新与锚点滚动符合预期，无焦点陷阱 |
| 工程质量 | 项目适用的构建、lint、类型检查和测试；浏览器无未处理异常，关键资源可加载 |

布局或交互变化时，至少查看代表性宽窄视口和关键状态截图；长页检查不同内容模板，不只看首屏。固定并记录实际视口、主题和动效偏好；启用工具支持的无障碍检查时，修复适用问题，但不把自动化分数当作完整合规证明。

### 完成标准

- 必须功能已打通，用户能从入口完成主任务，关键状态与失败恢复正确。
- 适用检查确实执行，发现的问题已修复并重验；未执行、受阻和不适用分别记录，不统称通过。
