## 交付内容

可能随目标的不同有所变化.但通常包括:

### 文档

请给出完善的文档,规划好内容,内容规范,正式,完整,全面.

- 如果是实践指南文档,通常包括:
  - 必须怎么做;
  - 应该/推荐怎么做;
  - 可以怎么做;
  - 避免怎么做; 
  - ...
- 如果是产品设计和使用文档,通常包括:
  - 设计思路;
  - 部署和使用说明;
  - 如果文档比较多,要组织好目录结构,做好文档地图;
  - ...

### web程序

- 给出web页面要求能够比较全面地反映和覆盖所讨论的话题,最好能够给出一个综合案例(场景考虑完整全面),能够很好的说明相关设计(或指南)文档中提到的最佳实践和问题.要求呈现形式设计巧妙,通俗易懂;
- 对于部分演示类程序,建议设置适当的调节控件,方便模拟不同窗口大小,或者不同设备端的显示效果;
  - 酌情提供贴心功能:对于模拟不同宽度窗口,考虑提供自动调节滑条,并且考虑提供自动调节的播放演示功能(应力)
  - 对于方案对比,可以提供多个查看模式(老方案,改进方案,同时对比观察);
- 外观适配主题功能(至少支持浅色和深色,以及跟随系统(默认)).
- 鼓励使用侧边栏或侧边大纲设计(但要能够控制收起/展开),并善用悬浮设计和sticky设计.也可以考虑按需出现的浮层设计.(尤其是某些控制区,通过浮层让其可见性和位置稳定性更可靠,控制某些演示更方便)
- 注意web中一些操作的性能问题和潜在的bug修复,项目构建成功也不代表质量合格.(例如,加载逻辑和操作效率的检查和优化)
- 文字大小等样式合适,清晰可见,内容之间的间隔和边距设计合理.对给出的示例**代码片段**提供行号,高亮等支持(允许采用合适的库实现),提高阅读体验.

#### web程序基本原则

应具备：

- 任务清晰：一句话说清用户/任务/下一步；首屏只做一件事，主操作≤3个；表单超7项分组分步；危险操作远离首屏+二次确认。
- 布局克制：仪表盘/表单单列/列表+详情/设置页四选一；间距只用 4/8/12/16/24/32/48；先线框确认再写 CSS。
- 无障碍底线：全键盘可达、焦点可见、目标≥24px（触屏44px）、对比度 4.5:1、320px 可回流、中英行高≥1.6。
- 视觉一致：先写令牌再写样式；字号≤7档、圆角≤4档、阴影≤3级、一套图标库。
- 自适应和响应式可用：390/768/1440 三宽验证；页面级无横向滚动；表单有可见标签、两级校验、首错聚焦、保留已填、允许粘贴。
- 酌情考虑和支持极端窄的窗口: 300px甚至更窄.

不应该犯（NEVER）：

- 无替代 outline:none、div onClick 假按钮、仅 hover 功能、alert、禁用提交代替校验、禁粘贴/禁缩放；
- 纯装饰渐变/满屏毛玻璃/标题 emoji/卡片套卡片；
- 元素挤压和溢出,尤其是在窄窗口的条件下.
