## 教程与指南写作指导

**好的教程，不是把作者掌握的知识完整展示出来，而是让目标读者沿着合理的路径，从已有能力走到新的能力。**

面向初学者时，重点尤其不是“写得更长”或“说得更简单”，而是：

- **减少读者必须自行补全的前提、推理和判断。**
- **在需要信息的位置提供信息，而不是要求读者不断回查。**
- **让读者知道正在做什么、为什么这样做、如何判断结果。**
- **从完整指导逐步过渡到独立运用，避免只获得一次跟做成功。**

本文面向教程、技术指南及知识型文档的作者，重点讨论初学者，同时说明进阶与高级读者的差异。多数原则也适用于非技术主题。

**取证日期为2026年11月4日。**文中引用的文档分工、写作规范与教学原则来自已读取的来源；具体结构、示例和验收清单是基于这些材料的综合建议，不代表某一种模板具有普遍最优性。

## 先确定文档要帮助读者做什么

### 区分学习、办事、理解与查阅

“教程”“指南”经常混用，但读者可能带着完全不同的目的进入文档。

Diátaxis是一种按读者需求区分文档职责的方法，其名称有“编排、安排”之意。它区分的文档类型，有助于避免一篇文章同时承担过多任务。[来源：Diátaxis的*教程原则*](https://diataxis.fr/tutorials/)

| 文档类型 | 读者的主要问题 | 写作重点 | 不应成为主体的内容 |
| --- | --- | --- | --- |
| **教程**(Tutorial) | 我还不会，怎样通过实践学会？ | 受控的学习路径、示例、观察和练习 | 大量选项、完整参数表、无关分支 |
| **操作指南**(How-to Guide) | 我有一个实际问题，怎样解决？ | 适用条件、操作方法、分支、验证与恢复 | 从零解释所有基础概念 |
| **解释性文档**(Explanation) | 为什么这样工作？不同概念有什么关系？ | 动因、机制、关系、边界与权衡 | 为了凑实践而加入冗长操作 |
| **参考资料**(Reference) | 这个字段、规则或接口的准确含义是什么？ | 完整、精确、一致、便于定位 | 要求读者从头阅读的教学叙事 |

**文档类型与读者水平是两个不同维度。**

高级读者学习陌生技术时，也可能需要教程；初学者完成一项已学过的操作时，也可能只需要简短指南。不要把“教程”等同于低级内容，也不要把“参考资料”等同于高级内容。

这些分类用于明确职责，不是强制设置目录。例如，小型教程可以包含必要的概念解释，而不必把每一句解释拆成独立页面。专业写作者Tom Johnson对Diátaxis的讨论，也指出了机械分桶可能带来的问题。[来源：*Diátaxis及其与其他文档方法的比较*](https://idratherbewriting.com/blog/what-is-diataxis-documentation-framework)

### 把目标写成可以观察的能力

“了解”“熟悉”“掌握”可以表达意图，却不够适合决定内容取舍和验收标准。

| 模糊目标 | 更可执行的目标 |
| --- | --- |
| 了解数据筛选 | 根据给定条件筛选记录，并说明为什么这些记录被保留 |
| 掌握配置方法 | 修改指定配置、验证生效，并在失败时恢复原配置 |
| 理解权限管理 | 区分不同权限的作用范围，并为给定场景选择所需权限 |
| 熟悉性能优化 | 根据测量结果识别瓶颈，并说明优化方案的代价 |

**先确定读者最后需要完成什么，再反推必须讲什么。**

这也意味着：某个知识点很重要，不等于它必须出现在当前教程中。判断依据是它是否服务于本篇目标，而不是它在整个知识体系中的地位。

## 按具体能力定义读者，而不只写等级

### 初学者、进阶和高级是相对的

读者水平不是一个人的固定标签。

有经验的程序员可能第一次使用某种命令行工具；熟悉业务的工作人员可能不熟悉电子表格公式；高级用户切换平台后，也可能不清楚新的路径、权限和默认行为。

Google的技术写作课程强调：除职业角色外，还要考虑读者与当前知识的接近程度，不能仅凭职位推定其背景。[来源：*受众分析*](https://developers.google.com/tech-writing/one/audience)

建议在动笔前记录以下信息：

| 分析项 | 需要明确的问题 |
| --- | --- |
| **已有知识** | 哪些概念可以直接使用？哪些概念必须解释？ |
| **已有操作能力** | 能否创建文件、运行命令、读取图表、修改配置？ |
| **学习目的** | 系统学习、立即完成任务，还是辅助决策？ |
| **使用环境** | 使用什么平台、版本、工具、语言和权限？ |
| **典型误解** | 可能把哪些对象、状态或因果关系混为一谈？ |
| **成功标准** | 跟做成功即可，还是需要独立迁移、诊断和判断？ |

### 不同水平应改变什么

| 设计维度 | 初学者 | 进阶读者 | 高级读者 |
| --- | --- | --- | --- |
| **主要需求** | 建立基本理解并完成首次实践 | 从会用过渡到会选择、会组合 | 在约束下诊断、设计和权衡 |
| **起点** | 具体问题、可见结果、必要基础 | 已知方法的不足、常见变体 | 复杂问题、约束、争议或失效案例 |
| **指导程度** | 明确位置、动作、输入和检查点 | 保留关键步骤，减少重复说明 | 省略已声明的基础，保留关键依据 |
| **示例形式** | 完整示例，控制变量 | 对照示例、补全任务、组合任务 | 真实案例、边界条件、多方案比较 |
| **原理深度** | 足以解释当前行为的最小模型 | 机制、关联和适用条件 | 假设、证据、反例及模型局限 |
| **练习方式** | 小幅修改并观察结果 | 独立选择方法、处理变体 | 开放任务、故障分析和方案论证 |
| **应避免的问题** | 术语堆砌、隐含步骤、过早选择 | 永远重复入门操作，缺乏迁移 | 用晦涩代替深入，省略风险与依据 |

这里的关键不是“初级长、高级短”，而是**不同读者需要不同的信息密度与支撑方式**。

**专家逆转效应**(Expertise Reversal Effect)指的是：某种指导对缺乏相关知识的学习者有帮助，但随着相关知识增加，同样的指导可能变成冗余，甚至妨碍学习。因此，支撑应随熟练度调整，而不是永久保持不变。[来源：新南威尔士州教育部门的*认知负荷实践指南*](https://education.nsw.gov.au/about-us/education-data-and-research/cese/publications/practical-guides-for-educators/cognitive-load-theory-in-practice)、[北京师范大学的中文研究综述](https://cit.bnu.edu.cn/syscg/53511.html)

## 面向初学者，先解决理解上的断点

### 不把作者熟悉的内容当作读者已知

作者常常知道一连串操作，却忘记其中包含多少隐含知识。这是**知识诅咒**(Curse of Knowledge)：掌握知识以后，很难准确想象尚未掌握它时的状态。

例如，“修改配置后重启服务”对作者可能十分明确，对初学者却可能留下这些问题：

- 修改哪个文件，文件在哪里？
- 修改哪一项，保留哪些内容？
- 保存以后是否已经生效？
- 重启的是应用程序、后台服务，还是整台计算机？
- 在哪里执行重启操作？
- 怎样确认重启完成，而不是失败退出？

初学者并非需要所有背景知识，但需要补足**会阻断当前任务的知识**。

可逐处检查：

> 读者第一次遇到这个词、这个动作或这个结果时，仅凭前文，能否知道它是什么、应该怎样处理？

### 为新概念建立最小理解模型

**最小理解模型**是足以解释当前任务中关键行为的简化认识，不是完整理论。

引入一个主线概念时，建议按以下顺序组织：

1. **问题或动因**：为什么需要它？
2. **基本定义**：它是什么？
3. **当前用途**：本例中用它做什么？
4. **可观察行为**：操作后发生什么？
5. **关键边界**：最容易误解的地方是什么？

例如，介绍电子表格筛选：

> 当表格记录较多时，逐行查找低库存商品容易遗漏。筛选可以按条件只显示部分记录，方便检查。本例只显示库存数量小于5的商品。**筛选隐藏了不符合条件的行，并没有删除这些记录。**

这段解释同时交代了用途、行为和边界，而不必先介绍完整的数据分析理论。

### 避免循环定义和术语递归

不良解释：

> 缓存用于提高缓存命中率；命中率就是命中缓存的比例。

问题不只是语言重复，而是读者没有获得更基础的理解。

更好的解释：

> 为了避免重复执行耗时工作，系统可以暂存以前得到的结果。再次遇到相同请求时，如果能直接使用暂存结果，就不必重新计算。这个暂存机制称为缓存；能够复用暂存结果的请求，占全部请求的比例，称为命中率。

**定义应依靠读者已知的概念，而不是依靠另一个尚未解释的术语。**

术语表可以帮助回查，但不能替代首次使用处的必要说明。缩写的英文全称也不等于解释了其含义。

### 简化内容，但不建立错误认识

初学者说明可以省略细节，却不能省略会改变判断的条件。

| 容易误导的简化 | 更合理的写法 |
| --- | --- |
| 筛选会去掉不需要的数据 | 筛选会隐藏不符合条件的记录，原始数据仍然保留 |
| 保存配置后就会生效 | 本例中的程序在启动时读取配置，因此保存后还需重启 |
| 这个参数越大越好 | 在本例范围内增大参数可以提高并发，但也会增加资源占用 |
| 系统会自动完成 | 说明在什么条件下自动完成，以及何时需要手工处理 |

**适用条件和重要例外，应与结论一起出现，不宜全部留到文末纠正。**

## 按学习依赖安排内容，而不是按知识分类堆砌

### 推荐使用有闭环的主线

面向初学者的实践教程，可以采用以下组织顺序：

1. **展示任务与结果**：说明要解决的问题，以及完成后的样子。
2. **确认起点**：列出必要知识、环境、材料和风险。
3. **建立最低限度理解**：只解释开始行动所必需的概念。
4. **完成一次受控实践**：提供明确步骤和阶段性检查点。
5. **解释关键结果**：把操作、变化和原因联系起来。
6. **完成小幅迁移**：改变条件、补全步骤或处理一个常见异常。
7. **收束与分流**：总结已能完成的任务，指向进阶学习或参考资料。

这不是要求所有教程都机械采用相同章节。它表达的是一种顺序：**先形成方向感，再提供行动能力，最后促进独立运用**。

Google的文档组织课程同样建议，在开头明确范围、受众与关键内容，并按读者需要安排材料。[来源：*组织完整文档*](https://developers.google.com/tech-writing/one/documents)

### 前置知识要“够用”，不要变成先修百科

前置部分容易走向两个极端：

- **不足**：写“需要基础知识”，却不说明究竟需要什么。
- **过量**：要求先学习整套基础课程，才允许开始当前任务。

更合适的做法是区分：

| 内容 | 放置方式 |
| --- | --- |
| 缺少就无法开始的知识或工具 | 放在前置条件，提供明确检查方法 |
| 开始操作时才需要的概念 | 在首次使用处解释 |
| 有助于理解但不影响完成主线的背景 | 标为选学，放在合适的阶段之后 |
| 完整规则、全量参数、历史沿革 | 放入参考或深入阅读 |

**前置条件应具体到可检查的能力。**

“需要计算机基础”不如“能够创建并保存文件，知道文件保存在哪个文件夹”明确。

### 不强求“理论永远在前”或“实践永远在前”

两种绝对规则都不可靠。

- 涉及安全、费用、数据破坏或不可逆操作时，必须先解释风险和必要原理。
- 面向初学者的低风险任务，可以先建立简短模型，再通过操作加深理解。
- 概念本身就是学习对象时，可以先讲概念，但应尽快连接具体情境。
- 面向高级读者时，可以从现有方法失效的案例进入，再分析机制。

**决定顺序的依据，是理解依赖、任务风险和已有知识，而不是固定写作流派。**

### 拆分应形成完整单元，避免过度碎片化

**认知负荷**(Cognitive Load)可以理解为：学习时，为暂时保持、处理和关联信息而承担的心理负担。它受任务复杂度、已有知识和材料呈现方式影响。

写作应减少无关负担，而不是消除一切思考。例如，寻找上一页的参数说明是可避免的负担；比较两个条件的差别，则可能正是学习目标。

拆分内容时，以**有意义的学习单元**为单位：

- 一个概念与足够理解它的例子。
- 一组共同完成一个小目标的操作。
- 一个可以观察、验证并暂停的阶段。

不要把连续任务拆成大量只容纳几句话的页面，迫使读者持续切换。中文研究综述也提醒，材料不是切得越细越好，复杂度和读者知识水平都需要考虑。[来源：北京师范大学的*认知负荷综述*](https://cit.bnu.edu.cn/syscg/53511.html)

## 把步骤写成可执行、可判断的动作

### 关键步骤应交代什么

对于容易出错或状态变化明显的步骤，可以用以下要素检查完整性：

| 要素 | 要回答的问题 |
| --- | --- |
| **目的** | 当前步骤要完成什么？ |
| **位置与前提** | 在哪个文件、窗口、目录或状态下操作？ |
| **动作与输入** | 具体做什么，哪些内容需要替换？ |
| **预期结果** | 完成后应看到什么，哪些内容允许不同？ |
| **判断方法** | 什么表明可以继续？ |
| **异常处理** | 出现典型差异时，先检查什么？ |

不是每次点击都需要完整展开。**简单操作可以合并，关键状态转换必须明确。**

Microsoft的步骤写作规范强调，先交代操作位置，再给动作；多步过程使用有序列表，并避免把过多操作挤在一起。[来源：*分步说明写作规范*](https://learn.microsoft.com/en-us/style-guide/procedures-instructions/writing-step-by-step-instructions)

### 预期结果要帮助读者判断，而不只是展示

不良写法：

> 运行成功后进入下一步。

更好的写法应说明：

- 成功时出现什么标志。
- 输出中的哪些部分具有判断意义。
- 时间、路径、标识符等哪些值可能不同。
- 是应当等待、继续输入，还是已经完成。

**不要要求读者把示例输出逐字匹配，也不要让读者从几十行日志里猜重点。**

对于编程和配置类教程，还应说明：

- 代码放在哪个文件，是新增还是替换。
- 命令在哪个终端、哪个目录执行。
- 示例是否完整可运行，是否省略了导入或初始化。
- 哪些值固定，哪些值由读者填写。
- 操作影响当前会话、当前项目还是整个系统。

### 风险与恢复要在操作之前可见

涉及删除、覆盖、权限、公开发布、联网收费等行为时：

- 在动作之前说明影响范围。
- 提供备份、预览或安全试验方式。
- 使用练习数据、测试账号或隔离环境。
- 说明失败以后如何停止、恢复或清理。
- 说明重复执行会不会产生重复资源或改变结果。

**不要用“为了简洁”删除读者作出安全决定所必需的信息。**

## 用示例建立理解，再逐步撤去帮助

### 选择最小但有意义的案例

好的入门示例应同时满足：

- **真实问题**：读者知道为什么值得做。
- **复杂度受控**：不引入大量无关业务知识。
- **因果可见**：能看出操作与结果之间的关系。
- **可以变化**：能够通过小幅修改练习迁移。
- **允许安全重试**：失败不会造成难以恢复的后果。

“真实”不等于“完整生产系统”。过于复杂的案例会让学习目标被业务、工具安装和环境问题淹没。

### 让完整示例逐渐变成独立任务

**教学支架**(Scaffolding)指学习过程中提供的临时帮助，例如完整步骤、提示、检查点和部分答案。它的目的不是永久代替思考，而是帮助读者获得独立完成任务的能力。

一种实用安排是：

1. **完整示范**：提供全部必要步骤，说明关键判断。
2. **局部修改**：只改变一个条件，预测并观察结果。
3. **部分补全**：保留目标和部分步骤，让读者补足关键环节。
4. **独立完成**：给出新任务与验收标准，不再提供完整过程。
5. **解释选择**：说明为什么采用这种方法，以及何时不适用。

美国教育科学研究所的实践指南支持将完整解题示例与独立练习交替安排，也建议连接具体与抽象表示、通过提问促进解释和回忆。[来源：*组织教学与学习以改善学习效果*](https://ies.ed.gov/ncee/wwc/practiceguide/1)

这些证据主要来自教育情境。将其用于成人技术教程是有依据的设计迁移，但仍需要通过实际读者测试确认效果。

### 不把“跟做成功”当作唯一完成标准

不同目标需要不同验证：

| 要验证的能力 | 合适的任务 |
| --- | --- |
| 能否执行 | 按教程完成操作 |
| 是否理解因果 | 解释某一步为什么必要 |
| 能否迁移 | 改变输入或条件后独立完成 |
| 能否判断边界 | 识别一个不适用场景 |
| 能否诊断 | 根据异常现象选择检查方法 |
| 能否保持 | 间隔一段时间后再次完成核心任务 |

练习应针对本篇目标。不要刚教完基础筛选，就要求读者设计完整库存管理系统。

## 通过贯穿案例观察写法差异

以下为**教学设计示意**，不对应某个电子表格软件版本的实测操作记录。实际发布时，应补齐具体软件、版本、界面路径和验证结果。

### 原始写法的问题

> 打开库存表，筛选库存小于5的商品，再按库存排序即可。

对于已经熟悉筛选功能的人，这可能足够；对于初学者，仍有明显缺口：

- 不知道筛选和删除的区别。
- 不知道应对哪一列设置条件。
- 不确定“小于5”是否包含5。
- 不知道排序只作用于某一列，还是整行记录。
- 没有检查结果，无法发现漏选数据范围等问题。

### 改成面向初学者的学习单元

**目标与范围**

> 使用筛选找出库存数量小于5的商品，并理解筛选不会删除其他商品。本次不处理排序、公式和自动补货。

这里主动移除排序，是因为它引入了新的目标与风险，并非完成首次筛选所必需。

**练习数据**

| 商品 | 库存数量 |
| --- | ---: |
| 笔记本 | 3 |
| 文件夹 | 5 |
| 铅笔 | 12 |
| 橡皮 | 0 |

**必要概念**

> 筛选按照条件决定显示哪些记录。本例的条件是“库存数量小于5”，因此数量为0和3的商品符合条件，数量等于5的不符合条件。

**操作安排**

1. 打开包含练习数据的工作表，确认商品名称与库存数量分别位于不同列。
2. 对包含标题与全部记录的数据区域启用筛选。
3. 在“库存数量”列设置数值条件“小于5”。
4. 检查结果：应只显示“笔记本”和“橡皮”。
5. 清除筛选，确认所有商品重新出现。

实际教程应把“启用筛选”和“设置数值条件”替换为经过验证的具体界面步骤。

**解释观察**

> 清除筛选以后，其他商品重新出现，说明这些记录只是暂时隐藏，并未被删除。

**小幅迁移**

> 把条件改成“小于或等于5”。先预测哪些商品会出现，再实际检查。

这个练习只改变条件边界，能够检验理解，又不会同时引入新工具。

**异常检查**

> 如果结果与预期不同，先检查筛选条件是否设在“库存数量”列、数量是否为数值，以及数据区域是否包含全部记录。

### 同一主题如何面向其他水平

| 读者 | 后续内容的重点 |
| --- | --- |
| **进阶读者** | 组合多个条件、处理空值和数字文本、解释不同条件的结果 |
| **高级读者** | 分析交互式筛选与自动化处理的适用边界、可复现性、数据更新和审计要求 |

同一主题的深化，不只是增加操作步骤，而是逐步增加**变体、判断、约束和责任范围**。

## 提高阅读体验，不只是缩短文字

### 用标题帮助读者判断与定位

标题应反映内容或行动，不应只有“相关说明”“其他内容”“深入理解”等宽泛标签。

| 宽泛标题 | 更有帮助的标题 |
| --- | --- |
| 环境准备 | 检查运行环境 |
| 注意事项 | 避免覆盖原始文件 |
| 问题分析 | 为什么筛选结果为空 |
| 进阶内容 | 组合多个筛选条件 |

**只看标题，读者也应大致知道文档覆盖什么，以及去哪里找答案。**

长文提供目录和稳定锚点；允许从搜索结果直接进入的页面，应保留必要上下文，不能只写“按照前面的方式处理”。

### 让版式服务于信息关系

| 内容关系 | 优先形式 |
| --- | --- |
| 连续动作 | 有序列表 |
| 并列要点 | 无序列表 |
| 多对象按相同维度比较 | 表格 |
| 原因、论证与例外 | 正文段落 |
| 空间关系、依赖、状态与复杂交互 | 有明确用途的图 |
| 需要识别的界面位置 | 局部截图与文字说明 |
| 代码、命令、配置 | 可复制且标明类型的代码块 |

**不要把所有内容都改成列表，也不要为了“结构化”把长段论证塞进大表格。**

Microsoft的可扫读性指南强调重要内容前置、清晰标题、稳定格式和长文导航。[来源：*可扫读内容*](https://learn.microsoft.com/en-us/style-guide/scannable-content/)

### 降低来回查找的成本

- 把参数说明放在相关命令附近。
- 把图片标注放在对应对象附近。
- 在步骤旁提供关键预期结果。
- 核心路径不依赖大量外链。
- 基础概念在首次使用处简释，再链接完整说明。
- 选学内容说明阅读收益，不只标注“扩展”。

**必要信息不应默认折叠；选学信息不应伪装成必读。**

全文知识的唯一正本与局部可读性可以兼顾：详细规则集中维护，首次使用处保留一句理解当前内容所需的解释，而不是复制完整章节。

### 使用清晰、尊重读者的语言

应避免：

- “很简单”“显然”“只需要”，掩盖真实难点。
- “自行配置”“按需修改”，却不给判断依据。
- “这个”“那里”“上面的内容”，造成指代不明。
- 用更多术语、更长句子表示“专业”。
- 为追求轻松而使用不必要的俚语和文化梗。

**正式与易懂并不冲突。**可以使用准确术语，同时把句子写短、把关系写明。

### 把无障碍和跨平台差异纳入正文设计

无障碍不仅面向特定群体，也有助于移动阅读、低带宽访问、翻译和快速查阅。

- 标题层级应表达真实结构。
- 链接文字说明目标内容，不只写“点击这里”。
- 图片提供必要的替代文本，不仅靠颜色传达区别。
- 视频提供字幕，并为关键操作保留可检索的文字说明。
- 避免只能从截图复制代码或识别参数。
- 大表格、长代码和复杂图片应考虑窄屏阅读。
- 技术教程明确Windows与类Unix系统的终端、路径、权限、编码或换行差异。
- 中文文件名、字体和非英文字符存在兼容风险时，提前说明已知限制。

这些要求可参考W3C的网页无障碍写作建议。[来源：*面向网页无障碍的写作提示*](https://www.w3.org/WAI/tips/writing/)

## 同时面向不同群体时，采用分层而非混写

### 不建议一段基础、一段高级地交替

这种安排容易让初学者不断遇到陌生内容，也让高级读者反复跳过基础说明。

更合理的方式是：

| 情况 | 组织建议 |
| --- | --- |
| 任务相同，仅解释深度不同 | 保留共同主线，基础解释与深入分析分层 |
| 前置能力和操作路径明显不同 | 分成入门与进阶教程，明确衔接条件 |
| 学习目标不同 | 分成不同文档，不强行共享全文 |
| 只有少量环境差异 | 在相关步骤提供清晰的平台分支 |
| 环境差异贯穿全过程 | 提供独立路径，避免每一步反复分叉 |

**入口应按可检查的能力引导，而不只按身份标签分流。**

例如：

> 如果你已经能够独立完成单条件筛选，并解释清除筛选后的变化，可以直接阅读“组合多个条件”。

这比“高手请跳过”更明确，也更尊重读者。

### 显式权衡组织方式

以下是写作设计上的综合判断，不是实验排名：

| 组织方式 | 阅读可靠性 | 成熟度 | 对现代阅读方式的适配 | 主要边界 |
| --- | --- | --- | --- | --- |
| 按学科分类完整展开 | 适合系统查阅，但主路径容易不明显 | 传统教材与手册中常见 | 需要额外导航支持按需阅读 | 不宜直接作为所有入门实践的结构 |
| 单任务线性教程 | 首次实践路径明确 | 常见教程形式 | 适合独立网页和阶段式学习 | 容易只教会固定案例 |
| **任务主线加分层解释、练习与参考入口** | 能兼顾首次成功与后续理解 | 可结合已有写作规范实施 | 支持顺读、跳读、搜索与回查 | 需要维护清晰边界和链接关系 |

**默认推荐第三种。**它适用于大多数实践型教程；纯概念课程、严格顺序课程或篇幅很小的单任务说明，可以简化，不必强行配齐所有层次。

## 建立可重复使用的写作与验收流程

### 动笔前先填写写作简报

| 项目 | 需要写清的内容 |
| --- | --- |
| **文档职责** | 主要帮助学习、完成任务、理解机制，还是查询规则 |
| **目标读者** | 已会什么，不假定会什么 |
| **目标能力** | 完成后能够做出哪些可观察行为 |
| **适用范围** | 环境、版本、情境与不覆盖的相关问题 |
| **主线任务** | 用什么案例串联内容 |
| **概念依赖** | 哪些概念必须先于另一些概念解释 |
| **风险与恢复** | 可能造成什么影响，怎样安全重试 |
| **检查点** | 在哪里验证阶段结果 |
| **迁移任务** | 怎样验证不只是照抄成功 |
| **维护条件** | 哪些变化会触发重新验证 |

The Good Docs Project的教程模板，也把学习目标、受众、前置条件、步骤和后续学习作为重要组成部分。[来源：*教程模板指南*](https://www.thegooddocsproject.dev/template/tutorial)

模板用于提醒遗漏，不应变成“每篇必须填满”的形式要求。固定时长、固定步骤数和固定段落长度，都只能作为编辑参考，不能替代理解与任务判断。

### 按顺序完成写作与审查

1. **确定目标与验收任务**，先决定如何判断读者学会。
2. **设计主线案例**，排除无关工具与业务复杂度。
3. **梳理概念依赖**，检查是否存在前向依赖或循环定义。
4. **写通完整路径**，补齐输入、操作、状态与结果。
5. **加入必要解释与异常处理**，把选学内容移出主线。
6. **设计迁移练习**，逐步减少提示。
7. **验证示例与环境**，记录实际测试范围。
8. **观察目标读者使用**，根据卡点修改并复验。

### 区分技术正确与教学有效

| 验证层面 | 检查重点 |
| --- | --- |
| **技术正确** | 示例能否执行，界面、参数和结果是否准确 |
| **路径完整** | 是否存在遗漏步骤、隐含环境、状态不一致 |
| **理解可达** | 读者是否能解释关键变化，而非只复制动作 |
| **迁移有效** | 改变条件后，能否独立完成 |
| **查阅方便** | 能否找到前提、错误处理和关键规则 |
| **维护可靠** | 版本变化后，是否能识别并更新受影响内容 |

测试时，不要一遇到困难就口头补充，否则测到的是“作者陪同下能否完成”，而不是文档本身的可用性。

记录卡点时，优先记录具体行为：

> 读者在“设置条件”处停顿，不确定应选择文本条件还是数值条件。

而不是只写：

> 这一段不够清楚。

**作者能跑通，不等于读者能跑通；读者能跑通，也不等于已经理解。**

## 发布前检查清单

### 面向所有读者

- [ ] 文档职责、目标读者、适用范围和成功标准明确。
- [ ] 内容按任务与理解依赖组织，而不是按作者想到的顺序排列。
- [ ] 示例、命令、界面与关键结果经过验证；未验证内容有明确标注。
- [ ] 风险说明出现在相关操作之前，并提供必要恢复方式。
- [ ] 标题、术语、格式和链接含义一致。
- [ ] 核心路径能够独立完成，不依赖大量外部跳转。
- [ ] 实测环境与未验证的平台、版本明确区分。
- [ ] 有更新触发条件，能够识别内容何时可能失效。

### 面向初学者重点加查

- [ ] 没有用“基础知识”“自行配置”替代具体前提。
- [ ] 新概念说明了用途、含义和当前场景。
- [ ] 定义没有依赖未解释术语，也没有循环解释。
- [ ] 知道在哪里操作、输入什么、哪些内容需要替换。
- [ ] 关键步骤有检查点，知道何时可以继续。
- [ ] 重要例外与结论一同出现，没有先制造错误模型。
- [ ] 主线不存在过多方案选择和无关分支。
- [ ] 有小幅迁移任务，而不只要求重复原例。
- [ ] 可以暂停、回查、重试，并知道当前处于什么状态。
- [ ] 没有用“显然”“很简单”等表述掩盖解释缺口。

### 面向进阶与高级读者重点加查

- [ ] 进阶内容增加了变体、关联和方法选择，而不只是更多步骤。
- [ ] 已声明的基础内容可跳过，但必要前提并未省略。
- [ ] 高级内容明确约束、证据、替代方案和失败条件。
- [ ] 结论具有适用边界，没有把单一案例当作普遍规律。
- [ ] 练习需要独立判断，而不是换一组数据重复固定动作。

## 调研记录与证据边界

本次按**文档职责、读者能力、认知负担、步骤与示例、阅读体验、验证方法**分类检索，使用harness独立搜索入口，并读取官方写作指南、教育机构材料、中文研究综述与专业写作者的讨论。

| 轮次 | 实际使用的代表性搜索词 | 结果引出的线索与处理 |
| --- | --- | --- |
| 首轮：建立框架 | `Diataxis tutorials how to guides explanation reference limitations alternatives documentation`；`cognitive load novice expert worked examples expertise reversal effect instructional guidance review`；`教程 编写 规范 初学者 技术文档 先决条件 示例 用户测试` | 发现2025年专家逆转效应荟萃分析，以及文档分类的替代方法与批评线索 |
| 次轮：核验边界 | `"A meta-analysis of the expertise reversal effect" Tetzlaff 2025 findings`；`site.idratherbewriting.com "Diátaxis" "limitations"`；`site.education.nsw.gov.au cognitive load theory practice guide worked examples redundant information split attention` | 明确不能把文档分类机械当作目录；读取认知负荷实践指南，并从专业讨论中发现The Good Docs Project |
| 后续：补模板与中文证据 | `site.thegooddocsproject.dev tutorial template guide learning prerequisites`；`认知负荷 专家逆转效应 样例学习 初学者 教学 指导`；`site.writethedocs.org documentation usability testing observe users tutorials` | 核验模板中的受众、目标与前置条件要求，补充中文综述和验证方法线索 |

**证据边界：**

- 教学研究与技术写作规范的证据性质不同：前者研究特定情境下的学习效果，后者提供实践规范，不能将两者都表述成普遍因果定律。
- 2025年专家逆转效应荟萃分析的原文未能取得，本文没有引用其统计结果；相关建议依据已读的教育机构指南与中文综述。
- 未系统覆盖儿童教育、特殊教育、职业认证课程和高风险行业的专门要求。若用于这些场景，下一轮应定向检索对应受众和行业规范，而不是直接套用通用模板。

**最终原则是：对初学者减少隐含前提，对进阶读者增加迁移机会，对高级读者提供判断依据；对所有读者，都应保持目标明确、路径合理、结果可验证。**
