## 背景与症状

- **集成终端(Integrated Terminal)** 字体发虚、不清晰，**编辑器(Editor)** 显示正常。

## 环境

- 注册表存在第二台显示器记录，`DpiValue` 为 `3`，提示可能存在**多屏不同缩放(Multi-monitor mixed DPI)**。
- **字体平滑(Font Smoothing)** 已启用，`FontSmoothingType` 为 `2`，即 **ClearType** 生效中。
- 终端字体 `LiterationMono Nerd Font` 系列已安装，注册表名与文件名一致，包含常规、**等宽(Mono)**、`Propo` 三个变体。

## 根因

- **字体族配置错误(Font family mismatch)**：`settings.json` 中 `terminal.integrated.fontFamily` 为 `LiterationMono Nerd Font `，带尾空格，且使用非等宽变体，导致 **Nerd图标(Nerd icons)** 与中文字符走**回退字体(Fallback font)** 渲染，观感发虚。
- **渲染器默认值变化(Renderer default change)**：未显式设置 `terminal.integrated.gpuAcceleration`，跟随 `auto` 走 **WebGL**，在 Intel 核显加小字号下偏糊，同类问题常见解为切 `canvas` 或 `off`。
- **字号过小(Font size too small)**：终端为 `12`，浅色主题下细笔画对比不足，主观上像发虚。
- 非根因但顺带发现：`editor.fontLigatures` 被误写成字体名字符串，本次未改动，因编辑器显示正常。

## 修复内容

本次仅改终端相关三项，编辑器配置保持不动。

| 配置项 | 改前 | 改后 |
|---|---|---|
| `terminal.integrated.fontFamily` | `LiterationMono Nerd Font `，有尾空格 | `LiterationMono Nerd Font Mono, Consolas, 'Microsoft YaHei Mono', monospace` |
| `terminal.integrated.fontSize` | `12` | `13` |
| `terminal.integrated.gpuAcceleration` | 未设置，跟随 `auto` | `canvas` |
| `terminal.integrated.lineHeight` | 未设置 | `1.2` |

最终片段如下：

```json
"terminal.integrated.fontFamily": "LiterationMono Nerd Font Mono, Consolas, 'Microsoft YaHei Mono', monospace",
"terminal.integrated.gpuAcceleration": "canvas",
"terminal.integrated.lineHeight": 1.2,
"terminal.integrated.fontSize": 13,
```

改前已备份，原文件为 `settings.json`，备份为 `settings.json.bak-20261013`，均位于 `C:\Users\Administrator\AppData\Roaming\Code\User`。

选用 **等宽变体(Mono variant)** 的原因是终端需要图标与字符严格对齐，`Propo` 变体不适合终端；中文回退选用 `Microsoft YaHei Mono`，西文回退选用 `Consolas`。

## 验证

按以下顺序验证，每步改完重载一次：

1. 执行 `Reload Window`，在 100% 缩放下观察终端英文与中文是否变锐。
2. 用 `Ctrl+0` 重置工作区缩放，排除缩放叠加导致的**亚像素(Subpixel)** 模糊。
3. 若仍不满意，将 `terminal.integrated.gpuAcceleration` 改为 `off` 再重载，对比 `canvas` 与 `off` 的清晰度与流畅度。
4. 在 Windows 运行 `cttune.exe`，确认 ClearType 保持开启。

## 注意事项

- **渲染器 trade-off**：`canvas` 清晰且较快，为首选；`off` 走 **DOM** 最锐但大输出下较慢；`auto` 在不同版本默认值可能再变，升级后若复发先查此项。
- **等宽变体不可混用**：终端坚持用 `LiterationMono Nerd Font Mono`，编辑器若用常规变体也应补回退栈，勿只写单个字体名。
- **尾空格隐患**：字体名字符串尾空格看似无害，但会干扰精确匹配，复制字体名后应去除首尾空格。
- **字号与行高是主观项**：`13` 加 `1.2` 在 1080p 下适中，高分屏或远距离观看需再调，不宜直接照搬。
- **多屏缩放风险**：本机有一台高 `DpiValue` 显示器记录，窗口跨屏拖动时 Electron 可能模糊，若只在某台屏上虚，优先查该屏缩放而非改字体。
- **浅色主题显淡**：当前为 `Light Modern`，细字重在白底上本就偏淡，勿与模糊混淆，必要时再调 `terminal.integrated.fontWeight`。
- **未改项**：`editor.fontLigatures` 类型错误仍存在，`editor.fontSize` 的 `14.5` 小数也可能影响编辑器，一并留待下次处理。

## 后续建议

- 固定升级后检查项：记录 VSCode 版本号，升级后先看终端 `gpuAcceleration` 默认行为有无变化。
- 建立最小对比法：怀疑字体时，先切 `Consolas` 单字体隔离，确认是字体问题还是渲染器问题。
- 统一字体栈：编辑器与终端各自维护带回退的字体列表，中文统一回退到同一字体，避免中英文观感断层。
- 文档维护：若后续改用 `off` 或调整字重字号，回填本表并注明屏幕与缩放条件。
