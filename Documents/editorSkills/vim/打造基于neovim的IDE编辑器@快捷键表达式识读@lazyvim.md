## 按键表达式设计

`<C-h>`这种组合键记号为什么不使用“更通俗”的表达式（比如写成 `Ctrl+H` 或 `Command+H`），主要有以下几个深刻的原因：

------

### 1. 终端协议的限制（历史原因）

Vim 最初是在远程终端上通过 Telnet/SSH 使用的。

- 在古老的电传打字机时代，按键被视为发送特定的 **ASCII 码**。
- `<C-h>` 实际上是一个单一的**控制字符**（其十六进制值为 `0x08`）,因为键盘上的键数量有限,仅有最常用的部分字符,我们可以通过组合键来表达和发送键盘之外的字符(控制字符等)。
- 使用 `< >` 符号可以将这些**不可见的控制字符**转化为**可读的文本**。这种表示法非常严谨，能够区分“按下了 Ctrl 和 H”与“输入了字符 C, t, r, l...”这两种截然不同的行为。

### 2. 避免歧义：组合键 vs. 连续按键

在 Vim 中，按键的**顺序**和**组合**至关重要。

- **连续按键：** 如果文档写 `f f`，你可能会疑惑是按住两个 f，还是先按一个再按一个。
- **组合键：** 写成 `<C-f>` 明确表示这是一个组合动作。
- **Leader 键：** 写成 `<leader>f`。如果写成 `Space f`，用户可能会误以为要在文档里插入一个空格。使用 `<leader>` 这种“占位符”记号，可以让用户自定义自己的引导键（有人喜欢空格，有人喜欢逗号）。

### 3. 跨平台的一致性

Neovim 运行在 Linux, macOS, Windows 以及各种不同的终端模拟器（Terminal, Alacritty, iTerm2）中。

- 在 Windows 上我们说 `Ctrl`，在 Mac 上我们叫 `Control`。
- 在 Mac 上最重要的键是 `Command`，但在 Linux 里它根本不存在。
- **`<C-...>`** 是一套跨平台的标准语言。无论你用什么键盘，在 Neovim 的配置文件里，写下 `<C-h>` 永远代表同一个逻辑指令。

------

### 4. 它是“可编程”的文本

这是最核心的原因。**Neovim 的配置文件本身就是代码。**

如果你想在配置文件里设置一个快捷键，你必须使用程序能理解的格式：

```lua
-- 这是 Lua 配置文件中的写法
vim.keymap.set('n', '<C-h>', '<C-w>h') 
```

如果写成 `Ctrl plus H`，计算机就无法直接解析。

使用这种vim约定的记号，官方文档和你的代码配置就能保持**语言统一**。当你习惯了文档里的 `<leader>ff`，你可以直接把它原封不动地复制到你的配置里去。

------

### 如何快速“翻译”这些记号？

如果你觉得记忆困难，可以把这套记号看作一套**缩写系统**：

| **记号**   | **识读秘籍**                     |
| ---------- | -------------------------------- |
| **`<C-`**  | **C** 代表 **C**ontrol           |
| **`<M-`**  | **M** **M**eta (Mac 上的 Option) |
| **`<S-`**  | **S** **S**hift                  |
| **`<BS>`** | **B**ack**s**pace (退格)         |

**现有文档推荐：**

你可以直接在 Neovim 中输入以下命令查看官方对这些记号的定义：

```vim
:help key-notation
```

这会打开一张完整的对照表，涵盖了从 `F1` 到 `<ScrollWheelUp>` 的所有记号定义。

**总结：** 虽然它看起来不够“通俗”，但它是目前最**精确、无歧义且跨平台**的表达方式。一旦你习惯了这套逻辑，你会发现它比“按住 Ctrl 的同时按下 H 键”这种描述要高效得多。

## 识读指南

在 Vim 的语境下，这些符号被称为 **Key Notation**（按键表示法）。以下是基于 LazyVim 逻辑的识读指南：

------

### 1. 核心修饰键 (Modifier Keys)

在表达式中，尖括号 `< >` 包裹的是一个完整的按键指令。`-`链接的两个符号(按键)表示组合键中前一个按键按住不放的情况下再按第下一个键;

| **表达式**     | **对应键盘按键**   | **说明**                                           |
| -------------- | ------------------ | -------------------------------------------------- |
| **`<leader>`** | **空格键 (Space)** | LazyVim 默认将其设为空格，它是所有快捷键的“开头”。 |
| **`<C-...>`**  | **Control (Ctrl)** | 例如 `<C-h>` 就是 `Ctrl + h`。                     |
| **`<M-...>`**  | **Option (Alt)**   | M 代表 Meta 键，在 Mac 上通常对应 `Option`。       |
| **`<S-...>`**  | **Shift**          | 例如 `<S-Tab>` 就是 `Shift + Tab`。                |
| **`<CR>`**     | **Enter (回车)**   | CR 代表 Carriage Return。                          |
| **`<esc>`**    | **Escape**         | 退出键。                                           |

------

### 2. 为什么长按空格会弹出菜单？ (Which-Key)

LazyVim 默认安装了 **which-key.nvim**。当你按下 `<leader>`（空格）并停顿时，它会实时读取当前的快捷键字典并显示出来。

- **如果你看到 `+file/find`**：这意味着这只是一个“分类”，你需要再按下一个键（比如 `f`）才能看到具体的命令。
- **如果你看到 `Buffer`**：这通常对应 `<leader>b`，表示与当前打开的文件窗口有关的操作。

------

### 3. 常见的快捷键组合识读

试着翻译下面这些 LazyVim 常用快捷键：

- **`<leader>ff`** → 按空格，再按 f，再按 f (Find Files)：**打开文件搜索**。
- **`<leader>/`** → 按空格，再按斜杠：**在当前项目全局搜索文字**。
- **`<leader>e`** → 按空格，再按 e (Explorer)：**打开左侧文件树**。
- **`[d` 或 `]d`** → 按左/右中括号，再按 d：在代码错误（Diagnostics）之间**跳往上一个/下一个**。

------

### 4. 模式 (Modes) 的隐形前缀

Vim 的快捷键在不同状态下功能不同。虽然文档可能没写，但你需要知道：

- **Normal Mode (普通模式)**：按下 `Esc` 后的状态。大多数 `<leader>` 开头的键都在这里运行。
- **Insert Mode (插入模式)**：打字状态。在此模式下，快捷键通常以 `<C-...>` 开头。
- **Visual Mode (可视化模式)**：选中文本状态。有些快捷键（如格式化）只在选中后有效。

------

### 5. 哪里有官方文档？

LazyVim 的设计理念是“自文档化”，你不需要去翻网页，直接在编辑器里就能看：

1. **在线文档**：访问 [LazyVim Keymaps](https://www.lazyvim.org/keymaps)。这里按分类（文件、搜索、LSP）列出了所有默认快捷键。
2. **本地查看**：在 Neovim 中输入 `:help lazyvim.txt`。
3. **实时查找**：最实用的方法——直接按 **`<leader>sk`** (Search Keymaps)。这会弹出一个搜索框，你可以输入“find”或“git”，它会告诉你对应的快捷键是什么。

### 💡 给新手的建议

你不需要背诵这些。当你想要实现某个功能时（比如“我想关掉这个窗口”），先按一下 **空格**，然后看底部的提示栏，寻找相关的单词（比如 `w` 代表 Window，`q` 代表 Quit）。
