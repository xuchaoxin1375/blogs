## 参数

> bash中的许多规则用法不太符合直觉,或说不太现代化,参数部分内容就比较典型
>
> 一方面bash是一门shell语言,另一方面bash诞生较早,于上个世纪,功能和设计老旧是一方面,bash还要考虑兼容性,导致一些反直觉的用法和规则

**参数**是内存中的一种**命名空间**，可用于**检索或存储信息**。(参数可理解为存储可通过符号或名称检索的数据)

一般来说，它们用于**存储字符串数据，但也可用于存储整数、索引数组和关联数组**。

> 关联数组有些地方也称为字典或哈希表

**参数**分为两种： *变量*和*特殊参数* 。

- **特殊参数**是**只读**的，由 BASH **预先设置**，用于传递某种**内部状态**。
- 变量是您可以**自行创建和更新的参数**。
- bash中,变量实际上只是参数的一种

不过,bash中的参数更像是其他编程语言中的变量,不过高级编程语言的变量类型比较多,比如可以定义只读变量类型等,bash比较简化

bash语言作为典型的shell语言,编写的代码一般是一行行命令构成的,而变量(被当做参数)被命令引用,也就把变量归入参数的范畴

还需要明白一点,被定义好的变量或参数不能脱离命令而存在,bash遇到一个命令行(单行或多行),总是要试图找到一个命令,然后运行它,即便只是打印某个变量值,也得调用某个命令(通常是`echo`命令)

不过更加现代的脚本语言更加智能,它在常见场景下会推测用户的意图,比如`powershell`,而脚本语言(`python`等)的交互模式也一般也支持意图推测

> ```powershell
> #⚡️[Administrator@CXXUDESK][~\Desktop][9:24:10] PS >
>  $b=123
> #⚡️[Administrator@CXXUDESK][~\Desktop][9:37:41] PS >
>  $b
> 123
> ```
>
> 效果相当于`echo $b`



### 变量名称规则

*名称* ：仅由**字母、数字和下划线**组成的单词，以**字母或下划线**开头(数字可以出现在变量中,但是不能做为首字符)。

变量名称也称为***标识符*** 。

要将数据存储在变量中，我们使用以下*赋值*语法：



```bash
varname=vardata
```

> 注意,和bash的变量赋值和高级编程语言有显著不同,特别是定义字符串变量,字符串可以不使用引号包裹，除非字符串包含引号
>
> 另一方面重要的不同是引用已定义的变量,需要使用`$`引用变量

**shell 的参数并不以 `$` 符号开头**

`$`和已经定义的参数(变量)一起出现,只是因为**bash使用`$`让被引用的参数(变量)展开,`$`**不是参数(变量)的一部分

bash和python类似是弱类型的,仍然有细节上的不同,无论是变量定义还是变量的使用上

> php和powershell这两种脚本语言在定义变量上和bash更加类似,但仍然有显著的不同,这两种语言定义变量时,变量名需要带有`$`,而bash不需要也不可以用`$`开头做定义变量语句,但是引用先前定义好的变量却都类似,都使用`$`引用变量名

在bash这类shell语言中,之所以要使用`$varname`的形式来引用变量,这种符号和命令以及关键字有显著差异,便于bash解析代码,且对于一个bash代码片段,哪些单词是变量就一目了然,相比于bash,php和powershell更加彻底,在定义变量的时候也要求变量名前面是个`$`符号,这允许更加宽松的`=`附近的空格存在性,0个或多个空格都不影响解析,而bash由于定义变量时没有`$`引出变量,从而有和命令混淆的风险,因此bash规定,定义变量时,`=`附近不能有任何空格,否则`=`前的符号被解释为命令而不是变量.

> 另外注意,由于大多数编程语言不关心变量定义语句(甚至是赋值以及其他角色中)`=`两侧的空格数量,且许多代码格式化(排版)工具会为`=`两侧提供1个空格和其他单词分割开来,但在bash中这是严重的错误行为,所以要选对格式化工具!
>
> 在大多数高级编程语言中,定义变量和引用变量都不需要`$`来引出,好处是不用少打1个字符,也不会因为忘记添加`$`而导致变量引用失败

此命令将数据 `vardata` 赋值给名为 `varname` 的变量。

### 连续定义变量

同一行内可以定义多个变量,两个定义变量的语句可以用空格分隔(这种情况下,需要注意各个变量取值,使用引号包裹比较保险)

```bash
myname='Greg Wooledge' yourname='Someone Else'
```

```bash
# root@CxxuColorfulWin10 21:24:43> <.../cxxu/Desktop>
$ myname='Greg Wooledge' yourname='Someone Else'
# root@CxxuColorfulWin10 21:24:45> <.../cxxu/Desktop>
$ echo "$myname;$yourname"
Greg Wooledge;Someone Else
```

虽然可以定义在同一行,但是通常不推荐这么做,代码可读性不好

### 变量访问和参数扩展🎈

要**访问存储在变量中的数据**，我们使用[参数扩展 ](https://mywiki.wooledge.org/BashGuide/Parameters#Parameter_Expansion)。

参数扩展是指用参数的值*替换原有*参数，也就是说，语法告诉 Bash 你想使用变量的内容。之后，Bash *可能还会对结果进行其他操作* 。这是一个非常重要的概念，必须正确理解，因为**它与其他编程语言处理变量的方式截然不同**！

为了说明什么是参数扩展，我们来看这个例子：



```bash
$ foo=bar
$ echo "Foo is $foo"
```

当 Bash 即将执行你的代码时，它首先会修改命令，将你的参数展开（ `$foo` ）替换为 `foo` 的内容，即 `bar` 。

命令变为：

```bash
$ echo "Foo is bar"
Foo is bar
```



现在，Bash 已准备好执行命令。执行命令后，屏幕上会显示这句简单的句子。

理解参数扩展会导致 `$parameter` 被其内容**替换** ，这一点很重要。

### 整数型变量在算数上下文中的使用

算数上下文,比如`$((...))`以及`${array[...]}`(其中`...`表示某个算数表达式)

如果变量`i`是一个整数,那么其参与数学计算的时候,例如为其加1,`i=i+1`,这比较符合现代变成语言的写法和习惯

> 与字符串类型的变量不同,通常都是`$`或`${}`扩展(并且通常要用双引号在外围包裹)

```bash
i=1
echo $((i=i+1))
# output:2
```



### 变量内容替换和括号保护

和C语言中的**宏**替换类似,使用这类**直接替换**的处理方式在使用时要小心,特别是带有空格的情况

> 和编程中的变量不同,在变量的使用方式上,参数扩展(直接替换内容)是原始而粗暴的方式,对于初学者(尤其是学习过其他编程语言的人)容易引发意外行为

请注意以下示例:

```bash
$ song="My song.mp3"
$ rm $song
rm: My: No such file or directory
rm: song.mp3: No such file or directory
```



为什么这样做行不通？因为 Bash 会将你的 `$song` 替换成它的内容，也就是 `My song.mp3` ；然后进行单词分割；最后才执行命令。

> 定义`song`变量的语句中的`""`会被bash丢弃,并不会存储到song变量中,`""`的作用只是让bash将`My song.mp3`当做一个整体(单个字符串)而不是两个分开的单词(2个字符串)

这就像你输入了这样一段话：



```bash
$ rm My song.mp3
```



根据单词分割规则，Bash 认为您是想用 `My` 和 `song.mp3` 表示两个不同的文件，因为它们之间有空格，而且没有用引号括起来。

我们该如何解决这个问题呢？记住， **每次参数展开都要用双引号括起来**

## 特殊参数和变量



在正式开始之前，我们先来理清一下术语。 *参数*和*变量*是不同的概念。

**变量实际上只是参数的一种**：它们都带有名称。

而那些**不是变量的参数**则被称为***特殊参数*** 。

例如

```bash
$ # Some parameters that aren't variables:
$ echo "My shell is $0, and has these options set: $-"
My shell is -bash, and has these options set: himB
$ # Some parameters that ARE variables:
$ echo "I am $LOGNAME, and I live at $HOME."
I am lhunath, and I live at /home/lhunath.
```



**请注意** ：与 PHP/Perl 等语言不同，shell 的参数并不以 `$` 符号开头。示例中的 `$` 符号仅用于*展开*其后的参数。**展开的本质是 shell 会将参数替换为其内容。**因此， `LOGNAME` 是包含您用户名的参数（变量）。

bash中 `$LOGNAME` 是一个**表达式**，它将被替换为该变量的内容，在我的示例中是 `lhunath` 。

### 小结

请记住，Bash 不是 Perl 或 PHP。您需要非常清楚*扩展*机制的工作原理，才能避免出现**大**问题。否则，您的脚本最终会变得非常危险，尤其是在使用 `rm` 时犯这样的错误：



```bash
$ ls
no secret  secret
$ file='no secret'
$ rm $file
rm: cannot remove `no': No such file or directory
```



假设我们有两个文件， `no secret` 和 `secret` 。第一个文件没有任何有用的信息，而第二个文件却包含着拯救世界免于毁灭的秘密。你粗心大意地忘记**给**参数 `file` 加上引号。Bash 展开了参数，结果是 `rm no secret` 。Bash 像往常一样用空格分割参数，结果 `rm` 被传递了两个参数：'no' 和 'secret'。因此，它找不到文件 `no` ，并删除了文件 `secret` 。 *秘密就此丢失！*

### **良好实践** 

你应该**始终使用引号正确地括起参数扩展**(即便有些时候引号不是必须的,但也应该加上)。这样可以防止参数扩展中的**空格**或可能存在的**乱码**让你头疼不已，甚至意外地清除电脑上的数据。**只有用引号括起来的参数扩展才是好的**。

## 总结

------



- *变量* ：变量是一种可以直接创建和修改的参数。它由一个名称表示，该名称必须以字母或下划线（ `_` ）开头，并且只能由字母、数字和下划线组成。变量名称区分大小写。
- *扩展* ：**当参数以美元符号开头时，就会发生扩展**。但是安全的扩展应该是用引号包裹的,否则有潜在的风险;扩展参数后,Bash 会获取参数的值，并在执行命令前将其扩展形式替换为参数的实际值。这也称为*替换* 。

## 变量类型



虽然 Bash 不是一种类型语言，但它确实有几种不同类型的变量。这些类型定义了变量可以包含的内容类型。类型信息由 Bash 内部存储。

- **数组** ： `declare -a ` *变量* ：该变量是一个字符串数组。
- **关联数组** ： `declare -A ` *变量* ：该变量是一个字符串关联数组（bash 4.0 或更高版本）。
- **整数** ： `declare -i ` *变量* ：该变量保存一个整数。为该变量赋值会自动触发*算术求值* 。
- **只读** ： `declare -r ` *变量* ：该变量无法再进行修改或取消设置。
- **导出** ： `declare -x ` *变量* ：该变量被标记为导出，这意味着它将被任何子进程继承。

[数组](https://mywiki.wooledge.org/BashGuide/Arrays)本质上是字符串的索引列表。它们非常方便，因为它们能够将多个字符串存储在一起，而无需依赖*分隔符*来分隔它们（正确使用分隔符很繁琐，错误使用分隔符则容易出错）。

将变量定义为整数的优点在于，在赋值或修改变量时可以省略一些语法：



```
$ a=5; a+=2; echo "$a"; unset a
52
$ a=5; let a+=2; echo "$a"; unset a
7
$ declare -i a=5; a+=2; echo "$a"; unset a
7
$ a=5+2; echo "$a"; unset a
5+2
$ declare -i a=5+2; echo "$a"; unset a
7
```



然而，在实践中，使用 `declare -i` 的情况极其罕见。这主要是因为 `declare -i` 会产生一些令脚本维护者感到意外的行为，尤其是在他们忽略了 `declare` 语句的情况下。大多数经验丰富的 shell 脚本编写者在需要执行算术运算时，更倾向于使用显式的算术命令（使用 `((...))` 或 `let` ）。

很少见到使用 `declare -a` 显式声明数组的情况。通常只需写 `array=(...)` ，Bash 就会知道该变量现在是一个数组。唯一的例外是关联数组，它*必须*显式声明： `declare -A myarray` 。



------



- *字符串* ：字符串是一系列字符。
- *数组* ：数组是由数字索引的字符串列表。
- *整数* ：整数是正数、负数或零。
- *只读* ：只读参数不能修改或取消设置。
- *导出* ：标记为导出的变量将被任何子进程继承。以这种方式继承的变量称为*环境变量* 。

## 参数扩展



*参数扩展*是指任何导致参数展开（被内容替换）的操作。最基本的参数扩展方式是在参数名称前加上 `$` 符号。在某些情况下，还需要在参数名称周围添加花括号：



```bash
$ echo "'$USER', '$USERs', '${USER}s'"
'lhunath', '', 'lhunaths'
```



这个例子展示了基本参数扩展 (PE) 的形式。第二个 PE 的结果是一个空字符串。这是因为参数 `USERs` 为空。我们原本并不打算让 `s` 成为参数名的一部分。由于 Bash 无法知道你想要在参数值后附加一个字面值 `s` ，所以你需要使用花括号来标记参数名的开头和结尾。这就是我们在上面示例中的第三个 PE 所做的。

*参数扩展*还为我们提供了修改待扩展字符串的技巧。这些操作非常方便：



```bash
$ for file in *.JPG *.jpeg
do mv -- "$file" "${file%.*}.jpg"
done
```



上述代码可以将所有扩展名为 `.JPG` 或 `.jpeg` 的 JPEG 文件重命名为标准的 `.jpg` 扩展名。表达式 `${file%.*}` 会截断从最后一个句点开始的所有内容（ `.` ）。然后，在相同的引号内，将新的扩展名附加到扩展结果之后。

以下是大部分可用的体育教育技巧的总结：

| **句法**                     | **描述**                                                     |
| ---------------------------- | ------------------------------------------------------------ |
| `${parameter:-word}`         | **使用默认值** 。如果“ `parameter` ”未设置或为空，则替换为“ `word` ”（可能是扩展）。否则，替换为“ `parameter` ”的值。 |
| `${parameter:=word}`         | **分配默认值** 。如果“ `parameter` ”未设置或为空，则将“ `word` ”（可能是扩展）赋值给“ `parameter` ”。然后替换为“ `parameter` ”的值。 |
| `${parameter:+word}`         | **使用备选值** 。如果“ `parameter'` ”为空或未设置，则不进行任何替换；否则，将替换为“ `word` ”（可能是扩展）。 |
| `${parameter:offset:length}` | **子字符串扩展** 。从 ' `offset` '（索引从 0 开始）指定的字符开始，扩展 ' `parameter` ' 至多 ' `length` ' 个字符。如果省略 ' `:length` '，则一直扩展到末尾。如果 ' `offset` ' 为负数（请使用括号！），则从 ' `parameter` ' 的末尾向后计数，而不是从开头向前计数。如果 ' `parameter` ' 是 @ 符号或以 @ 或 * 为下标的索引数组名，则结果分别为 ' `length` ' 个位置参数或数组元素，从 ' `offset` ' 开始。 |
| `${#parameter}`              | 将' `parameter` '的值替换为字符长度。如果' `parameter` '是带有下标@或*的数组名，则返回元素个数。 |
| `${parameter#pattern}`       | 将“ `pattern` ”与“ `parameter` ”的**开头**进行匹配。结果是“ `parameter` ”的扩展值，其中删除了最短的匹配项。 如果数组名“ `parameter` ”以@或*作为下标，则对每个元素执行此操作。后续所有元素均适用。 |
| `${parameter##pattern}`      | 与上述相同，但删除*最长的*匹配项。                           |
| `${parameter%pattern}`       | 将“ `pattern` ”与“ `parameter` ”的**末尾**进行匹配。结果是“ `parameter` ”的扩展值，其中最短的匹配项已被删除。 |
| `${parameter%%pattern}`      | 与上述相同，但删除*最长的*匹配项。                           |
| `${parameter/pat/string}`    | 结果是将“ `parameter` ”扩展为**第一个** （未锚定的）匹配项“ `pat` ”替换为“ `string` ”。如果缺少“ `/string` ”部分，则假定为空字符串。 |
| `${parameter//pat/string}`   | 与上述相同，但**每个**匹配项“ `pat` ”都会被替换。            |
| `${parameter/#pat/string}`   | 与上述相同，但匹配的是**开头部分** 。可用于添加带有空模式的常用前缀： `"${array[@]/#/prefix}"` 。 |
| `${parameter/%pat/string}`   | 与上述相同，但匹配的是**末尾字符** 。可用于添加带有空模式的常用后缀。 |



你会在经验中学会它们。它们的实用性远超你的想象。以下是一些入门示例：



```bash
$ file="$HOME/.secrets/007"; \
echo "File location: $file"; \
echo "Filename: ${file##*/}"; \
echo "Directory of file: ${file%/*}"; \
echo "Non-secret file: ${file/secrets/not_secret}"; \
echo; \
echo "Other file location: ${other:-There is no other file}"; \
echo "Using file if there is no other file: ${other:=$file}"; \
echo "Other filename: ${other##*/}"; \
echo "Other file location length: ${#other}"
File location: /home/lhunath/.secrets/007
Filename: 007
Directory of file: /home/lhunath/.secrets
Non-secret file: /home/lhunath/.not_secret/007

Other file location: There is no other file
Using file if there is no other file: /home/lhunath/.secrets/007
Other filename: 007
Other file location length: 26
```



记住 `${v#p}` 和 `${v##p}` 之间的区别。 `#` 字符重复出现意味着模式将变为贪婪模式。 `%` 也是如此：



```bash
$ version=1.5.9; echo "MAJOR: ${version%%.*}, MINOR: ${version#*.}."
MAJOR: 1, MINOR: 5.9.
$ echo "Dash: ${version/./-}, Dashes: ${version//./-}."
Dash: 1-5.9, Dashes: 1-5-9.
```



注意： **不能**同时使用多个参数执行指令 (PE)。如果需要对一个参数执行多个 PE，则需要使用多条语句：



```bash
$ file=$HOME/image.jpg; file=${file##*/}; echo "${file%.*}"
image
```
