## abstract

`sed` 是 **Stream Editor**（流编辑器）的缩写，而 `gsed` 特指 **GNU 版的 sed**。

它们之间的差别主要源于**操作系统发行版**的不同。在 Linux 系统上，你平时用的 `sed` 通常就是 GNU sed；但在 macOS 或 BSD 系统上，自带的 `sed` 是 BSD 版本，功能相对精简。

以下是它们的主要区别：

------

### 1. 核心定义

- **sed (BSD/macOS):** 遵循 POSIX 标准，功能比较“复古”和严谨，很多高级语法不支持。
- **gsed (GNU sed):** 也就是 GNU 版本的 sed。它在 POSIX 标准之上增加了大量的扩展功能，更强大、更易用。在 macOS 上，用户通常通过 `brew install gsed` 来安装它，以获得和 Linux 一致的体验。

------

### 2. 关键语法差异

#### **`-i` 参数（就地编辑）**

这是最容易让人抓狂的区别。

- **gsed:** 可以直接使用 `sed -i 's/a/b/g' file.txt`。
- **sed (BSD):** 要求强制指定备份扩展名。如果你不想备份，必须加一个空字符串：`sed -i '' 's/a/b/g' file.txt`。如果不加 `''`，它会报错或者把你的文件名弄乱。

#### **正则表达式支持**

- **gsed:** 支持更现代的正则表达式扩展，比如 `\+|?|{}` 等，并且支持 `\s`（空白符）、`\w`（单词字符）等快捷转义。
- **sed (BSD):** 对这些支持较弱，通常需要使用 `-E` 参数来开启扩展正则表达式，且不支持 `\s` 这种 GNU 特有的转义。

#### **换行符的处理**

- **gsed:** 可以直接在字符串里用 `\n` 来代表换行，例如 `sed 's/,/\n/g'`。
- **sed (BSD):** 很难直接处理 `\n`。如果你想插入换行，通常需要敲一个反斜杠然后真的按回车换行，或者利用 Bash 的 `$'...'` 语法。

------

### 3. 功能对比表

| **特性**          | **sed (BSD/macOS)**      | **gsed (GNU sed)**   |
| ----------------- | ------------------------ | -------------------- |
| **就地编辑**      | `sed -i ''` (必须带引号) | `sed -i` (简单直接)  |
| **扩展正则**      | `sed -E`                 | `sed -r` 或 `sed -E` |
| **\s, \w 支持**   | 不支持                   | 支持                 |
| **\n 换行符替换** | 极其困难                 | 支持良好             |
| **性能**          | 稍快（因为功能少）       | 极佳                 |

------

### 4. 为什么大家推荐在 Mac 上用 gsed？

如果你在网上搜到一个比较复杂的 `sed` 脚本（比如在 GitHub 或 StackOverflow 上），它们大概率是基于 **GNU sed** 写的。如果你直接在 Mac 的终端运行，经常会报“illegal option”或“command cannot be parsed”的错误。

**建议：**

如果你是开发者，且经常需要在 Linux 服务器和 macOS 本地切换，最省心的方法是在 Mac 上：

1. `brew install gnu-sed`
2. 在 `.zshrc` 或 `.bash_profile` 里给它设置别名：`alias sed='gsed'`。

这样你就能在两个平台上享受一致的丝滑体验了。
