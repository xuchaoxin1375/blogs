### 常见文件传输协议

- 常见文件传输协议包括但不限于以下几种：

  1. **文件传输协议 (FTP, File Transfer Protocol)**
     - FTP 是一种基于TCP/IP的传统网络协议，用于在网络上进行文件传输，包括上传、下载和管理文件。FTP使用两个连接：一个控制连接（默认端口21）用于命令交互，另一个数据连接（动态端口，默认端口范围为20）用于实际的数据传输。FTP存在明显的安全隐患，因为它在未经加密的情况下传输用户名、密码和数据，所以现代应用中更多使用FTPS（FTP over SSL/TLS）或SFTP（SSH文件传输协议）。
  2. **超文本传输协议 (HTTP, Hypertext Transfer Protocol)**
     - HTTP 主要用于万维网的网页浏览和数据传输，也可以用于传输任何类型的数据，特别是通过HTTP(S)下载文件。HTTP(S)支持身份验证、状态管理和缓存等功能，但默认情况下，HTTP不提供文件管理功能，而是通过Web服务接口来实现。
  3. **SSH文件传输协议 (SFTP, SSH File Transfer Protocol)**
     - SFTP 是SSH协议的一部分，它使用安全的SSH连接在服务器之间传输文件。SFTP不是FTP在SSH上简单封装，而是一个独立的设计，提供了类似FTP的文件操作功能，如文件列表查看、文件上传下载、目录创建删除等，但所有操作都在加密的SSH连接内进行。
  4. **安全复制 (SCP, Secure Copy)**
     - SCP 也是一个基于SSH的安全文件传输工具，允许用户在本地和远程主机之间加密复制文件和目录。
  5. **简单文件传输协议 (TFTP, Trivial File Transfer Protocol)**
     - TFTP 是一个轻量级的文件传输协议，常用于网络设备初始化、系统引导等场合，它不需要复杂的用户身份验证过程，但传输时不加密，只支持基本的文件读写操作。


### FTP协议及其发展

- [File Transfer Protocol - Wikipedia](https://en.wikipedia.org/wiki/File_Transfer_Protocol)

- 文件传输协议（File Transfer Protocol，简称FTP）是一种用于在网络上进行文件传输的标准通信协议，它是因特网最早的应用服务之一，由Abhay Bhushan在1971年制定，并在之后经过多次修订和发展。

- FTP主要用于在客户端和服务器之间进行文件的上传和下载，以及其他相关的文件管理操作，如创建、删除目录，重命名文件等。

- FTP基于客户端-服务器模型运行，它在OSI模型中的应用层运作，并依赖于传输层的TCP协议（传输控制协议）来确保数据传输的可靠性和顺序性。FTP支持两种连接模式：
  1. **主动模式**（PORT）：服务器开启一个随机端口等待客户端连接来进行数据传输。
  2. **被动模式**（PASV）：服务器告诉客户端一个临时端口号，客户端发起连接进行数据传输。

  FTP可以通过用户名和密码进行身份验证，允许用户访问受保护的文件资源。此外，为了增强安全性，还有FTPS（FTP over SSL/TLS）和SFTP（SSH File Transfer Protocol）变种，它们提供了对数据传输过程的加密。

  随着技术发展，虽然FTP在某些场景下仍在使用，但由于其明文传输密码和数据的不安全性，现在越来越多的情况被更为安全的协议替代，如SCP、SFTP和HTTPS等。

#### 补充

- FTP 可以运行在主动或被动模式下，这决定了数据连接的建立方式

  这种“模式”的含义与FTP协议中的MODE命令的含义不同。

- In active mode, the client starts listening for incoming data connections from the server on port M. It sends the FTP command PORT M to inform the server on which port it is listening. The server then initiates a data channel to the client from its port 20, the FTP server data port.

  In situations where the client is behind a firewall and unable to accept incoming TCP connections, *passive mode* may be used. In this mode, the client uses the control connection to send a PASV command to the server and then receives a server IP address and server port number from the server, which the client then uses to open a data connection from an arbitrary client port to the server IP address and server port number received

- 在主动模式下，客户端开始在端口M上监听来自服务器的数据连接请求。它通过发送FTP命令“PORT M”告知服务器其正在监听哪个端口。然后，服务器从其固定的FTP服务器数据端口20启动一个数据通道，连接到客户端。

  而在遇到客户端位于防火墙后面，无法接受外来TCP连接的情况时，可以采用**被动模式**。在这个模式中，客户端通过控制连接向服务器发送PASV命令，然后接收到来自服务器的服务器IP地址和服务器端口号。接着，客户端使用这些信息，从任意一个客户端端口向接收到的服务器IP地址和服务器端口号发起数据连接。

  总之，在主动模式下，服务器主动发起数据连接；而在被动模式下，客户端主动发起数据连接，这样就能适应那些由于防火墙或NAT（网络地址转换）导致客户端不能接受服务器直接连接的网络环境。

- 这两种模式均于 1998 年 9 月更新以支持 IPv6。当时对被动模式进行了进一步的修改，将其更新为扩展被动模式。 

  服务器通过控制连接以 ASCII 格式的三位数状态代码和可选文本消息进行响应。例如，“200”（或“200 OK”）表示最后一个命令成功。数字代表响应的代码，可选文本代表人类可读的解释或请求（例如<需要帐户来存储文件>）。使用通过控制连接发送的中断消息可以中止通过数据连接正在进行的文件数据传输。

### 两种模式的比较

主动模式（Active/PORT Mode）与被动模式（Passive/PASV Mode）在FTP协议中的异同如下：

**相同点：**
1. **控制连接建立方式一致**：无论主动模式还是被动模式，FTP客户端都会先建立到FTP服务器21端口的控制连接，用于传输命令和响应。

2. **目的**：两者都是为了实现FTP客户端和服务器之间的数据传输，例如上传或下载文件。

**不同点：**
1. **数据连接建立方式：**
   - **主动模式**：
     - 客户端告诉服务器它将使用的数据端口号（大于1023的随机端口）。
     - 服务器使用其固定的FTP数据端口（通常是20）主动连接到客户端所提供的端口。
   - **被动模式**：
     - 客户端发送PASV命令请求服务器提供一个数据端口。
     - 服务器随机选择一个高阶端口并通知客户端，然后服务器在选定的端口上等待连接。
     - 客户端根据服务器提供的信息，从自身的随机端口主动发起数据连接到服务器的指定端口。

2. **网络环境适应性：**
   - **主动模式**：在网络环境简单，或者FTP服务器可以直接访问客户端所指定端口的情况下适用。但在有防火墙、NAT设备且配置不支持外向连接的网络中，主动模式往往难以正常工作。
   - **被动模式**：特别适合于客户端位于NAT或防火墙之后的场景，因为它总是由客户端发起数据连接，更容易穿越网络边界。

3. **安全和配置要求：**
   - **主动模式**：服务器需要能够发起对外连接，可能需要针对服务器端的安全策略进行特定配置。
   - **被动模式**：服务器需要能够监听任意高位端口，并且在有些情况下，需要在防火墙或NAT设备上打开足够大的端口范围以供FTP服务器被动模式使用。

综上所述，主动模式和被动模式在FTP数据连接的建立方面有着显著的不同，主要是谁发起连接以及连接的目标端口如何确定，而这两种模式的选择通常取决于具体的网络配置和安全要求。

#### 双端口

FTP 需要两个端口（一个用于发送，一个用于接收），因为它最初设计为在网络控制协议 (NCP) 之上运行，该协议是一种单工协议，利用两个端口地址，建立两个连接，以进行双向通信。为每个应用层应用程序或协议保留一个奇数和一个偶数端口。

 TCP 和 UDP 的标准化将每个应用程序使用两个单工端口的需求减少到一个双工端口，: 15  但 FTP 协议从未更改为仅使用一个端口，而是继续使用两个端口以实现向后兼容性。

### 浏览器对FTP的支持停止

- FTP 客户端过去通常集成在 Web 浏览器中，使用 URI 前缀“ftp://”浏览文件服务器。
-  2021 年，两大网络浏览器供应商 Google Chrome 和 Firefox  放弃了 FTP 支持，因为它被更安全的 SFTP 和 FTPS 取代；

### 下载协议

#### eDonkey2000 Network (ed2k) 协议：

eDonkey2000协议，通常简称为ed2k，是由Jed McCaleb在2000年左右开发的一种点对点（P2P）文件共享协议。这个协议最知名的应用是eMule等文件共享客户端软件。在ed2k网络中，用户通过客户端软件连接到eDonkey服务器检索文件索引信息，并通过P2P方式与其他客户端直接交换文件内容。ed2k协议允许文件被分割成多个区块进行传输，支持断点续传，这意味着即使在下载过程中断开连接，重新连接后可以从上次断开的地方继续下载。

**特点：**
- 依赖服务器索引文件信息，但实际文件数据交换是P2P模式。
- 支持大文件分割传输，提供文件完整性检查机制。
- 用户在下载的同时上传已下载的部分，实现资源共享。

#### BitTorrent (BT) 协议：

BitTorrent协议，由Bram Cohen在2001年发明，是另一种流行的P2P文件共享协议，因其高效的大文件分发能力而广受欢迎。在BT网络中，每个参与下载的用户被称为一个“peer”，其中包括“leecher”（下载者）和“seeder”（上传者）。用户通过.torrent文件（种子文件）启动下载，文件中包含文件的元数据和Tracker服务器的信息。

**特点：**
- 完全去中心化的P2P网络，没有单一的服务器集中索引文件。
- 文件被分成多个小块，每个块都可以独立下载并上传。
- 使用Tracker服务器协调peer之间的通信，但现在也有DHT（分布式哈希表）技术实现去Tracker的P2P共享。
- 用户下载文件的同时上传自己已有的文件块，鼓励公平分享。
- 速度取决于网络中seeders的数量和上传带宽，种子越多，下载速度越快。

**总结：**

ed2k和BT协议都是点对点文件共享技术，但它们在网络结构、文件传输方式和资源发现机制上存在明显差异。ed2k结合了中心服务器和P2P模式，而BT协议则更强调纯粹的P2P传播机制，且在文件碎片化传输、下载速度和资源利用率等方面表现出更高的效率。

`scp` 和 `SMB (Server Message Block)` 协议虽然都提供了文件传输和共享的功能，但它们在设计目标、应用场景和技术实现上有显著的不同：

### scp vs smb(Samba)

**scp (Secure Copy Protocol):**
- scp 是基于 SSH (Secure Shell) 协议的一个应用层协议，主要用于在不同主机之间安全地复制文件和目录。
- 它通常在命令行界面使用，例如Unix/Linux系统中的`scp`命令，可用于在两台机器之间加密传输数据。
- scp 默认情况下提供强大的安全性，因为它依赖于SSH协议的加密和认证机制。
- 使用scp时，用户需要知道远程主机的用户名、IP地址或域名以及对应的SSH密钥或密码才能进行文件操作。
- scp 不支持文件夹级别的权限同步，也不支持网络文件系统的特性，比如文件锁定、多用户同时编辑同一文件等。

**SMB(Samba)**

- SMB 是一个网络文件共享协议，最初由Microsoft开发并广泛应用在Windows环境中，但Samba项目使其能在Linux和其他非Windows系统上实现兼容。
- SMB 支持文件和打印服务的共享，旨在实现在同一网络内的不同操作系统间的文件和资源的透明访问。
- 使用SMB协议，用户可以直接挂载远程共享文件夹作为本地磁盘使用，支持多用户同时访问、文件权限管理等功能。
- Samba服务器在内网和外网环境下都可以部署，可通过防火墙规则和用户权限设置保证一定的安全性。
- SMB不仅支持文件共享，还支持诸如打印机共享、交互式登录等功能。

#### 总结

- scp更适合简单的、单点对单点的安全文件传输任务，尤其是在涉及敏感数据时，它的加密传输机制更为可靠。
- SMB则适用于搭建企业级或家庭内部的文件服务器，提供多用户、多设备共享和协作环境，提供更多的网络文件系统特性，但相比scp，如果没有正确配置，其安全性可能会相对较低。不过现代SMB协议（如SMB3及以上版本）已经包含了很多提高安全性的功能，如AES加密、多通道验证等。
