## 链表和单链表



线性表链式存储结构的特点是：用一组任意的存储单元存储线性表的数据元素（这组存储单元可以是连续的，也可以是不连续的）。

因此，为了表示每个数据元素 $a_i$ 与其直接后继数据元素 $a_{i+1}$ 之间的逻辑关系，对数据元素 $a_i$ 来说，除了存储其本身的信息之外，还需存储一个指示其直接后继的信息（即直接后继的存储位置）。

这两部分信息组成数据元素 $a_i$ 的存储映像，称为**结点**（node）。它包括两个域：

- 其中存储数据元素信息的域称为数据域；
- 存储直接后继存储位置的域称为指针域。

指针域中存储的信息称作指针或链。$n$ 个结点（$a_i$（$1 \leq i \leq n$）的存储映像）链结成一个**链表**，即为**线性表** $(a_1, a_2, \cdots, a_n)$ 的**链式存储结构**。

又由于此链表的每个结点中只包含一个指针域，故又称**线性链表**或**单链表**。

## 链表分类

根据链表结点所含指针个数、指针指向和指针连接方式，可将链表分为**单链表、循环链表、双向链表、二叉链表、十字链表、邻接表、邻接多重表**等。

其中单链表、循环链表和双向链表用于实现**线性表**的链式存储结构，其他形式多用于实现树和图等**非线性结构**。

## 头指针|首元结点

整个链表的存取必须从**头指针**开始进行，头指针指示链表中第一个结点（即第一个数据元素的存储映像，也称**首元**结点）的存储位置。

同时，由于最后一个数据元素没有直接后继，则单链表中最后一个结点的指针为空（NULL）



## 头指针和头结点

通常用**头指针** $L$（或 head 等）来标识一个**单链表**，指出**链表的起始地址**，头指针为 NULL 时表示一个**空表**。

此外，为了操作上的方便，在**单链表第一个数据结点之前**附加一个结点，称为**头结点**。

头结点的数据域可以不设任何信息，但也可以记录表长等信息,但是不包含数据元素(否则链表的第一个结点就不是头结点,而是第一个元素结点)。

- 单链表带头结点时，头指针 $L$ 指向头结点。
- 单链表不带头结点时，头指针 $L$ 指向第一个数据结点。
- 表尾结点的指针域为 NULL（示意图中经常用 “^” 表示）

链表的第一个数据元素(结点)可以称为**首元**结点,和头结点不同,首元是链表的第一个存储数据元素的结点

假设有n个数据元素$a_{1},\cdots,a_{n}$要存入到一个单链表中去

如果要设立**头结点**,那么不妨设头结点为$a_{0}$,此时**头指针**$L$指向头结点$a_{0}$(此时头指针也是头结点的指针,首元结点的指针:`L->next`,首元结点的数据域`L->next->data`),$a_{0}$是链表的第一个结点,但不是首元(链表的第一个数据结点);

如果不设立头结点,那么头指针直接指向首元(数据结点)$a_{1}$,首元结点的指针就是`L`,首元结点的数据域为`L->data`

## 尾指针和单链表变体

- 在基础**单链表**附加尾指针,可以使许多操作的复杂度降低到$O(1)$,
  - 例如许多情况下操作集中在首元和尾元时,尾指针可以将访问尾结点的复杂度降低到O(1),但是访问尾元前一个结点仍然需要通过从头遍历找到尾元前驱
  - 如果是单链表变体,比如循环链表和双链表,情况又有不同,对于循环链表,尾指针的后继就是头结点或首元(通常循环链表不设头结点,但是设置尾指针,尾指针的后继就是首元,但是首元且难以一步访问到尾元,而且循环链表的任意一个元素开始,就可以遍历完整个链表,不必从头指针开始)
  - 而双链表的特点更加明显,访问任意结点的前驱只需要O(1)的时间,根据双链表的特定元素的指针,删除,插入结点的时间复杂度仅为O(1)
    - 在知道前驱的情况下,插入和删除操作的复杂度都为O(1)
    - 双链表可以降低插入和删除操作的时间复杂度,但是需要动的指针更多,所以维护更加复杂,但是相比于顺序表,链表的插入删除操作不需要移动元素,因此算方便
  - 虽然单链表中有变通的方法将删除和插入操作的复杂度降为O(1),但是严格(常规操作)复杂度是O(n),并且如果不做特别说明,一般认为是O(n)
- 但是于此同时,我们要维护尾指针,许多操作看似能降低复杂度的操作不会比只有头指针的时候的复杂度要低
  - 比如带尾指针的单链表的尾元删除操作,为了维护尾指针,需要遍历找到尾元前驱,将尾指针修改为尾元前驱.
- 首尾指针并一定都有更好,因为维护首尾指针所指的结点也需要操作成本,例如单链表删除尾结点,如果有尾指针,时间复杂度没有降低,还要维护尾指针
- 带有头结点或指针的循环双链表,执行首元和尾元的删除,头插和尾插元素的时间复杂度都为O(1);因为这种情况下,首(尾)附近的结点都可以在O(1)时间复杂度内访问到,插入和删除操作时间复杂度都是O(1)

## 概念辨析

- **首元结点**是指链表中存储第一个数据元素$a_{1}$的结点。
- **头结点**是在首元结点之前附设的一个结点，其指针域指向首元结点。头结点的数据城可以不存储任何信息，也可存储与数据元素类型相同的其他附加信息。例如，当数据元素为整数型时，头结点的数据域中可存放该线性表的长度。
- **头指针**是指向链表中第一个结点的指针。若链表设有头结点，则头指针所指结，点为线性表的头结点；若链表不设头结点，则头指针所指结点为该线性表的首元结点。

## 头结点和头指针的关系

不管带不带头结点，头指针都始终指向链表的第一个结点，而头结点是带头结点的链表中的第一个结点，结点内通常不存储信息。

引入头结点后，可以带来两个优点：

### 便于首元结点的处理

- 由于第一个**数据结点**(首元结点)的位置(地址)被存放在**头结点**的指针域中(首元结点也有其前驱结点,只不过这个前驱是非数据元素结点)，因此在链表的第一个数据结点位置上的操作和在表的其他位置上的结点操作一致，无须进行特殊处理。

### 便于空表和非空表的统一处理

- 无论链表是否为空，其**头指针**都是指向头结点的**非空指针**（空表中**头结点**的指针域为空），因此**空表和非空表**的处理也就得到了统一

## 单链表代码描述👺

```c
#define ElemType int //ElemType根据需要也可以定义为其他类型
// 结构体名字为LNode,完整引用为struct LNode,便于内部的指针域定义指针变量
typedef struct LNode
{                       // 定义单链表结点类型
    ElemType data;      // 数据域
    struct LNode *next; // 指针域
} LNode, *LinkList;

```



- 这里利用 `typedef` 定义了两个别名，`LNode` 为结构体类型，`LinkList` 为结构体指针类型。根据 `typedef` 的用法，`LNode,*LinkList` 表达式的值都是 `struct LNode` 类型，因此，`LNode` 是结构体类型，`LinkList` 是结构体指针类型。
- 这样后续要定义 `LNode` 结点可以形如 `LNode node;`，而定义 `LNode` 的指针变量形如 `LinkList node;`，这相当于 `LNode *node;`。这两种定义都表示 `node` 是指向 `LNode` 类型的指针变量。
- 也就是说，`LinkList` 从语法上和 `LNode*` 完全等价，也就是说，`LinkList` 这个指针类型不是必须要的，定义结点指针时可以 `LNode*` 类型替代。但是对此做名字区分可以提高可读性，前者用来定义链表（作为头指针），后者作为一般性结点的指针变量定义时使用。
- 习惯上，`LinkList` 用来定义单链表的头指针，例如 `LinkList L;` 这表示我们定义了一个名为 `L` 的单链表（头指针）。`LNode *node` 用来定义一个指向 `LNode` 类型的指针变量 `node`。这样的可读性比较好。

### 说明

（1）这里定义的是单链表中每个结点的存储结构，它包括两部分：存储结点的数据域 `data`，其类型用通用类型标识符 `ElemType` 表示.存储后继结点位置的指针域 `next`，其类型为指向结点的指针类型 `LNode *`。

（2）为了提高程序的可读性，在此对同一结构体指针类型起了两个名称，`LinkList` 与 `LNode *`，两者本质上是等价的，通常习惯上用 `LinkList` 定义类型，强调定义的是某个单链表的头指针；用 `LNode *` 定义指向单链表中任意结点的指针变量。

> 例如，若定义 `LinkList L`，则 `L` 为单链表的头指针，若定义 `LNode *p`，则 `p` 为指向单链表中某个结点的指针，用 `*p` 代表该结点。
>
> 当然也可以使用定义 `LinkList p`，这种定义形式完全等价于 `LNode *p`。

（3）单链表是由表头指针唯一确定，因此单链表可以用头指针的名字来命名。若头指针名是 `L`，则简称该链表为表 `L`。

（4）注意区分指针变量和结点变量两个不同的概念，若定义 `LinkList p` 或 `LNode *p`，则 `p` 为指向某结点的指针变量，表示该结点的地址；而 `*p` 为对应的结点变量，表示该结点的名称。

C语言中,一般使用`malloc`函数申请内存,然后将内存地址用`(LNode*)`来强制类型转换,赋值给辅助变量,例如

```c
LNode *s;
s=(LNode*)malloc(sizeof(LNode));//申请结点空间,然后赋值给对应类型的指针变量s
```

合并为一句,初始化指针变量`s`

```c
LNode *s=(LNode*)malloc(sizeof(LNode));
```

事实上,`LNode`直接定义变量

```c
LNode s;//直接定义一个未初始化的结点变量,此时s是LNode类型的变量而非指针变量
```

这种情况下,访问`s`的域写法如下:`s.data`,`s.next`

这个看似挺方便的,不需要malloc申请内存,但是如果我们要`s`作为辅助变量，来完成结点查找或表长计算等操作时,会有不便

以带头结点的单链表常见操作为例

```c
L->next;//带头结点的单链表的首元结点的指针
//将首元赋值给s
s=*(L->next);
//更改首元(头插法)
s.next=L->next;
L->next=&s;

```

```c
LNode *s;
//将首元赋值给s
s=L->next;
//更改首元(头插法)
s->next=L->next;
L->next=s;
```

可以看出,定义LNode类型的指针变量比LNode类型本身的变量在后续使用中更加方便,运算符号基本上都是`->`

### 两种情况判断空表语句

- 当链表不设头结点时，假设 $L$ 为单链表的头指针，它应该指向**首元结点**，则当单链表为长度 $n$ 为 0 的空表时，$L$ 指针为空（判定空表的条件可记为：`L == NULL`）。
- 增加头结点后，无论链表是否为空，头指针都是指向头结点的非空指针。若为空表，则头结点的指针域为空(头结点的后继为NULL)（判定空表的条件可记为：`L->next == NULL`,可见,和一般的数据结点判断后继结点是否为空的语句一样）

## 单链表的顺序存取(访问)

---

在顺序表中，由于逻辑上相邻的两个元素在物理位置上紧邻，则每个元素的存储位置都可从线性表的起始位置计算得到。

而在**单链表**中，各个元素的**存储位置都是随意**的。然而，每个元素的存储位置都包含在其直接前驱结点的信息之中。

由此，**单链表是非随机存取的存储结构**，要取得第 $i$ 个数据元素必须从头指针出发顺链进行寻找，也称为**顺序存取**的存取结构。

### 当前结点的指针变量的相关用法

假设 $p$ 是指向单链表中第 $i$ 个数据元素（结点 $a_i$，即数据域为 $a_i$ 的结点）的指针

#### 访问当前结点的后继结点

则 `p->next` 是指向第 $i+1$ 个数据元素（结点 $a_{i+1}$）的指针。

根据C语言的语法,`p->next`相当于`(*p).next`这里`(*p)`括号不能省略,因为成员访问运算符`.`的优先级高于间接寻址运算符`*`

#### 访问后继结点的数据元素

若 $\rm p\to data = a_i$，则 $\rm p\to next\to data = a_{i+1}$。

根据C语言的语法,`p->next->data`相当于`(*(*p).next).data`

可见,`->`运算符在这类情况下书写要方便的多,不需要套括号

### 后继共享|交接|委托|更新

结点插入和删除时常用

以插入为例:当前结点指针为p,新建结点的指针为s,将p的后继交接给s,`s->next=p->next`

### 访问前驱结点(插入|删除操作)

在插入新结点,删除数据结点操作中常用

由于单链表结构的限制,需要借助位置结点查找函数(复杂度为O(n))定位到第$i-1$个结点,然后在第$i$个结点处进行插入或删除结点操作,进行必要的结点指针域的维护;

事实上,有变通的方法可以实现O(1)复杂度的在指定位置结点`*p`前插入新结点算法(其中`p`是结点指针,`*p`表示结点本身);

做法是先将新结点`*s`插到`*p`后面,然后交换`*p,*s`结点内容

```c
s->next=p->next;
p->next=s;
tmp=p->data;
p->data=s->data;
s->data=tmp;
```

对于删除`*p`结点操作方法类似,也有O(1)复杂度的算法,先将`*p`的后继结点备份,然后删除后继(`p->next`结点),然后将备份的数据覆盖掉`*p`即可

```c
q=p->next; //记住p的后继,以便删除(释放对应结点的内存)
p->data=q->data;//或p->data=p->next->data;
p->next=q->next;
free(q);
```

## 线性表的顺序存取和随机存取

- 顺序表和链表都可以实现顺序存取(顺序存取要求低)
- 顺序表可以实现随机存取,链表只能顺序存取

## 静态链表

静态链表是用数组来描述线性表的链式存储结构，结点也有数据域data和指针域next,与前面所讲的链表中的指针不同的是，这里的指针是结点在数组中的相对地址（数组下标），又称**游标**。和顺序表一样，静态链表也要预先分配一块连续的内存空间。

静态链表以`next==-1`作为其结束的标志。静态链表的插入、删除操作与动态链表的相同，只需要修改指针，而不需要移动元素。

总体来说，静态链表没有单链表使用起来方便，但在一些不支持指针的高级语言(如Basic)中，这是一种非常巧妙的设计方法。

```c

// 静态链表
#define ElemType int
#define MaxSize 50
typedef struct SNode
{
    ElemType data;
    int next; // 使用数组下标表示指针域,而不是SNode类型的指针
} SLinkList[MaxSize];
/*
这里typedef 定义SLinkList 为数组类型,数组元素类型为struct Node类型;
根据C语言的typedef语法,SLinkList[...]表达式的值类型为struct SNode类型,因此SLinkList 是数组(第一个元素的指针);

这里我们并不直接定义一个静态链表类型SLinkList,而是定义SLinkList的结点类型SNode;最后用数组的声明方式将SNode的数组类型取名为SLinkList;(数组元素有MaxSize个)
 */

```

分开定义

```c

struct SNode
{
    ElemType data;
    int next; // 使用数组下标表示指针域,而不是SNode类型的指针
};
typedef struct SLinkList
{
    SNode list[MaxSize];//SNode类型的数组
} SLinkList;
/*
利用已经定义好的SNode类型,再定义一个SLinkList类型,内部包含一个数组(元素类型为SNode类型,有MaxSize个元素);
这种定义也可以,但是结构中仅包含变量,不太值得单独用typedef定义,可以考虑
 */
```



## 单链表基础操作

- 详情另见它文

- 主要区分是否引入头结点

- 遍历相关的操作时,通常使用循环实现,借助指针域来遍历数据结点,找到对应结点或位置后,执行相应的操作


### 核心判断代码

```c
while(p&&j<i) //查找第i个元素(p指示的是第j个数据结点,直到变成NULL之前说明链表还没有被遍历走到尽头)
{
    p=p->next;//指向下一个结点(第j+1个)
    j++; //更新j,自增1,j指示当前p指向第几个数据结点
}
//退出循环时j==i;并且p指向第i个数据结点
```

```c
//按值查找链表中是否有元素e
while(p!=NULL&&p->data!=e){
    p=p->next;
}
return p;
```

```c
//计算表长
p=L->next;//首元指针
cnt=0;
while(p){
    p=p->next;
    cnt++;//累计数据结点数量
}
```

### 防止链表断开丢失链接

- 无论是单链表,双链表,以及相关变体,在执行插入和删除操作时都要防止链表断开

- 插入和删除操作主要是指针修改操作,是新指向关系的产生和旧指向关系的消失

  - 修改操作的语句都是结点指针域修改语句,左值形如`p->next`,`p->prior`等

- 例如插入新结点s,通常应该先处理新结点的后继(如果是双链表还要处理前驱,这两个操作不会影响原链,新结点处理好后,在执行原链中的断开操作)

- 不过断裂不一定丢失,如果有辅助指针保留断裂前的相关结点位置,就会在后续找回该结点

  - 单链表插入新结点就是这种情况,例如往结点p后插入新结点s,先把s的后继链接到p的后继`s->next=p->next`,此时p,和s开头的链表处于断开,但是通过`p->next=s`可以接回来

  - 有些情况下会让你判断给定的操作序列是否可行,可以通过检查操作序列会不会造成断裂并且丢失,如果不会说明该操作序列是可行的,在绘制示意图时有些操作新链接的行程同时造成旧链接的断开,一个原链结点的指针域的变更,可能造成两个箭头变换(一个出现,一个消失)

  - 对双链表检验一个操作序列是否合法时,每个结点的示意图要区分前驱指针域和后驱指针域,否则会引起混乱

  - 对于双链表,结点$a_{i}$有一个指针变量$p$指定,那么此时若把前驱指针指向其他结点,就造成$a_{i-1}$无法访问而丢失;同理,若干此吧后继指针指向别的结点,后继结点也将无法访问而丢失(这和单链表是一样的)

  - 总之,前驱或后继保持可访问或可找回状态,那么相应的操作序列就有可能成功,否则必定不能达到目的(插入)

  - 双链表的删除操作(删除p所指结点)比插入操作简单,只需要修改2个指针域即可

    - ```c
      p->next->prior=p->prior;
      p->prior->next=p->next;
      ```

      两个操作顺序任意,并且p结点的指针域不会变,p的前驱和后继的指针域会变;

      最后释放内存`free(p);`
