## 数据的存储和排列



### MSB最高有效字节

- MSB(Most Significant Byte)，最高有效字节，指**多字节序列**中具有**最大权重**的字节，是一个数据中权值最大的那一个字节 

### LSB最低有效字节

- LSB(Least Significant Byte)，最低有效字节，指多字节序列中最小权重的字节，是一个数据中权值最小的那一个字节 

### 示例

在32位计算机中，一个int型变量`ⅰ`的机器数为01234567H,其**最高有效字节**MSB=01H,最低有效字节LSB=67H

## 字节序和大小端存储方式

- 现代的计算机系统一般采用字节(Octet, 8 bit Byte)作为逻辑寻址单位 

- 当物理单位的长度大于1个字节时，就要区分字节序（Endianness），字节序是指处理器在处理多字节数据时，在寄存器和内存中保存字节的顺序 

- 为了简便起见它的英文也常常表示为 Byte Order 

- 目前在各种体系的计算机中通常采用的字节存储机制**主要有两种**：

  - Little-Endian(小端)
  - Big-Endian (大端)

- 另外还有一种不常用的字节序Middle-Endian，又称为Mixed-Endian或者PDP-Endian，它是Little-Endian 和 Big-Endian的混合体 

  

### 大端方式(BE)

- 从数据的**最高有效字节**到**最低有效字节**的顺序存储数据，即`最高有效字节存放在前面`;
- Big-Endian(BE)，是指数据的**高字节(MSB)保存在内存的低地址**中，而数据的低字节(LSB)保存在内存的高地址中
  - 这样的存储模式有点儿类似于把数据当作字符串顺序处理：地址由小向大增加，而数据从高位往低位放；


### 小端方式(LE)

- 按从最低有效字节到最高有效字节的顺序存储数据，即`最低有效字节存放在前面` 
- Little-Endian(LE)，是指数据的高字节(MSB)保存在内存的高地址中，而数据的低字节(LSB)保存在内存的低地址中
  - 这种存储模式将地址的高低和数据位权有效地结合起来，高地址部分权值高，低地址部分权值低，和我们的逻辑方法一致 

### 小结

多字节数据在寄存器或内存中时,我们无法用最左或最右来表征数据的最高位或最低位,除非明确该机器是大端方式还是小端方式存储数据

通常用**最低有效字节(LSB)和最高有效字节(MSB)来分别表示数据的低位和高位**。

### 示例



例如十六进制数据01234567H(相当于32位二进制数)

| 内存地址 | ...  | 0800H | 0801H | 0802H | 0803H | ...  |
| -------- | ---- | ----- | ----- | ----- | ----- | ---- |
| 大端方式 | ...  | 01H   | 23H   | 45H   | 67H   | ...  |
| 小端方式 | ...  | 67H   | 45H   | 23H   | 01H   | ...  |

* 通常的,一个数的**书写顺序**是从高位写到低位
  * 而<u>保存顺序却有两种,</u>从的低位开始保存(小端方式)或者从高位开始保存(大端方式)
  * 比如01H;23H;45H;67H
  * $MSB=01H$(最高权重字节)
  * $LSB=67H$(最低权重字节)
* 内存的地址从低地址到高地址增长
  * 大端方式是先存放数据的高位字节再存放低位字节
    * 例如1122H,**高位字节**11H先被存放在低地址内存单元处

  * 小端方式先存放的是数据的低位字节
    - 例如,1122H,低位字节22H先被存放在低地址内存单元

### 按字节编址

现代计算机基本都**采用字节编址，即每个地址编号中存放1字节**。

不同类型的数据占用的字节数不同，如int型和float型占4字节，double型占8字节等，而程序中对**每个数据只给定一个地址**。

### 变量字节在内存中的排列

假设变量`i`的地址为`0800H`,字节01H、23H、45H、67H应各有一个内存地址，那么4字节在内存中应如何排列呢？

根据数据中各字节在**连续字节序列**中的**排列顺序**不同，可以采用两种排列方式：**大端方式**(big endian)和**小端方式**(little endian)

1)大端方式：先存储高位字节，后存储低位字节。字中的字节顺序和原序列的相同。

2)小端方式：先存储低位字节，后存储高位字节。字中的字节顺序和原序列的相反。

在检查底层机器级代码时，需要分清各类型数据字节序列的顺序

一个变量(数据)只有一个地址,这个变量空间的第一个字节地址作为变量地址,如果先存储高位字节，就是大端方式存储,否则先存储低位字节,就是小端方式存储;

总之,先存储高位**字节**,就是大端方式,先存储低位字节,就是小端;结合指令和操作数比较数的各个字节排列顺序(以**字节**为单位而不是以**位**为单位)

### 案例

例如，以下是由反汇编器(汇编的逆过程，即将机器代码转换为汇编代码)生成的一行机器级代码的文本表示：

```c
4004d3: 01 05 64 94 04 08 add eax, 0x8049464
```

其中

- “4004d3”是十六进制数表示的**地址**

- `01 05 64 94 04 08`是**指令的机器代码**(6个字节)(每一字节对应两位16进制数)

  - 前两个字节是操作码,后面4个字节是操作数(立即数)
  - **01 05**：这是 `add` 指令的操作码（opcode）。在x86汇编中，`01 05` 表示将一个立即数与寄存器 `eax` 相加。
  - **64 94 04 08**：这是立即数 `0x8049464` 的小端序（little-endian）表示。小端序是指最低有效字节（Least Significant Byte，LSB）存储在最低地址。

- `add eax, 0x8049464`是**指令的汇编形式**(对应于6字节指令的机器代码`01 05 64 94 04 08`)，该指令的**第2个操作数**是一个立即数`0x8049464`。将其展开为32位(4字节),高位补0:`0x 08 04 94 64`;指令中将立即数的4个字节从低位先存储(低地址存储低位字节,是小端存储)

  - 小端序转换：

    `64 94 04 08` 对应的十六进制值排列如下：

    - **64**: 最低有效字节
    - **94**
    - **04**
    - **08**: 最高有效字节

    将它们组合起来就是 `0x8049464`。

####  地址部分

- **4004d3**：这是**指令的内存地址**（memory address），表示这条指令在内存中存储的位置。这个地址通常是在程序加载到内存中后的实际运行地址。

#### 机器代码部分

- **01 05 64 94 04 08**：这是这条指令的机器代码（machine code）。这六个字节组成了处理器可以执行的机器指令。

#### 反汇编指令部分

- add eax, 0x8049464
  - **add**：汇编指令，表示进行加法操作。
  - **eax**：是x86架构中的一个通用寄存器。`eax`通常用来存储整数运算的结果。
  - **0x8049464**：这是一个立即数（immediate value），表示要与 `eax` 寄存器中的值相加的常数值。

#### 指令执行过程

该指令将寄存器 `eax` 中的值与立即数 `0x8049464` 相加，并将结果存储回 `eax`。

```
eax = eax + 0x8049464
```

将立即数 `0x8049464` 加到 `eax` 寄存器的当前值上。

示例：

假设 `eax` 的初始值为 `0x1000`：

- 执行后，

  ```
  eax
  ```

   的值为：

  ```
  0x1000 + 0x8049464 = 0x804a464
  ```

执行指令时，从指令代码的后4字节中取出该立即数，立即数存放的字节序列为64H、94H、04H、08日，正好与操作数的字节顺序相反，即采用的是小端方式存储，得到08049464H,去掉开头的0，得到值0x8049464,在阅读以小端方式存储的机器代码时，要注意字节是按相反顺序显示的。

* 现代计算机基本上都采用`字节编址`，即每个`地址编号`中存放1字节 
* 不同类型的数据占用的`字节数`不同，
  * int和 float型数据占4字节，double型数据占8字节等，而`程序中对每个数据只给定一个地址` 
  * 假设`变量i`的地址为08 00H，`字节`01H、23H、45H、67H应该各有一个`内存地址`(字节地址)
  * 那么地址08 00H对应4字节中`哪字节的地址(最高字节地址还是最低字节地址)`呢?



### 应用情况

- 我们常见的**大部分处理器都采用Little-Endian**，
  - 例如x86、6502、Z80、VAX以及PDP-11等；
- 使用Big-Endian的处理器通常是**Motorola的处理器**，
  - 例如：6800、68000、PowerPC 以及System/370等；
- 可切换的字节序(Bi-Endian)
  - 像ARM、PowerPC、Alpha、SPARC V9、MIPS、PA-RISC和IA64等体系结构 **支持可切换的字节序**，
  - 这个特性可以提高效率或者简化网络设备和软件的逻辑 
  - 这种可切换的字节序被称为**Bi-Endian**，用于硬件上意指计算机或者传递数据时**可以使用两种不同字节序中任意一种的能力 **
- Middle-Endian 使用很少，偶尔会在一些小型机体系中的十进制数的压缩格式中出现



## 立即数（Immediate Value)

**立即数**（Immediate Value）是指在汇编语言或机器代码中，直接嵌入在指令中的常数值。与寄存器或内存地址不同，立即数不需要从其他位置加载数据，而是直接作为指令的一部分提供。

### 特点

1. **直接嵌入**：立即数在指令中明确给出，不需要从内存或寄存器中读取。
2. **只读不可修改**：立即数是固定值，不能在程序运行时改变。
3. **常见用途**：用于赋值、加法、减法、比较等操作中，提供固定的操作数。

### 例子说明

#### 1. 使用立即数的指令

```assembly
mov eax, 5   ; 将立即数 5 移动到 eax 寄存器
add eax, 10  ; 将立即数 10 加到 eax 中
```

- 在 `mov eax, 5` 中，`5` 是立即数。
- 在 `add eax, 10` 中，`10` 是立即数。

#### 2. 与其他操作数类型比较

| 类型           | 描述                       | 示例                   |
| -------------- | -------------------------- | ---------------------- |
| **立即数**     | 直接在指令中指定的固定值。 | `add eax, 5`           |
| **寄存器**     | 使用 CPU 寄存器中的数据。  | `add eax, ebx`         |
| **内存操作数** | 使用内存地址中的数据。     | `add eax, [0x8049464]` |

### 优缺点

- **优点**：
  - 速度快：无需访问内存或寄存器，指令执行时立即可用。
  - 代码简洁：直接嵌入常数，使程序更易读。
- **缺点**：
  - 大小限制：指令的固定长度限制了立即数的大小。例如，在 x86 指令集中，立即数的长度通常为 8、16 或 32 位。
  - 灵活性较低：无法在运行时更改。

### 示例比较

假设 `eax = 3`：

- 使用立即数：

  ```assembly
  add eax, 7   ; eax = eax + 7，结果为 10
  ```

- 使用寄存器：

  ```assembly
  mov ebx, 7
  add eax, ebx ; eax = eax + ebx，结果同样为 10
  ```

### 总结

立即数是直接嵌入指令中的固定值，在汇编编程中广泛用于简单运算。它在执行时速度快，但大小受限，适合用来表示常量数据。

## 数据在存储器中的存放方式

这部分是指令系统的内容

### 存储器的存储单元

存储器（Memory）是计算机系统中用来存储数据和指令的设备。其存储单元和存储特点决定了数据如何在系统中被存储、访问和管理。

### 存储单元（Storage Unit）

**存储单元** 是存储器中用于**存储数据的基本单位**，每个存储单元都有一个唯一的地址（Address）。

- 位（Bit）：存储信息的最小单位。表示二进制中的 0 或 1。
- 字节（Byte）：通常由 8 位构成，是基本的数据存储单位。一个字节可以存储一个 ASCII 字符。
- 字（Word）：字是计算机的自然数据**处理单位**，它的长度通常是字节的整数倍（如 2 字节、4 字节或 8 字节）。
  - **32位系统**：一个字通常是 4 字节（32 位）。
  - **64位系统**：一个字通常是 8 字节（64 位）。

### 存储特点

1. **按地址访问**
    每个存储单元都有一个唯一的地址，CPU 通过地址总线（Address Bus）访问数据。例如，访问存储单元地址 0x0000 的数据。
2. **顺序存储**
    数据在存储器中通常是连续存储的。例如，整型数据（4 字节）会占据连续的 4 个字节单元。
3. **对齐存储（Aligned Storage）**
   - **对齐访问**：数据在特定边界（如 4 字节或 8 字节边界）上存储，从而提高访问效率。
   - **未对齐访问（Unaligned Access）**：数据没有按边界对齐，可能导致访问速度降低，甚至在某些处理器上引发错误。
4. **数据填充（Padding）**
    为了满足对齐要求，可能会在数据之间插入填充字节。例如，一个结构体中不同类型的成员可能会因为对齐规则而导致填充。
5. **存储结构**
   - 字节存储顺序（Endianness）
     - **小端序（Little Endian）**：低位字节存储在低地址（如 x86 架构）。
     - **大端序（Big Endian）**：高位字节存储在低地址（如某些网络协议）。
   - **位顺序（Bit Order）**：描述字节内部的位存储顺序。通常用于通信协议和硬件描述。

### 存储器类型及特点

| 存储器类型             | 特点和用途                                     | 速度   | 容量 |
| ---------------------- | ---------------------------------------------- | ------ | ---- |
| **寄存器（Register）** | CPU 内部存储器，用于暂存指令和数据。           | 极快   | 极小 |
| **缓存（Cache）**      | 速度比主存快，通常分为 L1、L2、L3。            | 非常快 | 小   |
| **主存（RAM）**        | 系统的主要工作内存，存储当前运行的程序和数据。 | 快     | 大   |
| **只读存储器（ROM）**  | 非易失性存储，存储固件（如 BIOS）。            | 较慢   | 小   |
| **辅助存储器（磁盘）** | 用于长期存储数据（如 HDD、SSD）。              | 慢     | 极大 |

### 示例：数据存储过程

假设要在主存中存储一个 32 位的整型数据（如 `0x12345678`），在小端序系统中，存储方式如下：

| 地址   | 数据 |
| ------ | ---- |
| 0x1000 | 78   |
| 0x1001 | 56   |
| 0x1002 | 34   |
| 0x1003 | 12   |

### 总结

存储器的存储单元通过唯一地址访问，每种数据类型都有特定的存储边界。对齐存储和按地址访问是存储器的关键特点。合理地使用不同类型的存储器（如寄存器、缓存、主存）有助于提高计算机系统的性能和效率。

## 边界对准存储

### 机器字长

- 数据在存储器中的存放方式通常计算机中的数据存放在**存储器或寄存器**中，而**寄存器的位数便可反映机器字长**。
- 一般机器字长可取字节的1、2、4、8倍，这样便于字符处理。在大、中型机器中字长为32位和64位，在微型计算机中字长从4位、8位逐渐发展到目前的16位、32位和64位。
- 由于不同的机器数据字长不同，每台机器处理的数据字长也不统一，一个字对应的字节数不同,例如
  - 奔腾处理器可处理8（字节）、16（字）、32（双字）、64（四字）；
  - PowerPC可处理8（字节）、16（半字）、32（字）、64（双字）。

### 多字节数据的边界对准存储

- 为了便于硬件实现，通常要求多字节的数据在存储器的存放方式能满足“边界对准”的要求
- 下图(a)所示的存储器存储字长为32位，可按字节、半字、字、双字访问。
  - 在对准边界的32位字长的计算机中，半字地址是2的整数倍，字地址是4的整数倍，双字地址是8的整数倍。当所存数据不能满足此要求时，可填充一个至多个空白字节。

### 对齐存储👺

现代计算机都是按字节编址的，假设字长为32位，数据**按边界对齐**方式存放要求其存储地址是自身大小的整数倍，半字地址一定是2的整数倍，字地址一定是4的整数倍

这样**无论所取的数据是字节、半字还是字，均可一次访存取出**。

当所存数据不满足上述要求时，可通过填充空白字节使其符合要求。这样做虽然会浪费一些存储空间，但可以提高存取数据的速度。

当数据不按边界对齐方式存储时，半字长或字长的数据可能在两个存储字中，此时需要两次访存，并对高低字节的位置进行调整后才能得到所需数据，从而影响了系统的效率。

### 为什么要按边界对齐

1. **提高访问速度**：对齐的数据可以更快地被CPU访问。处理器通常一次读取固定大小的数据块（如4字节或8字节）。如果数据与这些边界对齐，读取操作只需一次即可完成。

2. **减少CPU访问次数**：未对齐的数据可能需要读取两次或更多次才能完整获取。例如，访问跨越两个内存块的数据会导致额外的读取操作。

   

### 对齐方式

不同的数据类型通常有不同的对齐要求：

| 数据类型        | 对齐边界（示例）                        |
| --------------- | --------------------------------------- |
| 字节（Byte）    | 1字节（无特定要求）                     |
| 短整型（Short） | 2字节边界                               |
| 整型（Int）     | 4字节边界                               |
| 长整型（Long）  | 4字节或8字节边界                        |
| 指针（Pointer） | 通常与平台字长一致（如64位系统为8字节） |

### 示例说明

假设有一个结构体（C语言）如下：

```c
struct Example {
    char a;      // 1字节
    int b;       // 4字节
    short c;     // 2字节
};
```

在内存中存储时：

按边界对齐：

- `a` 会占用1字节，但为了对齐，后续的 `int b` 需要在4字节边界上，因此会填充3个字节的填充（Padding）。
- `b` 从第4字节开始，占用4字节。
- `c` 从第8字节开始，占用2字节，通常会再填充2字节以保证结构体整体大小是4字节的倍数。

内存布局如下：

```
[a][ ][ ][ ][b][b][b][b][c][c][ ][ ]
```



### 注意事项

1. **内存浪费**：边界对齐可能会引入填充字节，导致内存浪费。
2. **跨平台兼容**：不同平台的对齐规则可能不同，需要注意数据序列化和反序列化。

### 相关概念

- **字节填充（Padding）**：用于填补对齐边界与实际数据长度之间的空隙。
- **结构体对齐（Struct Alignment）**：结构体中的各个成员变量对齐，以优化访问速度。

通过按边界对齐存储，可以在大多数情况下提高程序性能，但需要在性能和空间利用率之间做权衡。
