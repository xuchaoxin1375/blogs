## 中缀表达式转后缀表达式

利用画括号的方法来将中缀表达式中所有的运算步骤标记出来,最终形成若干并列和嵌套的括号;最内部的括号先算,同级别的括号从左边开始先算

不过同一个表达式的计算顺序不一定唯一,例如$A+B+C*D$,我们可以

- 由于乘法优先级高于加法,先把$C*D$看做一个整体,先算$(A+B)$,再算$(C*D)$,最后算$(A+B)+(C*D)$
- 或者,先算$(C*D)$,再算$(A+B)$,最后算$(A+B)+(C*D)$

而有些情况计算顺序唯一

- 例如$A-B-C$,必须从左算到右,减法运算不满足交换律,也不满足结合律
- 又比如$A+B*C$,必须先算$B*C$再算加法

对于一个中缀表达式,将每个高优先级运算符(假设仅包含4则运算)的子算式(比如$A+B*C+D$中的乘法子算式$B*C$)视为一个整体,剩下的单个操作数通过低优先级的运算符和这些整体连接成最终算式,这些算式就可以从左往右计算

### 手动转换算法

分为三个步骤
1)按照运算符的运算顺序对所有运算单位加括号。
2)将运算符移至对应括号的后面，相当于按“左操作数右操作数运算符”重新组合。
3)去除所有括号。

例如$A+B*(C-D)-E/F$,画括号后得到$A+(B*(C-D))-(E/F)$,接下来考虑每个外层括号和单项式间的计算顺序,这里是从左往右算:

- $((A+(B*(C-D)))-(E/F))$

标注运算顺序:

可以用括号标注
$$
((A+(B*(C-D)_{1})_{2})_{4}-(E/F)_{3})_{5}
$$
不过用运算符标注更加清晰
$$
((A+_{(4)}(B*_{(2)}(C-_{(1)}D)))-_{(5)}(E/_{(3)}F))
$$
或者
$$
((A+_{(3)}(B*_{(2)}(C-_{(1)}D)))-_{(5)}(E/_{(4)}F))
$$
运算结果一样,转换为后缀表达式是一样的
$$
ABCD-* +EF/-
$$


### 计算机算法

在计算机中，中缀表达式转后缀表达式时需要**借助一个栈**，用于保存暂时还不能确定运算顺序的运算符。

基本原则是:

- 中缀表达式中的所有字符(除了括号)都会被条件到后缀表达式中,这些字符的排列无非是顺序和中缀表达不同,单不能丢失
- 这里括号成为界限符而不做运算符看待,设立的辅助栈不叫运算符栈,而是非操作数栈;但是如果要把括号当作特殊运算符也可以,但是仍然要和普通运算符做区别处理
- 算法利用利用栈在合适的时候将运算符弹出栈并追加到后缀表达式,而且注意弹出的时候不一定只弹出一个运算符,可能是多个连续弹出,如果弹出多个,还要注意栈的特点弹出顺序(例如弹出栈中的`o1,o2`,那么加到后缀表达式后的顺序是`o2,o1`

从左到右依次扫描中缀表达式中的每一项，具体转化过程如下：

1. 遇到**操作数**。直接加入后缀表达式。
2. 遇到**界限符**。(括号)
   - 若为`(`，则直接入栈：
   - 若为`)`，则依次弹出栈中的**运算符**，并加入后缀表达式，**直到弹出`(`为止**。`(`直接删除，不加入后缀表达式。
3. 遇到**运算符**(将运算符operator用符号`op`表示,比如$\rm{op}\in\set{+,-,\times,\div,\cdots}$)
   - 若其**优先级**高于除`(`外的**栈顶运算符**，则直接入栈。
     - 若栈顶是`(`则也让`op`入栈
     - 例如`A+B*C`,扫描到`*`前辅助栈中有`+`,遇到`*`优先级高,应该要比`+`先出栈参与运算(栈是后进先出的,`*`后入栈于`+`,则会先于`+`出栈)
   - 否则(`op`优先级不高于栈顶运算符)，从栈顶开始，依次弹出栈中**优先级高于或等于当前运算符的所有运算符**，并**加入后缀表达式**，直到遇到一个**优先级低于它的运算符**或遇到离栈顶最近的一个做括号**`(`**时为止(该左括号一并弹出丢弃)，**之后将当前运算符入栈**。
     - 例如`A+B*C-D`,扫描到`C`时栈中序列为`+*`,再遇到低于`*`优先级的`-`,应该让`*`出栈和操作数结合,然后让`-`入栈
     - 例如`A+B*(C-D)-E/F`,当`(`入栈后,下一个运算符`-`会入栈,接着遇到`)`,此时立即让栈开始出栈,直到弹出`(`位置(本例中此时的栈顶和次栈顶分别是`-,(`,那么这两者都被弹出,其中`(`被丢弃,而`-`则是加入到现有的后缀表达式末尾)
     - 那如果是`B*(C-D*T)+M`,在第一个`-`入栈后,括号内的第二个运算符`*`遇到栈顶的`-`,发现优先级低于`*`,所以`*`入栈,再后来遇到`)`,令栈出栈,直到`(`被弹出,这些弹出的符号加入到后缀表达式的末尾
       - 本例中`*,-,(`依次被弹出,但是`(`在出栈时直接删除并不加入后缀表达式中,`)`也是扫描到就被丢弃,并不加入到后缀表达式中,所以被加入到后缀表达式的只有`*,-`;
       - 至于后续待处理序列,继续按照上述方法处理,`+`和此时栈顶`*`比较,优先级低于栈顶,所以出栈顶,送到后缀表达式末尾,`+`继续和栈顶比较,发现栈空,那`+`就该入栈  
       - 这个例子转换后得到后缀表达式`BCDT*-*M+`
   - 按上述方法**扫描所有字符后，将栈中剩余运算符依次弹出**，并加入后缀表达式。

将中缀表达式 `A + B * (C - D) - E / F` 转换为后缀表达式的步骤。

具体步骤如下：其中扫描项表示当前处理的字符,是当前待处理序列的第一个符号,该符号是入栈或是接入后缀表达式的结果记录到下一样中

事实上待处理序列可以不用写,只需要在扫描项一列中,将中缀表达式的各个字符依次写下,中缀表达式有$n$个符号,那么扫描项又有$n$行!

| 步骤 | 待处理序列              | 扫描项 | 栈内    | 后缀表达式      | 说明                                                         |
| ---- | :---------------------- | ------ | ------- | --------------- | ------------------------------------------------------------ |
| 1    | A + B * (C - D) - E / F | A      |         |                 | A 加入后缀表达式<br />(刚开始辅助栈和后缀表达式都为空)<br />第一个扫描到的字符是`A` |
| 2    | + B * (C - D) - E / F   | +      |         | A               | 运算符+ 入栈                                                 |
| 3    | B * (C - D) - E / F     | B      | +       | AB              | B 加入后缀表达式                                             |
| 4    | * (C - D) - E / F       | *      | +       | AB              | 优先级高于 +，入栈                                           |
| 5    | (C - D) - E / F         | (      | + *     | AB              | ( 直接入栈                                                   |
| 6    | C - D) - E / F          | C      | + * (   | AB              | C 加入后缀表达式                                             |
| 7    | - D) - E / F            | -      | + * (   | ABC             | 栈顶为 (，直接入栈                                           |
| 8    | D) - E / F              | D      | + * ( - | ABC             | D 加入后缀表达式                                             |
| 9    | ) - E / F               | )      | + * ( - | ABCD            | 遇到 )，弹出，删除 (                                         |
| 10   | - E / F                 | -      | + *     | ABCD -          | 遇到 -,优先级低于栈顶`*`，依次弹出* +，然后`-` 入栈          |
| 11   | E / F                   | E      | -       | ABCD -*+        | E 加入后缀表达式                                             |
| 12   | / F                     | /      | -       | ABCD -* +E      | `/`优先级高于 `-`，入栈                                      |
| 13   | F                       | F      | - /     | ABCD -* +E      | F 加入后缀表达式                                             |
| 14   |                         |        | - /     | ABCD -* +EF     | 字符扫描完毕，弹出栈内运算符                                 |
| 15   |                         |        |         | ABCD -*+ EF / - | 结束                                                         |

对于表格中每一行的扫描项,如果是运算符(记为`op`,则令其和栈内符号序列比较优先级,如果高于栈顶,则入栈,否则出栈到剩下的栈顶优先级低于`op`为止

以第10行为例,扫描到`-`,和当前的栈内栈顶元素比价优先级发现低于`*`,而且不高于`+`,所以要把栈中的`*,+`弹出(这是按后进先出的顺序弹出,计算本行的后缀表达式一格和弹出的符号结果作为下一行的后缀表达式)

### 例

假设栈初始为空，将中缀表达式`a/b+(c*d-e*f)/g`转换为等价的后缀表达式的过程中，当扫描到f时，栈中的元素依次为`+(-*`

分析:这个问题比上一个例子简单,不需要记录中途变换(不需要找出中间过程的最大值),只需要迭代栈内字符序列到扫描项`f`为止即可

扫描项就不需要注意列出,直接根据给定的中缀表达式开始从左往有扫描

1. `/`
2. `+`
3. `+(`
4. `+(*`
5. `+(-`
6. `+(-*` 已经扫描到`f`了)
7. `+`
8. `+/`
9. `空`

可见,将整个序列转换完共经历9次栈内序列变换

还可以更快,我们只对被出栈的时后另起一行序列,否则已知收集非数字符号

- `/`
- `+(*`
- `+(-*` 此时已经扫到了`f`
