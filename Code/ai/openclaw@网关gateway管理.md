## 对比openclaw gateway run 和start

在 OpenClaw (Moltbot) 框架中，`gateway` 的 `run` 和 `start` 命令在执行逻辑和应用场景上有明显的区别。简单来说，一个是**前台运行**，一个是**后台服务管理**。

------

### 1. `openclaw gateway run`

这是**直接执行**命令，通常用于调试或手动临时启动。

- **运行模式**：前台运行（Foreground）。
- **日志输出**：所有的运行日志（INFO, DEBUG, ERROR）会直接打印在当前的终端窗口。
- **生命周期**：一旦你关闭终端窗口或按下 `Ctrl + C`，网关进程会立即停止。
- **适用场景**：
  - 刚修改完配置文件，检查是否有语法错误。
  - 调试 Skill 调用逻辑，实时查看交互日志。
  - 在 Docker 容器的前台进程中使用。

### 2. `openclaw gateway start`

这是**服务化启动**命令，通常配合框架内置的状态管理使用。

- **运行模式**：守护进程/后台运行（Daemon/Background）。
- **日志输出**：终端不会直接滚动日志，输出通常会被重定向到指定的日志文件（如 `logs/gateway.log`）。
- **生命周期**：即使关闭终端会话，网关也会继续在后台运行。通常需要通过 `openclaw gateway stop` 来关闭。
- **适用场景**：
  - 生产环境部署。
  - 服务器重启后的自动拉起。
  - 长期稳定的 API 服务提供。

------

### 核心差异对比

| **特性**     | **run**              | **start**          |
| ------------ | -------------------- | ------------------ |
| **执行位置** | 当前会话（阻塞终端） | 后台运行（非阻塞） |
| **交互性**   | 高，实时看到报错     | 低，需查看日志文件 |
| **稳定性**   | 随终端关闭而停止     | 持续运行           |
| **主要用途** | 开发、调试、容器环境 | 部署、生产环境     |

### 常用配套命令

如果你使用的是 `start` 模式，通常还会用到以下命令来管理状态：

- **查看状态**：`openclaw gateway status`
- **停止服务**：`openclaw gateway stop`
- **重启服务**：`openclaw gateway restart`

**建议：** 如果你正在调整网关的端口配置或排查内网穿透问题，先用 `run` 确认一切正常，再换成 `start` 长期挂载。
