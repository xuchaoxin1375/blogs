## abstract

openclaw或者claude code 能够理解用户的指令并操作电脑上的文件,例如我告诉大模型我要删除某些类型的文件,大模型是如何(直接或间接)调用工具为用户执行操作?

这类工具（OpenClaw, Claude Code 等）的核心本质是**将自然语言翻译为精确的系统指令**。它们并不直接“拥有”你的电脑权限，而是通过一套标准的“思考-执行-反馈”循环来操作文件。

以下是它们理解指令并调用工具的底层逻辑：

------

### 1. 意图解析：从“人话”到“任务”

当你输入“帮我删掉所有 `.tmp` 文件”时，大模型（LLM）会进行语义解析：

- **动作 (Action):** 删除 (Delete)
- **对象 (Object):** 文件 (Files)
- **约束 (Constraint):** 后缀名为 `.tmp`

模型不会盲目执行，它会先通过系统的 **System Prompt（系统提示词）** 确认自己有哪些可用的“工具箱”（Tools/Functions）。

### 2. 工具调用机制 (Function Calling)

这是关键所在。开发者在程序里为模型定义了一组函数接口。例如，一个名为 `list_files` 的工具和一个名为 `delete_file` 的工具。

- **模型输出指令：** 模型不会直接运行删除命令，而是输出一段特定格式的数据（通常是 JSON），告诉外部系统：“我决定调用 `list_files`，参数是 `path='.'`”。
- **外部代理执行：** **运行在本地的客户端（OpenClaw 或 Claude Code）接收到这个 JSON，替模型在你的电脑上执行真实的 Python 代码或 Shell 命令**。
- **结果回传：** 客户端把执行结果（如：找到了 5 个文件）传回给模型。

### 3. 循环决策流 (The Loop)

大模型操作文件的过程通常是多步的：

1. **观察 (Observe)：** 调用 `ls` 或类似命令查看当前目录结构。
2. **思考 (Thought)：** “我看到了 `a.tmp` 和 `b.tmp`，我需要针对这两个路径分别调用删除工具。”
3. **行动 (Act)：** 连续发送删除指令。
4. **确认 (Verify)：** 再次查看目录，确认文件是否消失，最后向你汇报。

------

### 4. 为什么它们能操作文件而网页版不行？

主要区别在于**运行环境**：

- **网页版 Claude/ChatGPT：** 运行在云端沙盒中，无法访问你的物理硬盘。
- **Claude Code/OpenClaw：** 运行在你的**本地终端**。它们拥有本地文件系统的读写权限，本质上是一个“拥有大模型大脑的命令行助手”。

> **安全提示：** 这类工具通常会有二次确认机制。当模型识别到“删除”这类不可逆的高危操作时，本地代理程序会拦截并弹窗询问：“大模型请求删除以下文件，是否允许？”

------

### 5. 核心架构对比

| **环节**     | **传统脚本 (Bash/Python)** | **AI 代理 (Claude Code/OpenClaw)**         |
| ------------ | -------------------------- | ------------------------------------------ |
| **理解方式** | 严格匹配正则表达式         | 语义理解（能处理“删掉那些没用的临时文件”） |
| **错误处理** | 报错即停止                 | 看到报错后会自我修正（Self-healing）       |
| **执行逻辑** | 硬编码路径                 | 动态探索路径                               |
