## abstract

openclaw或者claude code 能够理解用户的指令并操作电脑上的文件,例如我告诉大模型我要删除某些类型的文件,大模型是如何(直接或间接)调用工具为用户执行操作?

这类工具（OpenClaw, Claude Code 等）的核心本质是**将自然语言翻译为精确的系统指令**。它们并不直接“拥有”你的电脑权限，而是通过一套标准的“思考-执行-反馈”循环来操作文件。

以下是它们理解指令并调用工具的底层逻辑：

------

### 1. 意图解析：从“人话”到“任务”

当你输入“帮我删掉所有 `.tmp` 文件”时，大模型（LLM）会进行语义解析：

- **动作 (Action):** 删除 (Delete)
- **对象 (Object):** 文件 (Files)
- **约束 (Constraint):** 后缀名为 `.tmp`

模型不会盲目执行，它会先通过系统的 **System Prompt（系统提示词）** 确认自己有哪些可用的“工具箱”（Tools/Functions）。

### 2. 工具调用机制 (Function Calling)

这是关键所在。开发者在程序里为模型定义了一组函数接口。例如，一个名为 `list_files` 的工具和一个名为 `delete_file` 的工具。

- **模型输出指令：** 模型不会直接运行删除命令，而是输出一段特定格式的数据（通常是 JSON），告诉外部系统：“我决定调用 `list_files`，参数是 `path='.'`”。
- **外部代理执行：** **运行在本地的客户端（OpenClaw 或 Claude Code）接收到这个 JSON，替模型在你的电脑上执行真实的 Python 代码或 Shell 命令**。
- **结果回传：** 客户端把执行结果（如：找到了 5 个文件）传回给模型。

### 3. 循环决策流 (The Loop)

大模型操作文件的过程通常是多步的：

1. **观察 (Observe)：** 调用 `ls` 或类似命令查看当前目录结构。
2. **思考 (Thought)：** “我看到了 `a.tmp` 和 `b.tmp`，我需要针对这两个路径分别调用删除工具。”
3. **行动 (Act)：** 连续发送删除指令。
4. **确认 (Verify)：** 再次查看目录，确认文件是否消失，最后向你汇报。

------

### 4. 为什么它们能操作文件而网页版不行？

主要区别在于**运行环境**：

- **网页版 Claude/ChatGPT：** 运行在云端沙盒中，无法访问你的物理硬盘。
- **Claude Code/OpenClaw：** 运行在你的**本地终端**。它们拥有本地文件系统的读写权限，本质上是一个“拥有大模型大脑的命令行助手”。

> **安全提示：** 这类工具通常会有二次确认机制。当模型识别到“删除”这类不可逆的高危操作时，本地代理程序会拦截并弹窗询问：“大模型请求删除以下文件，是否允许？”

------

### 5. 核心架构对比

| **环节**     | **传统脚本 (Bash/Python)** | **AI 代理 (Claude Code/OpenClaw)**         |
| ------------ | -------------------------- | ------------------------------------------ |
| **理解方式** | 严格匹配正则表达式         | 语义理解（能处理“删掉那些没用的临时文件”） |
| **错误处理** | 报错即停止                 | 看到报错后会自我修正（Self-healing）       |
| **执行逻辑** | 硬编码路径                 | 动态探索路径                               |

------

## Claude Code 如何理解并执行工具调用？

当你在 Claude Code 中说“删除所有 `.log` 文件”时，发生的过程被称为 **“工具调用循环”（Tool Use Loop）**。

### 第一步：意图识别与工具选择

当你输入指令后，Claude 模型会分析你的意图。在 Claude Code 的系统提示词（System Prompt）中，已经告诉了它有哪些“工具”可用：

- `ls` (查看文件)
- `rm` (删除文件)
- `read_file` (读取内容)
- `execute_command` (执行任意 Bash 命令)

模型意识到要完成你的任务，必须调用 `execute_command`。

### 第二步：生成“结构化指令” (而非聊天文字)

模型不会直接在聊天框回复“好的，我这就去删”。相反，它会停止生成普通文本，转而生成一段**机器可读的代码块**（通常是 JSON 格式）：

```json
{
  "tool": "execute_command",
  "parameters": {
    "command": "rm *.log"
  }
}
```

### 第三步：本地代理执行 (真正的“手”)

**Claude Code**（运行在你电脑上的 CLI 程序）接收到了这段 JSON。

1. 它解析出模型想运行 `rm *.log`。
2. 它会在你的本地终端执行这条命令。
3. 它获取执行结果（例如：“已删除 5 个文件” 或 “权限不足”）。

### 第四步：反馈与闭环

Claude Code 将执行结果发回给云端的大模型。模型看到结果后，会再次思考：

- 如果成功了，它会对你说：“我已经清理了所有的日志文件。”
- 如果失败了（比如报错），它会分析原因，然后尝试换一种方式（例如加 `sudo` 或者先修改权限）再次调用工具。

------

 为什么 OpenClaw/Claude Code 敢让你操作电脑？

这涉及到一个**权限防御层**：

- **沙盒化 (Sandboxing)：** 很多工具会在一个隔离的虚拟环境（如 Docker 或 VM）中运行这些命令，防止它删掉你的系统核心文件。
- **人工确认 (Human-in-the-loop)：** 对于 `rm` 这种高危操作，Claude Code 通常会弹出一个提示：“模型想要运行 `rm -rf /`，你允许吗？” 你点确认后，它才会真正执行。

### 总结

大模型负责**“脑”**（理解意图、规划步骤、生成指令）；Claude Code 负责**“手”**（接收指令、调用系统接口、返回结果）。正是这种组合，让 AI 看起来像是在“操作”你的电脑。

## 大模型的输入和输出

大模型接收用户输入(最常见的是文本,对于多模态模型,可以接收图片等文件)后,输出过程**是在生成“token 序列”**；

这些 token 最常被**解码成文本、代码或 JSON，但并不必然只限于纯文本**。

现在的模型/API里，已经有支持**音频输入与音频输出**的模型，也有能**生成图像**的多模态语言模型；

图像生成文档还明确提到图像是通过专门的 image tokens 生成的。

你可以把“工具调用”理解成两层：

1. **模型层**：根据你给它的工具说明，产出一个**结构化的调用请求**。  
2. **宿主程序层**（CLI、IDE 插件、Agent 框架）：把这个请求当成“指令”，去真的执行命令、读写文件、调 API、打开网页，再把结果喂回模型。

## 一、工具调用到底是怎么“理解”的？

以 Anthropic 的工具调用文档为例，宿主程序会把工具以 `tools` 参数传给模型；每个工具至少有：

- `name`
- `description`
- `input_schema`（JSON Schema）
- 可选 `input_examples`。

然后 API 会把这些工具定义拼进一个特殊的 system prompt，让模型知道：  
“你现在可以使用这些工具；每个工具叫什么、干什么、参数长什么样。”  
所以模型所谓的“理解工具”，本质上主要来自：

- 工具名
- 工具描述
- 参数 schema
- 示例输入
- 外加训练中学到的“什么时候该调用工具”的模式。

换句话说，**模型不是在运行 Python 函数对象本身**，而是在根据文本化/结构化的工具说明，预测下一段最合适的结构化输出。

---

## 二、工具调用到底是怎么“执行”的？

典型流程是这样的：

**用户问题**  
→ 宿主程序把工具定义发给模型  
→ 模型返回 `tool_use`  
→ 宿主程序解析工具名和参数  
→ 宿主程序真的去执行  
→ 把结果作为 `tool_result` 发回模型  
→ 模型再继续回答。

Anthropic 文档说得很直接：当 Claude 返回客户端工具的 `tool_use` 时，你需要：

1. 取出 `name`、`id`、`input`
2. 在你自己的代码里运行对应工具
3. 再把结果作为新的 `user` 消息里的 `tool_result` 传回去。

而在 computer use 的说明里，Anthropic 也明确说：**Claude 并不是直接连接到那个计算环境**；而是**你的应用**接收 Claude 的工具请求，把它翻译成实际动作，再把截图/命令输出等结果返回给 Claude。这个循环就叫 **agent loop**。

---

## 三、所以“工具调用”本质上是什么？

一句话：**结构化生成 + 外部调度执行**。

模型输出的不是“魔法动作”，而是类似这样的结构化意图：

```json
{
  "type": "tool_use",
  "name": "read_file",
  "input": {
    "path": "src/app.py"
  }
}
```

真正的读文件动作，是外面的运行时做的，不是模型权重自己“伸手”去读。这个结论和 Anthropic 的 agent loop / tool runner 描述是一致的：tool runner 会自动执行工具、管理请求/响应循环和会话状态。

顺便一提，Anthropic 还明确说：**工具不一定真的是外部函数**；有时你也可以把“工具”仅仅当作一个 schema，让模型按这个 schema 产出结构化 JSON。也就是说，tool calling 有时只是“受约束的结构化输出”。

---

## 四、Claude Code 是怎么做的？

Claude Code 官方把它定义成一个 **agentic coding tool**：它能读代码库、编辑文件、运行命令、并和开发工具集成；还支持通过 MCP 连接外部数据源。

所以你在 Claude Code 里看到的“它会改代码、跑测试、提 PR”，背后并不是模型自己直接操作你的机器，而是：

- Claude Code 这个宿主程序把“读文件/改文件/执行命令/MCP 工具”等能力暴露给模型
- 模型根据上下文决定何时调用哪个工具
- Claude Code 负责执行、拿到结果、再回传给模型。

这和 Anthropic 文档里的通用工具调用架构完全一致，只不过 Claude Code 把它做成了一个面向编程场景的产品壳。

---

## 五、OpenClaw 这类工具又是怎么做的？

如果你指的是 OpenClaw 文档里的那个项目，它的做法也非常典型：**不是把模型当成孤立聊天机器人，而是把模型嵌进一个 agent runtime 里**。OpenClaw 文档写明，它是直接嵌入 `pi` 的 `AgentSession`，而不是把 `pi` 当子进程或 RPC 服务来调。

OpenClaw 的文档还直接写了：调用 `session.prompt(...)` 后，SDK 会处理**完整的 agent loop**，包括：

- 发请求给 LLM
- 执行工具调用
- 流式返回响应。

它的工具流水线也写得很清楚：

1. base tools  
2. custom replacements  
3. OpenClaw tools  
4. channel tools  
5. policy filtering  
6. schema normalization  
7. abort wrapping。

并且 OpenClaw 还有一个适配层，把通用 `AgentTool` 包装成底层 SDK 需要的 `ToolDefinition`，真正执行时调用的是工具对象的 `execute(...)`。

所以 OpenClaw 的“理解并执行工具调用”，本质上就是：

- 先把工具集合整理好、过滤好、适配成模型能用的定义
- 把这些定义交给模型
- 模型输出工具调用
- OpenClaw runtime 去执行
- 再把结果送回模型。

---

## 六、OpenClaw 里的 skills 又是什么角色？

OpenClaw 文档里说得很直白：**skills teach the agent how and when to use tools**。  
也就是 skill 本质上不是“给模型装插件 DLL”，而是给模型补一份带前置元数据和 Markdown 指令的“操作说明书”。每个 skill 目录有一个 `SKILL.md`，里面可以放 YAML frontmatter 和说明文字，也可以定义自定义工具 schema，或告诉模型该用哪些现有工具。

它的 system prompt 还会注入一个可用 skills 列表，并指示模型用 `read` 去加载相应的 `SKILL.md`。这说明 skill 的本质仍然是**给模型补上下文与操作规范**，不是让模型突然“原生懂”某个业务。

---

## 七、那安全是怎么保证的？

这类系统一般会把“能不能执行”放在宿主程序，而不是只靠模型自觉。OpenClaw 文档明确说，system prompt 里的安全护栏只是**advisory**；真正的硬约束要靠：

- tool policy
- sandboxing
- channel allowlists
- exec approvals。

比如它的 exec approvals 机制明确要求：让沙箱中的 agent 在真实主机上跑命令时，只有在**策略 + allowlist +（可选）用户审批**都同意的情况下才放行。

这点很关键：  
**模型负责“建议调用什么”，运行时负责“允许不允许、怎么执行、在哪执行”。** 

---

## 八、最简洁的心智模型

你可以把这整套机制理解成：

- **LLM = 规划器 / 决策器 / 结构化意图生成器**
- **Tool schema = 给它看的接口文档**
- **Agent runtime（Claude Code、OpenClaw）= 解释器 + 调度器 + 安全沙箱**
- **tool_result = 执行回执**。

所以答案是：

- **大语言模型不只是“生成文本”**；更准确说，是生成 token，很多场景下这些 token 会被解释成文本、JSON、音频，甚至图像。
- **Claude Code、OpenClaw 这类工具之所以能“执行工具调用”**，不是因为模型自己会执行，而是因为它们在模型外面包了一层 runtime：负责提供工具定义、解析 `tool_use`、执行动作、回传 `tool_result`，并加上权限、沙箱、审批等控制。
