## abstract

- [Workspaces in Visual Studio Code](https://code.visualstudio.com/docs/editor/workspaces)

- VSCode（Visual Studio Code）工作区是一种组织和管理项目的方式，它允许用户以一种结构化且灵活的方式对相关文件和资源进行分组，从而更高效地进行开发工作。





**什么是 VS Code 中的“工作区”？**

Visual Studio Code 中的“工作区”是指在一个 VS Code 窗口（实例）中打开的一个或多个文件夹的集合。大多数情况下，您会将一个单独的文件夹作为工作区打开。但根据您的开发工作流，您也可以使用名为“多根工作区”的高级配置包含多个文件夹。

工作区的概念使 VS Code 能够：

- 配置仅适用于特定文件夹而非其他文件夹的设置。
- 保留仅在该工作区上下文中有效的任务和调试器启动配置。
- 存储并恢复与该工作区关联的 UI 状态（例如，已打开的文件）。
- 仅为该工作区选择性地启用或禁用扩展。

您可能会在 VS Code 文档、问题报告和社区讨论中看到“文件夹”和“工作区”这两个术语交替使用。可以将工作区视为具有额外 VS Code 知识和能力的项目根目录。

**注**：不使用工作区打开 VS Code 也是可能的。例如，当您从平台的“文件”菜单中选择一个文件来打开一个新的 VS Code 窗口时，您实际上并未处于工作区中。在这种模式下，VS Code 的某些功能会受限，但您仍然可以打开并编辑文本文件。

您可以通过使用“文件”>“打开文件夹…”菜单，然后选择一个文件夹来打开一个工作区。

另外，如果您从终端启动 VS Code，您可以将文件夹路径作为 `code` 命令的第一个参数传递给打开操作。例如，使用以下命令使用 VS Code 打开当前文件夹（`.`）：

```bash
code .
```

**单文件夹工作区**

除了使用 VS Code 打开文件夹外，您无需做任何事情就可以将其变为一个 VS Code 工作区。一旦您打开一个文件夹，VS Code 会自动跟踪配置，如您打开的文件或编辑器布局。当您再次在 VS Code 中打开该文件夹时，编辑器将恢复到您先前离开的状态。

您还可以添加其他针对文件夹的特定配置，如相对于全局用户设置的工作区特定设置、任务定义和调试启动文件（见下文关于工作区设置的部分）。

**工作区设置**

工作区设置使您能够在您已打开的工作区上下文中配置设置。工作区设置始终覆盖全局用户设置。它们以 JSON 文件的形式物理存储，其位置取决于您是将一个文件夹作为工作区打开，还是打开了一个 `.code-workspace` 文件。

请参阅设置文档，了解设置作用域及其文件位置的全面解释。

- 当您以工作区形式打开一个文件夹时，工作区设置存储在 `.vscode/settings.json` 中。
- 当您以工作区形式打开一个 `.code-workspace` 时，所有工作区设置都添加到 `.code-workspace` 文件中。

- 以下是对VSCode工作区概念、类型、作用以及如何设置与使用的详细说明：

### **工作区的概念**
- **工作区（Workspace）** 是VSCode中的一种核心功能，它代表了用户正在处理的一个或多个项目的集合。
- 工作区不仅仅是简单地打开一个文件夹，而是包含了针对特定项目或项目集的各种定制化设置、插件配置、任务定义、调试配置等上下文信息。

### **工作区的类型**
VSCode提供了两种类型的工作区：

#### **1. 单文件夹工作区（Single-folder workspace）**
- **特点**：仅包含一个文件夹，即用户打开的单一项目目录。
- **功能**：VSCode会自动跟踪在这个文件夹内所做的编辑、文件状态以及编辑器布局等信息，确保用户在重新打开该项目时能恢复到之前的工作状态。
- **配置**：针对这个单个项目，用户可以在`.vscode`目录下创建特定的配置文件（如`settings.json`、`tasks.json`、`launch.json`等），覆盖全局用户设置，实现项目级别的个性化配置。

#### **2. 多文件夹工作区（Multi-root workspace）**
- **特点**：包含多个相互关联或需要同时处理的文件夹，即多个项目或项目子模块的集合。
- **功能**：在一个工作区文件中（`.code-workspace`格式），可以指定多个文件夹路径，使得这些文件夹在VSCode中以统一的视图呈现，便于同时访问和管理。
- **配置**：多文件夹工作区不仅共享一个全局工作区设置，还能为每个包含的文件夹单独配置（在各自`.vscode`目录下），提供更加精细化的项目管理。
- 优先级顺序为：用户设置 -> 工作区设置 -> 文件夹设置。

### **工作区的作用**
使用VSCode工作区有以下好处：

- **集中管理**：将相关的项目资源集中在一起，方便快速切换和协同开发。
- **个性化配置**：针对不同工作区或项目，定制特定的编辑器设置、代码片段、主题、键盘快捷键等，避免干扰其他项目或全局环境。
- **插件管理**：在工作区内启用或禁用特定插件，确保为每个项目提供最适合的工具集，减少不必要的资源消耗。
- **任务与调试**：定义和运行针对工作区特定的构建任务、测试脚本或调试配置，简化开发流程。
- **工作状态保存**：记录并恢复工作区的编辑状态、文件打开情况和布局，提高开发效率。

### **如何设置与使用VSCode工作区**

#### **创建工作区**
- **单文件夹工作区**：直接通过“文件”菜单选择“打开文件夹”（或使用快捷键“Ctrl + K，Ctrl + O”），选择一个项目目录即可。
- **多文件夹工作区**：
  - **新建**：打开一个项目文件夹后，通过“文件”菜单选择“将工作区另存为”，指定一个`.code-workspace`文件的位置并命名。随后在工作区编辑器中添加其他需要包含的文件夹路径。
  - **已有文件夹加入**：如果已经有一个工作区，可以通过“文件”菜单选择“将文件夹添加到工作区”，将新项目添加到现有工作区中。

#### **工作区设置**
- **基本设置**：对于单文件夹工作区，直接编辑`.vscode/settings.json`文件；对于多文件夹工作区，编辑`.code-workspace`文件中的`settings`部分。
- **生成工作区设置**：在文件浏览器侧边栏中，右键点击工作区文件夹，选择“生成代码工作区设置”，这将自动创建一个`settings.json`文件并填充基础配置。

#### **插件管理**
- **启用/禁用**：在插件列表中，对特定插件右键点击，选择“启用（工作区）”或“禁用（工作区）”，以限制插件在当前工作区的使用。

### **总结**
VSCode工作区是一个强大的项目管理工具，它允许开发者根据实际需求组织和定制开发环境，实现多项目并行处理、个性化配置以及高效的工作流程管理。通过创建、配置和合理使用工作区，用户可以极大地提升在VSCode中的开发体验和生产力。
