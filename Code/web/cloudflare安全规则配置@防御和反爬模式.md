## abstract

针对网站且经常遭受爬虫的情况，直接在 Cloudflare (CF) 上进行拦截是最经济且高效的选择。

在 Cloudflare 的 WAF（Web 应用程序防火墙）中，有几种主要的防御模式。以下是它们的对比以及针对你多站点情况的配置建议：

### 1. Cloudflare 防御模式对比

| **模式**                               | **防御强度**  | **用户体验**        | **对 curl 等脚本效果**                     | **适用场景**                             |
| -------------------------------------- | ------------- | ------------------- | ------------------------------------------ | ---------------------------------------- |
| **JS 挑战 (JS Challenge)**             | 中            | 较好 (等待 2-5 秒)  | **有效**。脚本通常无法执行复杂混淆的 JS。  | 普通爬虫，简单的自动化工具。             |
| **托管挑战 (Managed Challenge)**       | **高 (推荐)** | **极佳 (智能评估)** | **极强**。结合指纹、信誉等，脚本极难绕过。 | **最推荐的模式**。能自动识别真人与机器。 |
| **交互式挑战 (Interactive Challenge)** | 极高          | 差 (需手动点击)     | 脚本无法通过。                             | 遭受严重攻击时，或针对高价值路径。       |
| **五秒盾 (I'm Under Attack)**          | 极高          | 极差 (强制全站等待) | 全力拦截。                                 | 服务器即将宕机时的最后手段。             |

------

### 2. 为什么推荐“托管挑战 (Managed Challenge)”？

对于多网站服务器，托管挑战是**性价比最高**的方案：

1. **智能分级：** 它会根据访问者的信誉度来决定。如果是正常的海外真实用户，可能完全无感通过；如果是可疑的 `curl` 脚本，它会强制要求进行 JS 验证或弹出验证码。
2. **保护 SEO：** 它内置了 Google、Bing 等已验证爬虫的白名单，不会因为你开启了防御而导致网站从搜索结果中消失。
3. **低误伤：** 相比于死板的 JS 挑战，托管挑战能有效减少真实用户的流失。

------

### 3. 针对多网站的配置策略（两手抓）

既然你有多站，建议不要开启全局的“Bot Fight Mode”，因为那不可控。你应该使用 **WAF 自定义规则**。

#### 第一手：配置“通用型”防御规则（针对所有站）

在 CF 后台的 `安全性 -> WAF -> 自定义规则` 中：

- **匹配条件：** `(http.user_agent contains "curl") or (http.user_agent contains "python") or (http.user_agent contains "wget")`
- **操作：** **拦截 (Block)**。
- *注：直接在边缘侧切断最基础的脚本工具。*

#### 第二手：配置“核心业务”防御规则（针对特定路径）

这是保护 `/product/` 或 `/shop/` 等高价值页面的核心：

- **匹配条件：** `(http.request.uri.path contains "/product/")` 或 `(http.request.uri.path contains "/shop/")`
- **逻辑判断：** 且 `(not cf.client.bot)` (即：不是已验证的搜索引擎爬虫)
- **操作：** **托管挑战 (Managed Challenge)**。

------

### 4. 表达式参考（可直接复制到 CF）

如果你在 CF 后台点击 `编辑表达式`，可以参考这个逻辑：



```SQL
(http.request.uri.path contains "/product/" and not cf.client.bot) or (http.user_agent contains "curl") or (http.user_agent contains "python-requests")
```

*执行操作：Managed Challenge*

------

### 5. 多站点服务器的特别注意事项

1. **IP 隔离：** 如果你的服务器 IP 已经泄露（爬虫绕过 CF 直接扫你的 IP），CF 的挑战就失效了。
   - **优化：** 在你的 Nginx/防火墙上设置**只允许 Cloudflare 的 IP 访问**。
2. **Real-IP 模块：** 再次强调，一定要在 Nginx 里配置 `set_real_ip_from`，否则你的日志里全都是 CF 的 IP，你无法分析到底哪一个网站在被攻击。
3. **日志监控：** 定期查看 CF 的 `安全性 -> 概览`。它会告诉你哪些请求被托管挑战拦截了，这能帮你微调规则。

### 总结建议

**首选“托管挑战 (Managed Challenge)”**。它比单纯的 JS 挑战更聪明，对海外 SEO 更友好，且能有效阻挡包括 `curl` 和伪造 UA 在内的大多数自动化攻击。
