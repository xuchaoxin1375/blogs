## abstract

在某些不当操作,或者允许的软件或插件有bug的情况下,mac设备可能会出现耗电异常,或者发烫的情况出现;

有时候异常表现的比较隐蔽,例如,一个命令行程序陷入死循环,那么这个程序会消耗掉一个cpu核心,使得这个核心的使用率处于99%以上;并且cpu时间容易积累到很大的数值;

这时候仅仅查看"活动监视器"(进程管理器的图形界面)的cpu负载,会发现总负载并不算高(因为如果只有一个核心被用满,其余核心空闲的话,总的cpu负载看起来并不高,但是单个核心长时间满载也会导致热量堆积,导致明显发热,尤其是通电的情况下,积热现象会更加明显)

> 排查发热问题时,重要指标包括:`Energy Impact`(和电能消耗直接相关,降序排列直接定位耗电进程),`%cpu`(衡量进程对cpu负载),`cpu time`(统计进程占用cpu运行时间)
>
> 有些字段并不默认显示,用户可以通过调整活动监视器要显示的字段来调出指定的字段;

### macos中的%cpu指标

> 在 macOS 的 **Activity Monitor（活动监视器）** 或 `top`/`ps` 命令中，`%CPU` 的含义与 Windows 任务管理器略有不同。理解它的关键在于：**它是基于单个逻辑核心（Core）计算的，而不是总 CPU 容量。**

计算逻辑：以 100% 为单核基准:

在 macOS 中，**100% 代表一个完整的逻辑核心被占满**。

- 如果你的 Mac 是 **8 核** 处理器，那么你的总 CPU 理论上限是 **800%**。
- 如果你看到一个进程（比如你之前图中的 `zsh`）占用 **99.8%**，这意味着它几乎完全吃掉了一个核心。
- 如果一个多线程程序（如视频渲染或编译代码）占用了 **400%**，说明它正在同时利用 4 个核心的运算能力。

为什么会出现超过 100% 的情况？

这是类 Unix 系统（包括 Linux）的通用显示方式。这种设计的目的是为了让你一眼看出：

1. **进程的效率：** 该程序是否支持多线程。如果一个密集型任务始终只有 100%，说明它可能只运行在单核上，存在性能瓶颈。
2. **核心负载：** 方便开发者和系统管理员判断单核的压力，而不仅仅是整体的百分比。

### 异常进程示例

```bash
$ ps aux |grep zsh
cxxu             67385  98.7  0.0 435306352    912   ??  R     7:24PM 319:13.01 -/bin/zsh
cxxu             60286   4.3  0.0 442225216   7792 s000  S     9:07AM   0:00.65 -zsh
cxxu             43507   0.1  0.0 435310512   2192   ??  SN    8:30AM   0:03.35 -/bin/zsh
...
```

这里我使用`ps`命令检查被怀疑高占用的`zsh`进程,发现进程ID为67385的zsh进程霸占了一个核心,该进程正处于“单核满载”状态。由于 zsh 通常是单线程运行，这几乎就是它的物理极限了。

### 进程终止

对于命令行用户,查询到问题进程后,使用`killall`,`pkill`,`kill`等命令终止进程;

假设我在zsh这个shell中因为插件配置问题导致一个后台运行的死循环,导致设备发热,那么可以用命令

```bash
killall -9 zsh
```

强制终止;

对于GUI用户,更加友好的方式是使用活动监视器管理进程,也可以通过它终止指定进程;

> macos的活动监视器和windows的进程管理器最大的不同之一是邮件进程没有提供菜单可以结束进程;
>
> 活动监视器的顶部菜单栏中有进程结束(stop)按钮(建议最大化或全屏操作,否则有些按钮可能不会直接显示出来,而被收纳在折叠菜单中),选中进程后点击停止按钮即可;

### 系统电池统计耗电程序

对于macbook,菜单栏的电池点击后里面会统计耗电程序(不过有的程序会启动子进程,例如终端程序cmux中启动一个shell,如果shell死循环导致的高占用也会累计到父进程头上,因此建议还是根据活动监视器来排查问题)
