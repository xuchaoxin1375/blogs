### btop的功能模块

btop默认加载4大模块(内存,网络,cpu,进程)中,进程管理模块最为关键;

### 全屏查看某一个模块

btop默认加载4个模块,1,2,3,4;分被对应cpu,内存,网络,进程

如果要全屏观察其中的某个模块,可以关闭其他模块来间接实现;

例如我要全屏观察进程模块(4),则按下1,2,3(关闭这些模块)

## 使用btop进行资源占用分析

btop是同类工具中相对易用的工具,其help页面的内容相对直观且并不复杂;

根据你提供的 `btop` 进程列表截图，可以清晰地分析出 **btop 进程管理模块**的界面布局和菜单功能。

---

### 界面布局（从上到下）

| 区域                   | 内容说明                                                     |
| ---------------------- | ------------------------------------------------------------ |
| **顶部工具栏**(第一行) | 左侧:显示 `proc`（当前是进程视图）、`filter`（过滤器状态）、<br />右侧:`per-core`（每核CPU）、`reverse`（反向排序）、`tree`（树形视图）、<br />最后一列(表示当前的排序依据字段),例如`user`（用户过滤）,`mem`(内存)等可用字段(通过左/右方向键来更换排序依据字段) |
| **列标题行**(第二行)   | `Pid:`、`Program:`、`Command:`、`Threads:`、`User:`、`Mem`、`Cpu%` |
| **进程列表主体**       | 每一行显示一个进程或线程，树形结构通过缩进体现父子关系       |
| **底部提示栏**         | 显示 `select`、`info`、`terminate`、`kill`、`signal`、`Nice` 等可用操作，以及 `15/1703`（当前显示进程数/总进程数） |

### 进程排序

> 排序依据"字段"是可变的,其他字段是相对固定的;
>
> 在排查进程资源占用时,通常是逆序排序cpu或mem(内存)

`btop` 允许你根据不同的资源消耗维度对进程进行排序。

你可以通过使用 **`<`** 和 **`>`** 方向键快速切换排序字段。

以下是 `btop` 中可用的主要排序字段及其含义：

------

#### 进程排序字段 (Process Sorting)

`btop` 的配置文件中明确列出了进程排序选项：`"pid"` `"program"` `"arguments"` `"threads"` `"user"` `"memory"` `"cpu lazy"` `"cpu direct"`，即共 **8 个排序字段**。

> `btop.conf `模板相关参考:

```ini
#* Processes sorting, "pid" "program" "arguments" "threads" "user" "memory" "cpu lazy" "cpu direct",
#* "cpu lazy" sorts top process over time (easier to follow), "cpu direct" updates top process directly.
proc_sorting = "cpu lazy"
```

在 btop 的配置项 `proc_sorting` 中，可以设置进程的默认排序方式，默认值为 `"cpu lazy"`。

| 字段名       | 中文说明                      | 适用场景                                           |
| ------------ | ----------------------------- | -------------------------------------------------- |
| `pid`        | 按进程 ID 排序                | 查看进程创建先后顺序，ID 越小代表启动越早          |
| `program`    | 按程序名称排序（字母序）      | 快速定位特定名称的程序，便于查找                   |
| `arguments`  | 按启动参数/完整命令行排序     | 区分同名程序但参数不同的实例                       |
| `threads`    | 按线程数排序                  | 找出多线程密集型进程                               |
| `user`       | 按用户名排序                  | 按用户归属分组，适合多用户系统管理                 |
| `memory`     | 按内存占用排序                | 找出内存消耗大的进程，排查内存泄漏                 |
| `cpu lazy`   | 按 CPU 使用率排序（平滑采样） | **默认排序**，使用滑动平均，波动较小，适合日常监控 |
| `cpu direct` | 按 CPU 使用率排序（即时采样） | 实时采样，响应更灵敏，适合排查瞬时 CPU 飙升        |

------

`cpu lazy` vs `cpu direct` 的区别

| 对比项     | `cpu lazy`（默认） | `cpu direct`      |
| ---------- | ------------------ | ----------------- |
| 采样方式   | 滑动平均/延迟采样  | 当前周期即时采样  |
| 数值稳定性 | 波动小、较平滑     | 波动大、更敏感    |
| 适合场景   | 日常监控、总体趋势 | 定位瞬时 CPU 爆发 |

#### 常用操作小贴士

- **快速切换排序：** 在进程列表处于激活状态时，按下键盘上的 **`,` (逗号)** 和 **`.` (句号)** 可以直接循环切换排序依据。
- **反向排序：** 默认通常是降序（从大到小），你可以按 **`r`** 键反转排序顺序（Reverse）。
- **筛选进程：** 如果进程太多看不过来，按 **`f`** 键输入名称可以直接进行过滤，这比单纯排序更高效。
- btop 支持完整鼠标操作，直接**点击列标题**即可按该列排序。(对于选中的进程,回车或者双击可以查看详情)

> **注意：** `btop` 的 UI 非常灵活，如果你发现有些字段没显示，可能是因为窗口缩放太小。尝试全屏或拉大终端窗口，隐藏的列会自动出现。

### 典型使用流程示例

1. **切换树形/扁平显示**：按 `e`
2. **反向排序**：按 `r`
3. **过滤进程**：按 `/` 输入 `mysql`，只显示相关进程
4. **杀死进程**：
   - 用方向键选中进程（如 `mysqld`）
   - 按 `k` 强制杀死，或按 `t` 正常终止
5. **查看详情**：选中进程后按 `Enter`
6. **调整优先级**：选中进程后按 `N`，输入新的 nice 值
