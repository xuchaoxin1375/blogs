前面几篇讲的是命令和语法。这一篇把它们放进真实任务：改配置、批量处理文件、清理日志、转换文本格式。

所有涉及 `-i` 的例子都默认先备份。`-i` 会直接改原文件，出错时没有“撤销”按钮；在副本上验证、保留备份、用 `diff` 对比，是比记住更多语法更重要的习惯。

## 修改前的安全检查

### 先看会改哪些行

把 `-i` 去掉，先用 `-n` 和 `p` 预览：

```shell
$ sed -n '/^include /p' /path/to/app.conf
include /www/server/nginx/conf/cf-realip.conf;
```

确认匹配范围后，再加 `-i`。

### 用 diff 对比修改前后

```bash
cp app.conf app.conf.orig
sed -i 's/old/new/g' app.conf
diff -u app.conf.orig app.conf
```

`diff -u` 会显示具体改了哪几行。确认无误后再删除 `.orig`；如果改错了，用 `cp app.conf.orig app.conf` 恢复。

### 用进程替换做“不落盘”的预览

在 bash 中可以直接比较原文件和处理结果，不产生中间文件：

```bash
diff -u app.conf <(sed 's/old/new/g' app.conf)
```

进程替换 `<(...)` 是 bash 特性，POSIX `sh` 不一定支持；脚本要跨平台时用临时文件更稳。

## 注释与取消注释配置行

### 注释单行，并保证重复执行不叠加

最简单的注释是给行首加 `# `：

```shell
$ printf 'include /www/server/nginx/conf/cf-realip.conf;\n' | sed 's/^/# /'
# include /www/server/nginx/conf/cf-realip.conf;
```

但如果对已经注释过的行再执行一次，会变成 `# # include...`。配置脚本通常需要 **幂等**(idempotent，重复执行结果不变)，所以先判断行首有没有 `#`：

```bash
sed -E -i.bak \
  's|^([[:space:]]*)(include /www/server/nginx/conf/cf-realip\.conf;)|\1# \2|' \
  /path/to/app.conf
```

- `^([[:space:]]*)` 捕获行首缩进。
- `(include ...)` 只匹配未注释的行；已经以 `#` 开头的行不会匹配。
- 替换成 `\1# \2`，保留缩进并在内容前加 `# `。

测试幂等性：

```shell
$ printf 'include /www/server/nginx/conf/cf-realip.conf;\n# include /www/server/nginx/conf/cf-realip.conf;\n' > c.conf
$ sed -E -i 's|^([[:space:]]*)(include /www/server/nginx/conf/cf-realip\.conf;)|\1# \2|' c.conf
$ cat c.conf
# include /www/server/nginx/conf/cf-realip.conf;
# include /www/server/nginx/conf/cf-realip.conf;
```

两行都只带一个 `# `，第二行没有被重复注释。

### 取消注释

去掉行首的一个 `#` 和它后面的空白：

```bash
sed -E -i.bak 's|^#[[:space:]]*(include real_cdn_ip\.conf;)|\1|' /path/to/app.conf
```

它只匹配“行首正好是一个 `#`，后面可能跟空白，再跟目标内容”的行；不会误删行中间的 `#`。

### 注释一个区块

用地址范围加命令分组：

```bash
# 预览
sed -n '/^plugins=(/,/)/{s/^#*/#/;p;}' ~/.zshrc

# 正式修改，保留备份
sed -i.bak '/^plugins=(/,/)/{s/^#*/#/;}' ~/.zshrc
```

`s/^#*/#/` 会把行首零个或多个 `#` 统一成一个 `#`：未注释的行加上 `#`，已经有 `###` 的行压成一个 `#`。如果只想加、不想压缩已有的 `#`，用 `s/^/# /`。

范围里的 `/)/` 会匹配任何包含 `)` 的行；如果配置块里还有嵌套括号，结束条件可能提前触发。需要精确匹配时写成 `/^)$/`。

### 注释时对齐

配置行前面可能有缩进，注释后希望 `# ` 统一从行首开始：

```bash
sed -i.bak -E 's|^[[:space:]]*(map_hash_bucket_size.*)|# \1|' r.conf
```

修改前：

```bash
map_hash_bucket_size 128;
 map_hash_max_size 65536;
```

修改后：

```bash
# map_hash_bucket_size 128;
# map_hash_max_size 65536;
```

`[[:space:]]*` 吃掉原来的缩进，`# \1` 重新给出统一的 `# ` 前缀。

## 修改键值对

### 只改值，保留键名

```shell
$ printf 'host=old\nport=80\n' | sed -E 's/^host=.*/host=new/'
host=new
port=80
```

只匹配以 `host=` 开头的行，不会动 `port=`。

### 用分组保留原有格式

如果值的格式需要保留引号或空格，用分组把键名和分隔符捕获下来：

```shell
$ printf "define( 'DB_NAME', 'old_db' );\n" | \
  sed -E "s/(define\( 'DB_NAME', ')[^']*(' \);)/\1new_db\2/"
define( 'DB_NAME', 'new_db' );
```

- `(define\( 'DB_NAME', ')` 捕获前缀；`\(` 在 ERE 里匹配字面左括号。
- `[^']*` 匹配旧值，不会跨过单引号。
- `(' \);)` 捕获后缀。
- `\1new_db\2` 只替换中间的值。

这是 WordPress `wp-config.php` 里改数据库名的常见写法。先备份：

```bash
sed -E -i.bak "s/(define\( 'DB_NAME', ')[^']*(' \);)/\1new_db\2/" /path/to/wp-config.php
```

如果文件里的空格或引号格式不同，先 `grep -n "DB_NAME"` 看实际内容，再调整正则，不要直接套用。

## 删除区块与插入内容

### 删除两个标记之间的内容

```shell
$ printf 'keep\nBEGIN\nx\ny\nEND\nkeep2\n' | sed '/^BEGIN$/,/^END$/d'
keep
keep2
```

用 `^BEGIN$`、`^END$` 锚定整行，避免误匹配 `BEGINNER` 这类包含关系。

### 在配置节标题后插入一行

```shell
$ printf '[database]\nhost=old\n' | sed '/^\[database\]/a host=localhost'
[database]
host=localhost
host=old
```

`a` 把新行追加在匹配行之后，所以新行排在原来的 `host=old` 前面。如果希望替换旧值，用 `s` 而不是 `a`。

### 在文件末尾追加多行

```bash
sed -i.bak '$a\
# managed by ops\
max_connections=1000' config.ini
```

`$` 选中最后一行，`a` 在其后追加两行。注意第一行末尾的 `\` 是续行符，最后一行不带 `\`。

### 在文件开头插入文件内容

GNU sed 支持零地址 `0r`：

```bash
sed -i.bak '0r header.txt' body.txt
```

`0r` 表示在第一行之前插入 `header.txt` 的内容。BSD/macOS 不支持零地址，跨平台时用 `cat` 重新拼文件更直接：

```bash
cat header.txt body.txt > body.txt.new && mv body.txt.new body.txt
```

## 真实案例：替换 oh-my-zsh 安装脚本的下载源

旧笔记里有一条命令，想注释掉安装脚本里的 `remote`、`repo` 变量，再追加 Gitee 镜像。原命令类似：

```bash
sed '/(^remote)|(^repo)/I s/^#*/#/ ;
/^#*remote/I a\
REPO=${REPO:-mirrors/oh-my-zsh}\
REMOTE=${REMOTE:-https://gitee.com/${REPO}.git} ' -r -iE ~/install.sh
```

这条命令能演示不少东西，但不适合直接照抄，原因有几个：

- `-iE` 不是“`-i` 加 `-E`”，而是 `--in-place=E`，备份文件会叫 `install.shE`；`-E` 应该写在 `-i` 前面。
- `/^#*remote/I` 的 `I` 让 `remote` 也匹配 `REMOTE`，可能把后面新加的变量一起注释掉。
- `a` 的文本在单行写法里会读到行尾，在多行写法里靠反斜杠续行；脚本里的分号、引号和续行很容易被当成文本。
- 在宽泛的地址上使用 `a`，每个匹配行都会追加一遍，容易产生重复。

更稳妥的做法是直接替换赋值行的值，而不是“注释 + 追加”：

```bash
sed -E -i.bak \
  -e 's|^(REPO=).*|\1"${REPO:-mirrors/oh-my-zsh}"|' \
  -e 's|^(REMOTE=).*|\1"${REMOTE:-https://gitee.com/${REPO}.git}"|' \
  /path/to/install.sh
```

假设原文件是：

```bash
REPO="${REPO:-ohmyzsh/ohmyzsh}"
REMOTE="${REMOTE:-https://github.com/ohmyzsh/ohmyzsh.git}"
```

执行后变成：

```bash
REPO="${REPO:-mirrors/oh-my-zsh}"
REMOTE="${REMOTE:-https://gitee.com/${REPO}.git}"
```

要点：

- 单引号防止 shell 展开 `${REPO}`，让这段文本原样进入脚本。
- `^(REPO=).*` 匹配整行赋值，替换成新的整行。
- 重复执行结果不变，因为每次都从 `REPO=` 重新替换。
- 先备份，再 `diff` 确认只改了这两行。

修改安装脚本仍然有风险：不同版本的 `install.sh` 变量名和格式可能不同。先 `grep -nE '^(REPO|REMOTE)=' install.sh` 确认实际内容，再决定是否使用。

## 批量处理文件

### 先找出包含目标文本的文件

```bash
grep -rln 'old_api' /path/to/project
```

`-l` 只列文件名；想看行号时去掉 `-l`、保留 `-n`。先确认范围，再批量改。

### 用 find 加 -exec

```bash
find /path/to/project -name '*.conf' -exec sed -i.bak 's/old_api/new_api/g' {} +
```

- `{}` 是找到的文件名。
- `+` 表示一次把多个文件传给 `sed`，比每个文件启动一次进程更高效。
- `-i.bak` 会为每个文件生成 `.bak` 备份。

### 用 xargs 处理含空格的文件名

```bash
find /path/to/project -name '*.conf' -print0 |
  xargs -0 sed -i.bak 's/old_api/new_api/g'
```

`-print0` 用 NUL 分隔文件名，`xargs -0` 按 NUL 读取，能正确处理空格和换行。文件名里没有特殊字符时，`-exec ... +` 更简单。

如果 `find` 可能一个文件都找不到，先确认列表非空，或给 GNU `xargs` 加 `-r`，避免 `sed` 没有文件参数而转去读标准输入、看起来像“卡住”。

### 用通配符

```bash
sed -i.bak 's/old_api/new_api/g' ./*.conf
```

通配符由 shell 展开，只匹配当前目录；子目录要用 `find` 或 `globstar`。

### 批量修改的注意事项

- **先备份**：`-i.bak` 是最低要求；重要文件再加一层版本控制或目录备份。
- **先小范围测试**：拿一个文件跑一遍，`diff` 确认，再扩大到全部。
- **注意符号链接**：GNU sed 的 `-i` 默认替换链接本身，不修改目标；需要改目标时加 `--follow-symlinks`，或者先确认链接关系。
- **注意权限**：`-i` 会在目录里创建临时文件，需要对目录有写权限；只对文件有写权限不一定够。
- **注意 macOS**：`-i` 必须带后缀参数，批量脚本要单独处理，见 [跨平台差异](08-排错@编码控制字符与跨平台差异.md#gnu-与-bsdmacos-的主要差异)。

## 日志处理

### 截取时间段

```bash
sed -n '/2026-11-15 10:00/,/2026-11-15 11:00/p' access.log
```

范围结束行也会包含。如果日志里没有结束时间，范围会一直持续到文件末尾；先确认结束标记存在。

### 给每行加前缀

```bash
sed 's/^/[app] /' app.log
```

### 隐藏密码

```shell
$ printf 'user=alice password=secret123 role=admin\n' |
  sed -E 's/(password=)[^ ]+/\1*****/g'
user=alice password=***** role=admin
```

`[^ ]+` 只匹配到下一个空格，避免把后面的字段一起吃掉。真实日志的字段分隔可能更复杂，先确认格式。

### 加行号

```bash
sed = app.log | sed 'N;s/\n/\t/'
```

输出“行号 + 制表符 + 原行”。只想看行数：

```bash
sed -n '$=' app.log
```

### 删除 ANSI 颜色码

GNU sed 可以用十六进制转义匹配 ESC：

```bash
sed -E 's/\x1B\[[0-9;]*[mK]//g' colored.log
```

这只是常见颜色码的简化匹配，不是完整的终端转义解析器；复杂场景用 `ansi2txt` 之类的工具。

## 文本格式转换

### DOS/Windows 换行转 Unix

在 Linux 上：

```bash
sed -i.bak 's/\r$//' file.txt
```

在 macOS/BSD 上，`sed` 对 `\r` 的支持不一致，用 `tr` 更稳：

```bash
tr -d '\r' < file.txt > file.unix.txt
```

在 Windows 的 Git Bash/MSYS 中，`sed` 可能默认按文本模式打开文件，已经去掉了 CR；要看原始字节时加 `-b`。详见 [CRLF 与 BOM](08-排错@编码控制字符与跨平台差异.md#crlf-与-bom)。

### 去掉首尾空白

```bash
sed -E 's/^[[:space:]]+//; s/[[:space:]]+$//' file.txt
```

### 合并连续空白

```bash
sed -E 's/[[:space:]]+/ /g' file.txt
```

### 把所有行合并成一行

```bash
sed ':a;N;$!ba;s/\n/, /g' file.txt
```

只适合小文件，因为它会把整个文件读进一个模式空间。

### 把一行拆成多行

```bash
sed 's/;/\n/g' file.txt
```

GNU 支持 `\n`；BSD/macOS 用反斜杠加真实换行：

```bash
sed 's/;/\
/g' file.txt
```

### CSV 转 TSV 的边界

```bash
tr ',' '\t' < data.csv > data.tsv
```

这只适用于“字段里没有逗号、没有引号、没有换行”的简单 CSV。字段里出现 `"a,b"` 时，这个命令会把引号内的逗号也换掉，得到错误结果。真实 CSV 用 `csvkit`、Python 的 `csv` 模块或 `awk` 的字段模式处理。

如果坚持用 `sed`，GNU 版可以写 `sed 's/,/\t/g' data.csv > data.tsv`；BSD/macOS 对替换里的 `\t` 支持不一致，优先用 `tr`。

### Markdown 标题转 HTML

```bash
sed -E '
  s/^### (.*)/<h3>\1<\/h3>/
  s/^## (.*)/<h2>\1<\/h2>/
  s/^# (.*)/<h1>\1<\/h1>/
' doc.md
```

这些模式都要求 `#` 后面有空格，所以 `###` 不会被 `^# ` 误匹配；从多到少写只是读起来更顺。这个例子不处理行内格式、代码块和嵌套结构。

## 什么时候换用其他工具

`sed` 适合“按行选择 + 局部替换”。遇到下面的任务，换工具通常更快、更安全：

| 任务 | 更合适的工具 | 原因 |
| --- | --- | --- |
| 按列筛选、求和、分组 | `awk` | 直接按字段处理，不需要用正则拆列 |
| 解析 JSON、YAML、CSV | `jq`、`yq`、Python 的 `csv`/`json` 模块 | 能处理嵌套、引号、转义和类型 |
| 复杂替换或需要回调 | `perl`、`python` | 支持完整正则、函数和数据结构 |
| 只查找不修改 | `grep`、`rg` | 更直接，输出和退出码更适合判断 |
| 批量重命名文件 | `rename`、`mmv` 或脚本 | 专门处理文件名，能预览和回滚 |
| 结构化编辑配置文件 | 对应工具的配置命令或解析器 | 注释、缩进和嵌套结构更容易保持 |

判断标准不是“sed 能不能做到”，而是“下次还能不能读懂、改对”。一行 `sed` 能解决的事不必引入脚本；需要几十行 `sed` 加标签才能完成的事，通常已经超出它的舒适区。

## 性能与管道习惯

`sed` 本身是流式处理，通常不需要为了性能做复杂优化。下面几条习惯更实际：

- 只需要文件前面一部分时，用 `q` 提前退出，例如 `sed '1000q' huge.log`，避免读完整个文件。
- 多个替换合并到一次 `sed` 调用里，比串联多个 `sed` 少启动几个进程。
- 能直接写 `sed '...' file` 时，不必写成 `cat file | sed '...'`；少一个进程和一根管道。
- `-i` 会在同目录创建临时文件，处理超大文件前先确认磁盘空间。

这些是工程习惯，不是硬性规则；可读性和正确性优先于省下的一次进程启动。

## 实战清单

在把命令用于真实文件之前，按下面几条过一遍：

- 是否保留了备份？至少 `-i.bak`，重要文件再加目录备份或版本控制。
- 是否先预览过？去掉 `-i`，用 `-n`/`p` 或 `diff -u` 确认匹配范围。
- 正则是否会误伤？用 `^`、`$` 和 `[^...]` 收紧范围，先在样本上验证。
- 是否处理了多文件边界？默认多文件是一条连续流；需要独立时用 `-s` 或 `-i`。
- 是否在 macOS 上运行？`-i`、`\n`、`a/i/c` 写法都可能不同。
- 文件编码是否正常？出现 `^M`、`^@`、BOM 或乱码时先看 [排错](08-排错@编码控制字符与跨平台差异.md)。
- 是否有更合适的工具？按列处理用 `awk`，结构化数据用解析器，复杂替换用 `perl`/`python`。

## 自测

- 幂等地注释掉以 `include` 开头的行，保留缩进。
- 取消注释 `# include real_cdn_ip.conf;`。
- 删除 `BEGIN` 到 `END` 的整行区块。
- 批量给当前目录的 `.conf` 文件做替换并保留 `.bak`。
- 把 WordPress 配置里的 `DB_NAME` 值换掉，保留原有格式。

参考答案：

```bash
sed -E -i.bak 's|^([[:space:]]*)(include )|\1# \2|' file
sed -E -i.bak 's|^#[[:space:]]*(include real_cdn_ip\.conf;)|\1|' file
sed -i.bak '/^BEGIN$/,/^END$/d' file
sed -i.bak 's/old/new/g' ./*.conf
sed -E -i.bak "s/(define\( 'DB_NAME', ')[^']*(' \);)/\1new_db\2/" wp-config.php
```
