`sed` 是 Linux/Unix 上最常用的文本处理工具之一。它按行读取输入，把规则应用到匹配的行或文本片段上，再把结果写到标准输出；加上 `-i` 也可以直接修改文件。

这份资料把原先零散的笔记合并成一条学习路径：先建立工作模型，再学地址、正则和替换，最后进入多行处理、实战与排错。每一篇都尽量给出可直接运行的命令、真实输出和常见误区。

## 适合谁，读到什么程度

适合已经会基本 shell 操作、想批量修改配置、清理日志或写自动化脚本的读者。读完后应该能够：

- 看懂并写出常见的 `sed` 命令，而不是只会复制一行；
- 判断一条命令为什么匹配到（或没匹配到）某一行；
- 在 GNU sed 与 macOS/BSD sed 之间写出可移植的版本；
- 遇到“匹配不上”“文件被清空”“编码不对”时，知道先检查什么。

不要求事先系统学过正则表达式；需要的基础语法在 [正则表达式](03-正则@BRE与ERE@分隔符.md) 中从头讲。也不要求熟悉 `awk`、`perl`，但 [实战](07-实战@常见任务与案例.md#什么时候换用其他工具) 会说明什么时候换工具更合适。

## 阅读约定

- 示例默认在 **GNU sed 4.9** 上运行，环境为 Linux 或 Git Bash；示例输出以实际运行为准，带时间戳、路径等环境相关的内容会做归一化处理。
- 以 `$` 开头的代码块是**终端记录**，`$` 后面是命令，其余行是输出，不要连同提示符一起复制。
- 不带 `$` 的 `bash` 代码块是**可直接复制执行**的命令或脚本。
- macOS 自带的是 BSD 版 `sed`，`-i`、`\n` 替换、`a`/`i`/`c` 写法等与 GNU 版不同；跨平台写法集中在 [排错与跨平台差异](08-排错@编码控制字符与跨平台差异.md)。
- 命令中的不确定路径统一写成 `/path/to/...`，需要照做的例子会给出具体文件名。

## 主要依据

- [GNU sed manual](https://www.gnu.org/software/sed/manual/sed.html)：GNU 扩展、命令语义、退出状态。
- [FreeBSD sed(1)](https://man.freebsd.org/cgi/man.cgi?query=sed&sektion=1)：BSD 系 `sed` 的行为参考。
- [macOS sed(1)](https://man.freebsd.org/cgi/man.cgi?query=sed&sektion=1&manpath=macOS+15.8)：macOS 自带版本的选项与限制。
- 文中标注“实测”的输出，均在 GNU sed 4.9 上执行核对；不同版本或平台可能有细微差异，涉及可移植性时会在正文说明。
