`sed` 里使用频率最高的命令是 **替换**(substitute)命令 `s`。它的作用是：在当前模式空间里找到正则匹配的片段，把这段片段换成新的文本。

它的语法是：

```bash
s/正则/替换/标志
```

三个部分分别回答：

- **正则**：要找什么？
- **替换**：找到后换成什么？
- **标志**：只换第一个还是全部？要不要打印？要不要写文件？

这一篇把 `s` 的替换文本、标志和常见任务讲清楚。正则的语法本身在 [正则表达式](03-正则@BRE与ERE@分隔符.md) 里。

## 只替换第一个匹配

默认情况下，`s` 只替换每行的**第一个**匹配：

```shell
$ echo 'foo foo foo' | sed 's/foo/bar/'
bar foo foo
```

要替换一行里的全部匹配，加 `g`（global）标志：

```shell
$ echo 'foo foo foo' | sed 's/foo/bar/g'
bar bar bar
```

这是 `sed` 与很多编辑器“替换全部”习惯不同的地方。写批量替换脚本时，先问自己：每行可能有多个匹配吗？如果是，别忘了 `g`。

## 替换文本的写法

### 普通文本

替换部分默认按字面量处理，但有几个字符有特殊含义：`&`、`\1` 到 `\9`、反斜杠，以及某些 GNU 扩展序列。

```shell
$ echo 'hello' | sed 's/hello/world/'
world
```

### &：整个匹配

替换文本里的 `&` 代表“正则匹配到的整个片段”：

```shell
$ echo 'abc' | sed 's/b/[&]/'
a[b]c
```

给匹配内容加括号、引号或重复它，都用得上 `&`：

```shell
$ echo 'TODO: write tests' | sed 's/TODO/[&]/'
[TODO]: write tests
```

要输出字面量 `&`，写成 `\&`：

```shell
$ echo 'a&b' | sed 's/&/\&/'
a&b
```

### \1 到 \9：分组引用

正则里用括号分组，替换里用 `\1`、`\2` 引用对应组的内容。ERE 里分组直接写 `(...)`：

```shell
$ echo 'Ada Lovelace' | sed -E 's/([A-Za-z]+) ([A-Za-z]+)/\2, \1/'
Lovelace, Ada
```

BRE 里分组写 `\(...\)`：

```shell
$ echo 'Ada Lovelace' | sed 's/\([A-Za-z]*\) \([A-Za-z]*\)/\2, \1/'
Lovelace, Ada
```

分组编号按左括号出现的顺序从 1 开始。替换里的 `\1` 写法在 BRE 和 ERE 中相同；不同的只是正则里的分组语法。

### 反斜杠与特殊字符

要在最终输出里得到一个反斜杠，替换文本里要写两个：

```shell
$ echo 'C:/path' | sed 's|/|\\|'
C:\path
```

在单引号脚本里，`\\` 经过 shell 原样传递，`sed` 把它解释成一个字面反斜杠。实际写脚本时，建议先用 `sed -n 'l'` 查看结果，避免层数数错。

### 换行

GNU sed 允许在替换文本里写 `\n` 表示换行：

```shell
$ printf 'a,b\n' | sed 's/,/\n/' | od -c
0000000   a  \n   b  \n
0000004
```

更可移植的写法是在替换里放一个反斜杠加真实换行：

```bash
sed 's/,/\
/' file
```

这两种写法在 GNU sed 上都能得到换行；BSD/macOS sed 通常只认后一种。跨平台脚本优先用反斜杠加真实换行的形式。

注意：替换出的换行只是模式空间里的一个字符，后续命令仍然把整段内容当作一个模式空间处理。自动打印时它会显示成两行，但这不代表 `sed` 重新从输入读了一行。

## 标志

`s` 命令后面可以跟零个或多个 **标志**(flag)：

| 标志 | 作用 | 说明 |
| --- | --- | --- |
| `g` | 替换所有匹配 | 不加时只替换第一个 |
| `数字` | 只替换第 n 个匹配 | 例如 `2` |
| `数字g` | 从第 n 个匹配开始，替换后面所有匹配 | GNU 的行为；POSIX 未定义与 `g` 混用 |
| `p` | 如果发生了替换，打印模式空间 | 常与 `-n` 搭配 |
| `w 文件` | 如果发生了替换，把结果写入文件 | 文件名一直读到行尾 |
| `e` | 把替换结果当作 shell 命令执行 | GNU 扩展，有安全风险 |
| `I` / `i` | 匹配时忽略大小写 | GNU 与 FreeBSD/macOS 支持；老 BSD 不一定 |
| `M` / `m` | 多行模式 | GNU 扩展 |

### 数字：只替换第 n 个

```shell
$ echo 'a a a a' | sed 's/a/b/2'
a b a a
```

`2` 只替换第二个匹配。`2g` 表示“忽略前两个之前的匹配，从第二个开始全部替换”：

```shell
$ echo 'a a a a' | sed 's/a/b/2g'
a b b b
```

`g` 和数字混用的含义在 POSIX 里没有规定，不同 `sed` 实现可能不同。跨平台脚本里不要依赖 `2g`，需要时拆成更明确的步骤。

### p：只显示发生替换的行

```shell
$ sed -n 's/error/ERROR/p' app.log
```

`-n` 关闭自动打印，`p` 只在替换成功时打印。这样输出里只会有发生过替换的行，适合检查“到底改了哪些行”。

不加 `-n` 时，`p` 会和自动打印叠加，导致被替换的行出现两次：

```shell
$ echo 'error' | sed 's/error/ERROR/p'
ERROR
ERROR
```

### w：把替换结果写入文件

```shell
$ sed -n 's/error/ERROR/w errors.txt' app.log
```

只有发生替换的行才会写入 `errors.txt`。文件名从 `w` 后面一直读到行尾，所以不能在同一行后面再写别的命令：

```shell
# 不符合预期：文件名会变成 "errors.txt ; 2d"
sed -n 's/error/ERROR/w errors.txt ; 2d' app.log

# 正确：用 -e 或换行分隔
sed -n -e 's/error/ERROR/w errors.txt' -e '2d' app.log
```

这个“文件名吃到行尾”的规则同样适用于 `w`、`W`、`r`、`R` 命令，详见 [文件读写命令](05-常用命令@增删改查与文件读写.md#读取与写入文件)。

### e：把替换结果当命令执行

`e` 是 GNU 扩展：如果替换成功，就把模式空间的内容当作 shell 命令执行，并用输出替换模式空间。

```shell
$ echo 'echo hi' | sed 's/.*/echo hi/e'
hi
```

这个功能很强，也很危险：输入内容如果来自不可信来源，可能执行任意命令。处理外部数据时不要随手加 `e`；需要限制时可以用 `--sandbox` 禁用 `e`、`r`、`w`。

### I：忽略大小写

```shell
$ echo 'Error' | sed 's/error/ok/I'
ok
```

`I` 和 `i` 等价。它只影响匹配，不影响替换文本的大小写。

### M：多行模式

`M` 让 `^`、`$` 匹配内嵌换行前后的位置，并让 `.` 不再匹配换行：

```shell
$ printf 'a\nb\n' | sed 'N;s/^/X/gM'
Xa
Xb
```

不加 `M` 时，`^` 只匹配整个模式空间的开头，所以只有第一行前面加了 `X`：

```shell
$ printf 'a\nb\n' | sed 'N;s/^/X/g'
Xa
b
```

## 大小写转换

GNU sed 在替换文本里支持大小写控制序列：

| 序列 | 作用 |
| --- | --- |
| `\U` | 后面的字符转大写，直到 `\L` 或 `\E` |
| `\L` | 后面的字符转小写，直到 `\U` 或 `\E` |
| `\u` | 下一个字符转大写 |
| `\l` | 下一个字符转小写 |
| `\E` | 结束 `\U` 或 `\L` 的大小写转换 |

例子：

```shell
$ echo 'hello world' | sed -E 's/([a-z]+) ([a-z]+)/\u\1 \u\2/'
Hello World
$ echo 'aabb' | sed -E 's/(a+)(b+)/\1\U\2\E/'
aaBB
$ echo 'HELLO' | sed -E 's/(.*)/\L\1/'
hello
```

这些序列是 GNU 扩展，BSD/macOS sed 不支持。跨平台时用 `tr` 或 `awk` 处理大小写更稳妥。

## 分隔符

`s` 的默认分隔符是 `/`。当正则或替换里包含 `/` 时，可以换一个分隔符：

```shell
$ echo '/usr/local/bin' | sed 's|/usr/local|/opt|'
/opt/bin
$ echo 'a/b/c' | sed 's,/,-,g'
a-b-c
```

规则：

- 分隔符可以是任意一个不是反斜杠或换行符的字符。
- 同一条 `s` 命令里三个分隔符必须一致。
- 内容里出现分隔符本身时，用 `\` 转义，或者换一个不冲突的字符。

完整说明和地址里的自定义分隔符见 [分隔符与转义](03-正则@BRE与ERE@分隔符.md#分隔符与转义)。

## 常见任务

### 删除一段文本

把替换部分留空：

```shell
$ echo 'foo bar baz' | sed 's/bar //'
foo baz
```

注意，这只会删除匹配到的片段，不会删除整行。要删除整行用 `d`；要删除行首或行尾的空白，见下面的 trim。

### 去掉行首、行尾空白

```shell
$ printf '  hello  \n' | sed -E 's/^[[:space:]]+//; s/[[:space:]]+$//'
hello
```

两条命令用分号连接，按顺序执行：先去行首，再去行尾。

只去行尾空白：

```shell
$ printf 'hello   \n' | sed -E 's/[[:space:]]+$//'
hello
```

### 合并连续空白

```shell
$ printf 'a   b\t\tc\n' | sed -E 's/[[:space:]]+/ /g'
a b c
```

如果只想合并空格、不想动制表符，把字符类换成普通空格：

```bash
sed -E 's/ +/ /g' file
```

### 在行首或行尾添加内容

```shell
$ printf 'a\nb\n' | sed 's/^/# /'
# a
# b
$ printf 'a\nb\n' | sed 's/$/;/'
a;
b;
```

`^` 和 `$` 匹配空位置，所以 `s/^/.../` 相当于插入前缀，`s/$/.../` 相当于插入后缀。

### 注释与取消注释

```shell
# 给每一行加 "# "
$ printf 'a\nb\n' | sed 's/^/# /'
# a
# b

# 去掉行首的一个 "#" 和其后的空白
$ printf '# a\n#b\n' | sed -E 's/^#[[:space:]]*//'
a
b
```

更稳妥的配置注释写法会先判断“是否已经注释”，避免重复加 `#`，见 [实战：注释与取消注释](07-实战@常见任务与案例.md#注释与取消注释配置行)。

### 修改 key=value

只改键值对的值，保留键名：

```shell
$ printf 'host=old\nport=80\n' | sed -E 's/^host=.*/host=new/'
host=new
port=80
```

只改包含特定键的行，不会误伤其他行。

### 交换两个字段

```shell
$ echo 'left:right' | sed -E 's/^([^:]*):(.*)$/\2:\1/'
right:left
```

`[^:]*` 比 `.*` 更精确：它只匹配到第一个冒号之前，不会把后面的冒号也吞掉。

### 删除行尾的 CR

在 Linux 上处理 Windows 换行文件时常用：

```shell
$ printf 'a\r\n' | sed 's/\r$//' | od -c
0000000   a  \n
0000001
```

在 Windows 的 Git Bash/MSYS 环境中，`sed` 可能默认按文本模式打开文件，已经替你处理了 CRLF，这时上面的命令看起来“没效果”；需要看原始字节时加 `-b`。跨平台细节见 [CRLF 与编码](08-排错@编码控制字符与跨平台差异.md#crlf-与-bom)。

## 常见误区

- **忘了 `g`**：默认只替换每行第一个匹配，批量替换时经常因此漏改。
- **把 `&` 当普通字符**：替换里的 `&` 代表整个匹配；要字面量就写 `\&`。
- **分组语法混用**：BRE 用 `\(...\)`，ERE 用 `(...)`；替换里的 `\1` 两种都一样。
- **以为 `\n` 到处都能用**：GNU 支持替换里的 `\n`，BSD/macOS 通常要写反斜杠加真实换行。
- **把 `s/.*//` 当成删除行**：它只是把模式空间清空，自动打印仍会输出一个空行；删除行要用 `d`。
- **在 `s///w` 后面接分号**：文件名会一直读到行尾，分号和后面的命令都会变成文件名的一部分。
- **在双引号里写正则**：shell 会展开 `$`、反引号，反斜杠也可能被处理；不确定时先用单引号，或把脚本写进文件用 `-f`。
- **以为替换失败会报错**：`s` 找不到匹配时什么也不做，退出状态仍是 0；需要判断是否发生过替换时，用 `p` 观察或结合 `t` 分支。

## 自测

- 把一行里的所有 `foo` 换成 `bar`。
- 只替换每行的第二个 `foo`。
- 给匹配到的数字加上方括号。
- 把 `key=value` 中的值改成 `new`，保留键名。
- 把 `姓 名` 改成 `名, 姓`。
- 解释 `echo 'a b' | sed 's/ /,/2'` 的输出。

参考答案：

```bash
sed 's/foo/bar/g' file
sed 's/foo/bar/2' file
sed -E 's/[0-9]+/[&]/g' file
sed -E 's/^(key=).*/\1new/' file
sed -E 's/^([A-Za-z]+) ([A-Za-z]+)$/\2, \1/' file
```

最后一条：一行里只有一个空格，第二个匹配不存在，所以没有发生替换，输出仍是 `a b`。
