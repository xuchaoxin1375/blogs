`sed` 用正则表达式回答两个问题：

- **地址**里的正则：这一行要不要处理？
- **`s` 命令**里的正则：这一行里哪一段文本要被替换？

正则默认使用 **基本正则表达式**(Basic Regular Expression, BRE)；加 `-E`（GNU 也可用 `-r`）后使用 **扩展正则表达式**(Extended Regular Expression, ERE)。两种方言的元字符不同，混用是初学者最常见的错误来源。

这一篇先讲 BRE/ERE 的差异，再讲字符类、锚点、转义和分隔符。读完应该能看懂大多数 `sed` 正则，并能判断一条正则为什么匹配不到。

## BRE 与 ERE：先选方言

BRE 和 ERE 都能表达“分组、重复、或”等概念，区别在于哪些字符需要反斜杠。

| 目标 | BRE 写法 | ERE 写法 |
| --- | --- | --- |
| 分组 | `\(abc\)` | `(abc)` |
| 或 | <code>a\&#124;b</code> | <code>a&#124;b</code> |
| 零次或一次 | `a\?` | `a?` |
| 一次或多次 | `a\+` | `a+` |
| 恰好 n 次 | `a\{3\}` | `a{3}` |
| n 到 m 次 | `a\{2,4\}` | `a{2,4}` |
| 至少 n 次 | `a\{2,\}` | `a{2,}` |

同一件事用两种方言写：

```shell
$ echo 'aaa' | sed 's/a\+/X/'
X
$ echo 'aaa' | sed -E 's/a+/X/'
X
```

```shell
$ echo 'cat dog' | sed 's/\(cat\|dog\)/X/g'
X X
$ echo 'cat dog' | sed -E 's/(cat|dog)/X/g'
X X
```

### 为什么推荐 -E

- `-E` 的写法更接近 Python、JavaScript、PCRE 等常见正则，少一层反斜杠。
- GNU sed 和 BSD/macOS sed 都支持 `-E`，可移植性比 GNU 专有的 `-r` 更好。
- 只有需要兼容很老的系统时，才优先考虑 BRE 的 `\+`、`\|` 写法。

GNU sed 也接受 `-r`，它和 `-E` 等价；新脚本统一写 `-E` 即可。

### 字面量字符的写法

在 BRE 里，`(`、`)`、`+`、`?`、`|`、`{`、`}` 默认是普通字符，要表示特殊含义才加反斜杠。反过来，在 ERE 里它们是特殊字符，要匹配字面量通常要转义：

```shell
$ echo '(a)' | sed 's/(a)/X/'
X
$ echo '(a)' | sed -E 's/\(a\)/X/'
X
```

跨平台时，转义非特殊字符的行为不总是有保证。更稳妥的写法是把字面量放进方括号，例如用 `[+]` 匹配加号、用 `[(]` 匹配左括号。

## 字符与量词

### 点号

`.` 匹配任意一个字符。默认情况下，如果模式空间里包含换行符（例如用 `N` 把两行合并了），`.` 也可以匹配这个换行符：

```shell
$ printf 'a\nb\n' | sed 'N;s/a.b/X/'
X
```

加 `M` 标志后，`.` 不再匹配换行符，`^` 和 `$` 也会分别匹配内嵌换行前后的位置：

```shell
$ printf 'a\nb\n' | sed 'N;s/a.b/X/M'
a
b
```

多行模式的细节见 [替换命令的 M 标志](04-替换命令s@详解.md#标志)。

### 星号与加号

- `*`：前一个字符出现零次或多次。
- `+`：前一个字符出现一次或多次（BRE 写 `\+`，ERE 写 `+`）。
- `?`：前一个字符出现零次或一次（BRE 写 `\?`，ERE 写 `?`）。

这些表示重复次数的符号统称 **量词**(quantifier)。

```shell
$ echo 'color colour' | sed -E 's/colou?r/COLOR/g'
COLOR COLOR
$ echo 'aaa' | sed -E 's/a+/X/'
X
$ echo 'b' | sed -E 's/a*/X/'
Xb
```

`a*` 可以匹配空字符串，所以 `s/a*/X/` 在 `b` 前面插入了一个 `X`。这是“零次”含义带来的常见结果，不是错误。

### 方括号与字符类

方括号表示“其中任意一个字符”：

```shell
$ echo 'cat cut cot' | sed -E 's/c[auo]t/X/g'
X X X
$ echo 'cat cut cot' | sed -E 's/c[^au]t/X/g'
cat X cot
```

常用 POSIX **字符类**(character class)：

| 写法 | 含义 |
| --- | --- |
| `[[:alpha:]]` | 字母 |
| `[[:digit:]]` | 数字 |
| `[[:alnum:]]` | 字母或数字 |
| `[[:space:]]` | 空白字符（空格、制表符、换行等） |
| `[[:blank:]]` | 空格和制表符 |
| `[[:upper:]]` / `[[:lower:]]` | 大写 / 小写字母 |
| `[[:punct:]]` | 标点符号 |
| `[[:xdigit:]]` | 十六进制数字 |

组合用法：

```shell
$ printf 'a1 B2\n' | sed -E 's/[[:alpha:]][[:digit:]]/X/g'
X X
$ printf 'a b\n' | sed -E 's/[^[:space:]]/X/g'
X X
```

方括号里的规则和普通正则稍有不同：

- `]` 要放在第一位才表示字面量，例如 `[]a]`。
- `-` 放在最后或转义才表示字面量，例如 `[a-]`。
- `^` 放在第一位表示取反；放在其他位置是普通字符。
- `.`、`*`、`+` 等在里面通常是普通字符。

### 分组与反向引用

分组把一部分正则括起来，既可以对整组加量词，也可以在替换里用 `\1`、`\2` 引用。这种引用叫 **反向引用**(backreference)：

```shell
$ echo 'abab' | sed -E 's/(ab)\1/X/'
X
$ echo 'a-b' | sed -E 's/(a)-(b)/\2-\1/'
b-a
```

BRE 里分组要写 `\(...\)`：

```shell
$ echo 'a-b' | sed 's/\(a\)-\(b\)/\2-\1/'
b-a
```

替换侧的 `\1` 写法在两种方言里相同；分组语法不同。详见 [替换命令 s](04-替换命令s@详解.md#1-到-9分组引用)。

## 锚点与边界

### 行首、行尾

`^` 和 `$` 这类只匹配位置的符号叫 **锚点**(anchor)。

- `^`：行首（更准确地说，模式空间开头）。
- `$`：行尾（模式空间结尾）。

```shell
$ printf 'ERROR\nprefix ERROR\n' | sed -n '/^ERROR$/p'
ERROR
```

`/ERROR/` 会匹配第二行，`/^ERROR$/` 只匹配整行就是 `ERROR` 的行。

### 单词边界

GNU sed 支持：

- `\<`：单词开头。
- `\>`：单词结尾。
- `\b`：单词边界（开头或结尾）。
- `\B`：非单词边界。

```shell
$ echo 'cat scatter cat.' | sed -E 's/\bcat\b/DOG/g'
DOG scatter DOG.
```

`\b`、`\B` 是 GNU 扩展；BSD/macOS sed 对它们的支持不一致。有些实现也支持 `\<`、`\>`，但跨平台最稳妥的写法是用字符类显式写出边界：

```shell
$ echo 'cat scatter' | sed -E 's/(^|[^[:alnum:]_])cat([^[:alnum:]_]|$)/\1DOG\2/g'
DOG scatter
```

### GNU 的快捷转义

GNU sed 还支持：

| 写法 | 含义 | 可移植替代 |
| --- | --- | --- |
| `\w` | 单词字符（字母、数字、下划线） | `[[:alnum:]_]` |
| `\W` | 非单词字符 | `[^[:alnum:]_]` |
| `\s` | 空白字符 | `[[:space:]]` |
| `\S` | 非空白字符 | `[^[:space:]]` |

这些写法在 GNU sed 里很好用，但 BSD/macOS sed 不一定支持。写跨平台脚本时，优先用 POSIX 字符类。GNU 还提供缓冲区首尾锚点，多行模式下与 `^`、`$` 的行为不同；普通单行场景用 `^`、`$` 就够了。

### 不支持的常见写法

`sed` 使用的是 POSIX 正则，不是 PCRE，以下写法通常不支持：

- `\d`、`\D`：用 `[[:digit:]]`、`[^[:digit:]]`。
- 前瞻/后顾：`(?=...)`、`(?<=...)`。
- 非捕获分组：`(?:...)`。
- 懒惰量词：`*?`、`+?`。

如果正则里出现这些写法，先怀疑方言不对，而不是文本有问题。

## 转义：两层要分清

写 `sed` 正则时，至少有两层转义：

- **shell 层**：单引号里的内容原样传给 `sed`；双引号里 `$`、反引号、反斜杠可能被 shell 处理。
- **sed 正则层**：`.`、`*`、`[`、`]`、`\`、`^`、`$` 等有特殊含义，需要时加 `\`。

### 匹配字面量

```shell
$ echo 'a.b' | sed 's/a\.b/X/'
X
$ echo 'a*b' | sed 's/a\*b/X/'
X
$ echo 'a\b' | sed 's/a\\b/X/'
X
```

最后一条在单引号里写 `a\\b`：shell 原样传递两个反斜杠，`sed` 正则把 `\\` 解释为一个字面反斜杠。

### 匹配斜杠

默认分隔符是 `/`，正则里的 `/` 要写成 `\/`：

```shell
$ echo '/usr/local/bin' | sed 's/\/usr\/local/\/opt/'
/opt/bin
```

更省事的办法是换分隔符，下一节说明。

### 替换侧的转义

替换文本里的 `&` 表示“整个匹配”，`\1` 表示分组。要输出字面量 `&`，写成 `\&`；要输出字面反斜杠，写成 `\\`：

```shell
$ echo 'a&b' | sed 's/&/\&/'
a&b
$ echo 'a&b' | sed 's/&/[&]/'
a[&]b
```

第二条命令里 `[&]` 的 `&` 仍然代表整个匹配，所以结果是 `a[&]b`；如果只想输出字面量 `&`，写 `[\&]` 或 `\&`。

## 分隔符与转义

### s 命令的分隔符

`s` 命令的完整形式是：

```bash
s/正则/替换/标志
```

第一个字符（这里是 `/`）是 **分隔符**(delimiter)。它可以是任意一个不冲突的字符，整条命令里保持一致：

```shell
$ echo '/usr/local/bin' | sed 's|/usr/local|/opt|'
/opt/bin
$ echo 'a/b/c' | sed 's,/,-,g'
a-b-c
$ echo 'a@b@c' | sed 's@a@X@'
X@b@c
```

规则：

- 分隔符不能是反斜杠或换行符。
- 正则或替换里出现分隔符本身时，要用 `\` 转义，或者换一个分隔符。
- 选一个不会出现在内容里的字符最省事；路径常用 `|`、`#`，URL 常用 `#` 或 `@`。

需要转义的例子：

```shell
$ echo '/usr/loc|al/bin' | sed 's|/usr/loc\|al|/opt|'
/opt/bin
```

### y 命令也可以换分隔符

`y` 命令做逐字符转换，同样支持自定义分隔符：

```shell
$ echo abc | sed 'y,abc,def,'
def
```

`y` 的源字符和目标字符长度必须相同，否则会报错：

```shell
$ echo abc | sed 'y/abc/de/'
sed: -e expression #1, char 9: strings for `y' command are different lengths
```

### 地址里的自定义分隔符

地址里的正则默认用 `/` 包围。要换分隔符，必须在开头加一个反斜杠：

```shell
$ printf '/usr/local/bin\n/opt/bin\n' | sed -n '\|/usr/local|p'
/usr/local/bin
```

等价的写法：

```shell
sed -n '/^\/usr\/local/p' file
sed -n '\%^/usr/local/%p' file
sed -n '\;^/usr/local/;p' file
```

三条都表示“打印以 `/usr/local/` 开头的行”。第二种和第三种分别用 `%`、`;` 作分隔符，开头都需要 `\`。

在范围地址里也可以使用：

```shell
$ printf 'a\n/etc/x\nb\n/end/\nc\n' | sed '\|/etc/|,\|/end/|d'
a
c
```

## 大小写与多行模式

### I：忽略大小写

在 `s` 命令的结束分隔符后加 `I`（或 `i`），匹配时忽略大小写：

```shell
$ echo 'Error' | sed 's/error/ok/I'
ok
```

地址上的写法见 [正则地址](02-地址@选择要处理的行.md#忽略大小写)。

### M：多行模式

`M`（或 `m`）启用 **多行模式**(multiline mode)，让 `^` 和 `$` 除了匹配整个模式空间的开头/结尾，还匹配内嵌换行前后的位置：

```shell
$ printf 'a\nb\n' | sed 'N;s/^/X/gM'
Xa
Xb
$ printf 'a\nb\n' | sed 'N;s/^/X/g'
Xa
b
```

`M` 还让 `.` 不再匹配换行符。这个标志在 `N` 合并多行后做逐行替换时很有用，详见 [替换命令的标志](04-替换命令s@详解.md#标志)。

## 常用正则示例

下面几个例子都只做“简化匹配”，不保证覆盖所有合法格式；需要严格校验时，用专门的解析器。

```shell
# 把 IPv4 形状的字符串替换掉（不校验每段范围）
$ echo 'ip=192.168.1.10' | sed -E 's/[0-9]+\.[0-9]+\.[0-9]+\.[0-9]+/[IP]/'
ip=[IP]

# 把 YYYY-MM-DD 形状的日期替换掉
$ echo 'date=2026-11-15' | sed -E 's/[0-9]{4}-[0-9]{2}-[0-9]{2}/[DATE]/'
date=[DATE]

# 取出双引号里的内容（简化版）
$ echo 'say "hello" now' | sed -E 's/.*"([^"]+)".*/\1/'
hello

# 交换两个单词
$ echo 'Ada Lovelace' | sed -E 's/^([A-Za-z]+) ([A-Za-z]+)$/\2, \1/'
Lovelace, Ada

# 删除简单的 HTML 标签（不处理嵌套和属性里的 >）
$ echo '<p>hello</p>' | sed -E 's/<[^>]*>//g'
hello
```

### 贪婪与“最左最长”

POSIX 正则采用 **最左最长**(leftmost-longest) 匹配，不是 PCRE 的回溯语义。看一个例子：

```shell
$ echo 'a123b456b' | sed -E 's/a.*b/X/'
X
$ echo 'a123b456b' | sed -E 's/a[0-9]*b/X/'
X456b
```

`a.*b` 会从最左边的 `a` 开始，尽可能匹配到最右边的 `b`，所以整串被替换。`a[0-9]*b` 只能匹配数字和 `b`，最左最长的结果是 `a123b`，剩下 `456b`。

这意味着：

- `.*` 通常“吃到行尾”，需要更精确时用 `[^"]*`、`[0-9]*` 这类排除型字符类。
- 不要指望用 `.*?` 变成懒惰匹配；`sed` 不支持。
- 需要“只替换到第一个分隔符”时，把 `.*` 换成 `[^分隔符]*`。

## 常见误区

- **把 `\d` 当数字**：`sed` 不支持，用 `[0-9]` 或 `[[:digit:]]`。
- **在 BRE 里直接写 `+`、`?`、`|`、`()`**：它们会被当成普通字符；要么加反斜杠，要么用 `-E`。
- **在 ERE 里忘了转义字面括号**：`(` 在 ERE 里是分组，匹配字面量要写 `\(` 或 `[(]`。
- **以为 `^`/`$` 永远只匹配整行**：在 `M` 模式下它们也匹配内嵌换行前后；默认模式下 `.` 可以匹配内嵌换行。
- **以为 `.*` 是“最短匹配”**：POSIX 是最左最长；需要短匹配时换字符类。
- **正则里出现 `/` 却忘了转义或换分隔符**：`s/\/usr\/local/.../` 能跑，但可读性差；用 `s|...|...|`。
- **把 shell 的引号问题当成正则问题**：先用 `printf '%s\n' "$script"` 或 `set -x` 看实际传参，再调正则。

## 自测

- 用 `-E` 写一条命令，把 `cat` 或 `dog` 替换成 `pet`。
- 匹配以 `#` 开头、后面可能跟空格的注释行。
- 把 `2026-11-15` 改成 `15/11/2026`。
- 删除行尾的一个或多个空格。
- 解释为什么 `echo b | sed -E 's/a*/X/'` 输出 `Xb`。

参考答案：

```bash
sed -E 's/(cat|dog)/pet/g' file
sed -n '/^#[[:space:]]*/p' file
sed -E 's/([0-9]{4})-([0-9]{2})-([0-9]{2})/\3\/\2\/\1/' file
sed -E 's/[[:space:]]+$//' file
```

最后一条：`a*` 可以匹配零个 `a`，所以在 `b` 前面插入了一个 `X`。
