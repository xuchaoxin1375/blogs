`sed` 的大部分命令都可以在字母前面加一个 **地址**(address)。地址回答的是“这条命令对哪些行生效”。没有地址时，命令对每一行都执行；写了地址，只有被选中的行才执行。

地址和替换命令里的正则容易混淆，先把边界分清：

- **地址**决定“处理哪些行”。例如 `/error/p` 只打印包含 `error` 的行。
- **`s` 命令里的正则**决定“替换这一行里的哪一段文本”。例如 `s/error/ERROR/` 只替换 `error` 这几个字符，不改动整行。

两者可以组合：`/error/s/error/ERROR/` 表示“只在包含 `error` 的行上，把 `error` 换成 `ERROR`”。

## 地址的基本写法

一条 `sed` 命令的形状是：

```bash
[地址]命令[参数]
```

例如：

```shell
$ seq 5 | sed -n '3p'
3
$ seq 5 | sed -n '3,4p'
3
4
$ seq 5 | sed -n '/[24]/p'
2
4
```

地址可以省略，也可以是一个行号、一个正则表达式、一个范围，或它们的组合。下面按类型说明。

## 行号地址

### 单行与最后一行

- `n`：第 n 行，行号从 1 开始。
- `$`：最后一行。

```shell
$ seq 5 | sed -n '2p'
2
$ seq 5 | sed -n '$p'
5
$ seq 5 | sed '$d'
1
2
3
4
```

注意 `$` 在地址里表示“最后一行”，不是正则里的“行尾”。要表示行尾，应该写在 `s` 命令的正则里：

```shell
$ printf 'a\nb\n' | sed '$s/$/ END/'
a
b END
```

第一行地址 `$` 选中最后一行，`s/$/ END/` 里的 `$` 才是行尾锚点。

### 行号范围

`addr1,addr2` 表示从匹配 `addr1` 的行开始，到匹配 `addr2` 的行结束，**包含两端**。这种写法叫 **范围地址**(address range)：

```shell
$ seq 6 | sed -n '2,4p'
2
3
4
$ seq 6 | sed -n '3,$p'
3
4
5
6
```

`1,$` 就是“所有行”，因为第 1 行到最后一行覆盖全部输入。

行号默认跨多个文件连续计数。`sed -i` 隐含 `-s`，每个文件的行号从 1 重新开始；显式加 `-s` 也有同样效果。多文件的行为见 [入门：多文件与 -s](01-入门@概念与调用方式.md#多文件与-s)。

## 正则地址

### 基本写法

把正则放在两个 `/` 之间，表示“匹配这个正则的行”：

```shell
$ printf 'ok\nERROR: disk\nok\n' | sed -n '/ERROR/p'
ERROR: disk
```

正则默认匹配行内的任意位置，不需要整行完全相等。要限定整行，自己加锚点：

```shell
$ printf 'ERROR\nprefix ERROR suffix\n' | sed -n '/^ERROR$/p'
ERROR
```

正则的完整语法见 [正则表达式](03-正则@BRE与ERE@分隔符.md)，这里先记住“地址选行、正则选文本”的分工。

### 自定义分隔符

当正则里包含大量 `/`（例如路径）时，可以用别的字符当分隔符。地址里的自定义分隔符要在开头加一个反斜杠：

```shell
$ printf '/usr/local/bin\n/opt/bin\n' | sed -n '\|/usr/local|p'
/usr/local/bin
```

`\|/usr/local|` 等价于 `/\/usr\/local/`，但不用逐个转义斜杠。分隔符的规则和 `s` 命令的写法见 [分隔符与转义](03-正则@BRE与ERE@分隔符.md#分隔符与转义)。

### 忽略大小写

在结束分隔符后加 `I`，正则匹配时忽略大小写：

```shell
$ printf 'Error\nERROR\nerror\n' | sed -n '/error/Ip'
Error
ERROR
error
```

`I` 是 GNU 扩展，FreeBSD/macOS 的 sed 也支持地址和替换命令上的 `I`；更老的实现可能不支持，跨平台时可改用 `[Ee][Rr][Rr][Oo][Rr]` 这类写法。

### 空正则复用上一次的正则

如果地址或 `s` 命令里的正则是空的（只写 `//`），会复用上一次执行到的正则：

```shell
$ printf 'abc abc\n' | sed -n '/abc/{s//X/;p}'
X abc
```

`/abc/` 先匹配整行，`s//X/` 复用 `abc` 作为要替换的模式。这个写法在“先选行、再在同一行里替换同一个模式”时很方便，但可读性不如把正则重写一遍；脚本里建议显式写出，避免后续修改时忘记“上一次的正则”是什么。

## 范围地址

### 基本语义

范围由两个地址组成，中间用逗号分隔：

```shell
$ printf 'BEGIN\na\nb\nEND\nc\n' | sed -n '/BEGIN/,/END/p'
BEGIN
a
b
END
```

规则细节比表面多一点：

- 范围包含起始行和结束行。
- 如果第二个地址是正则，**从起始行的下一行开始**检查结束条件；起始行本身不参与结束匹配。因此一个范围至少覆盖两行（除非输入提前结束）。
- 如果一直找不到结束地址，范围会一直持续到文件末尾。
- 如果第二个地址是行号，且小于或等于起始行号，则只选中起始行。
- 一个范围结束后，`sed` 会从下一行重新寻找起始地址，所以同一个文件里可以出现多个范围。

第二条规则容易让人意外。看一个起始行同时包含结束模式的例子：

```shell
$ printf 'BEGIN END\na\nb\n' | sed -n '/BEGIN/,/END/p'
BEGIN END
a
b
```

起始行 `BEGIN END` 已经包含 `END`，但结束正则不会在起始行上测试，所以范围继续到文件末尾。若希望“同一行就结束”，需要用 `0,/regex/` 或改用其他写法。

### 行号与正则混用

两个地址可以一个是行号、一个是正则：

```shell
$ seq 8 | sed -n '3,/6/p'
3
4
5
6
```

也可以反过来写 `正则,行号`，表示从匹配正则的行到指定行号。

### 0,/regex/：让结束正则从第一行开始检查

GNU sed 支持用 `0` 作为起始地址：

```shell
$ printf 'x\nx\n' | sed -n '0,/x/p'
x
$ printf 'x\nx\n' | sed -n '1,/x/p'
x
x
```

`0,/x/` 允许结束正则从第一行开始匹配，所以第一行就结束范围；`1,/x/` 把第一行当作起始行，结束正则从第二行开始找，于是输出两行。这个写法适合“从文件开头到第一个匹配为止”。

### addr,+N：从起始行往后多选 N 行

```shell
$ seq 10 | sed -n '6,+2p'
6
7
8
```

`6,+2` 表示第 6 行以及它后面的 2 行，共 3 行。起始地址也可以是正则：

```shell
$ printf 'a\nb\nc\nd\n' | sed -n '/b/,+2p'
b
c
d
```

### addr,~N：选到下一个 N 的倍数行

```shell
$ seq 10 | sed -n '6,~4p'
6
7
8
```

`6,~4` 表示从第 6 行开始，一直到下一个行号是 4 的倍数的行为止，所以结束在第 8 行。这个形式在“按固定块大小截取”时有用。

### first~step：步长地址

`first~step` 从第 `first` 行开始，每隔 `step` 行选一行。它是 GNU 扩展：

```shell
$ seq 6 | sed -n '1~2p'
1
3
5
$ seq 6 | sed -n '2~2p'
2
4
6
$ seq 6 | sed -n '0~2p'
2
4
6
```

按 GNU 手册的定义，选中的行满足“存在非负整数 n，使当前行号 = first + n × step”：

- `1~2`：1、3、5……
- `2~2`：2、4、6……
- `0~2`：2、4、6……（因为 0 + 1×2 = 2）
- `0~3`：3、6、9……
- `50~0`：只有第 50 行（step 为 0 时退化为单行）

初学者常把 `0~3` 理解成“从第 0 行开始每 3 行”，然后疑惑为什么不是 0、3、6。行号从 1 开始，不存在第 0 行，所以实际选中的是 3、6、9。更直观的写法是 `3~3` 或 `1~3`，按你要包含的首行来选。

### 范围地址速查

| 写法 | 含义 | 备注 |
| --- | --- | --- |
| `n` | 第 n 行 | 行号从 1 开始 |
| `$` | 最后一行 | 多文件时默认指最后一个文件 |
| `/re/` | 匹配正则的行 | 匹配行内任意位置 |
| `n,m` | 第 n 到第 m 行 | 包含两端 |
| `/re1/,/re2/` | 从匹配 `re1` 的行到匹配 `re2` 的行 | 结束正则从下一行开始检查 |
| `0,/re/` | 从第一行到第一个匹配 `re` 的行 | GNU 扩展 |
| `n,+N` | 第 n 行及其后 N 行 | GNU 扩展 |
| `n,~N` | 第 n 行到下一个 N 的倍数行 | GNU 扩展 |
| `first~step` | 从 first 开始每隔 step 行 | GNU 扩展 |

## 取反

在地址后加 `!`，表示对“不匹配该地址的行”执行命令。

```shell
$ printf 'keep\nremove\nkeep\n' | sed -n '/keep/!p'
remove
$ seq 5 | sed -n '2!p'
1
3
4
5
$ seq 5 | sed -n '2,4!p'
1
5
```

常见用法是“删除不包含某模式的行”，等价于只保留匹配行：

```shell
$ printf 'keep\nremove\nkeep\n' | sed '/keep/!d'
keep
keep
```

取反也可以和命令分组一起用：

```bash
sed '/^#/!{
  s/^/# /
}' file
```

这段脚本会给所有不以 `#` 开头的行加上 `# `，已经注释的行保持不变。

## 命令分组

一对花括号 `{ ... }` 可以把多条命令组合起来，让它们共享同一个地址。这种写法叫 **命令分组**(command grouping)：

```shell
$ printf 'plugins=(\n git\n z\n)\n' | sed -n '/^plugins=(/,/)/{=;p;}'
1
plugins=(
2
 git
3
 z
4
)
```

- 左花括号前写地址。
- 右花括号可以另起一行，也可以写成 `;}`（GNU 允许；为了兼容 BSD/macOS，建议把 `}` 单独放一行）。
- 花括号可以嵌套，用来表达更细的条件。

多行写法更适合阅读：

```bash
sed -n '/^plugins=(/,/)/{
  =
  p
}' file
```

分组里的 `=` 打印行号，`p` 打印内容，所以输出是“行号 + 内容”交替出现。

### 分组里使用 a、i、c 的注意点

`a`、`i`、`c` 的文本会一直读到行尾，不能像普通命令那样用分号分隔。把它们放进分组时，通常写成多行：

```bash
sed '/^plugins=(/,/)/{
  s/^/# /
}' file
```

如果确实要在分组里插入文本，建议把文本部分写成独立行，或拆成多个 `-e`。详细规则见 [插入、追加与整行替换](05-常用命令@增删改查与文件读写.md#插入追加与整行替换)。

## 常见误区

- **把 `$` 当成行尾**：地址里的 `$` 是最后一行；行尾锚点要写在 `s` 的正则里，如 `s/$/;/`。
- **以为 `/error/` 只匹配整行**：它匹配行内任意位置，`prefix ERROR suffix` 也会命中；需要整行时加 `^...$`。
- **以为范围结束正则会在起始行上测试**：不会，结束检查从下一行开始；需要第一行就结束时用 `0,/re/`。
- **忘了 `-n`**：`p` 在默认模式下会与自动打印叠加，输出重复；只想看选中行时加 `-n`。
- **把地址和 `s` 的正则混为一谈**：地址选行，`s` 选行内片段；两者可以写同一个正则，但作用范围不同。
- **多文件时误用 `$` 或行号**：默认是一条连续流；需要每个文件独立时用 `-s` 或 `-i`。

## 自测

- 打印第 2 到第 5 行。
- 打印从 `BEGIN` 到 `END` 的块，包含两端。
- 删除所有空行，但保留包含空格的行。
- 只对第 3 行执行替换 `old` → `new`。
- 给所有非注释行加 `# ` 前缀。

参考答案：

```bash
sed -n '2,5p' file
sed -n '/BEGIN/,/END/p' file
sed '/^$/d' file
sed '3s/old/new/' file
sed '/^#/!s/^/# /' file
```
