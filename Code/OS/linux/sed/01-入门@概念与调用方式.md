`sed` 是 **流编辑器**(Stream Editor)：它不打开交互式界面，而是从文件或管道读入文本，按你给的规则逐行处理，再把结果写到标准输出。加上 `-i` 时，它才会直接改文件。

这一篇先建立三个最关键的认识：**sed 在什么上面操作**、**一条命令由哪几部分组成**、**`-i` 到底做了什么**。后面的地址、正则和替换都建立在这三个认识上。

## sed 适合解决什么问题

最适合的场景有共同点：规则固定、文本量大、需要重复执行。

- 批量修改配置文件：把一批 `.conf` 里的 `old_api` 换成 `new_api`。
- 从命令输出或日志里筛出需要的行，或删掉噪声行。
- 在管道中做一次轻量转换：删空行、去行尾空格、合并行。
- 在安装脚本、构建脚本里自动注释或取消注释某一行。

不适合的场景也要提前知道：

- 需要按列计算、聚合、排序时，`awk` 更合适。
- 需要解析 JSON、YAML、CSV 的嵌套结构时，用对应的解析器，不要用正则硬拆。
- 需要复杂的分支、函数和数据结构时，`perl`、`python` 更可读。

`sed` 的强项是“按行选择 + 局部替换”，把它用在这个范围内最省事。

## 一个最小例子

假设要把一个文件里的 `hello` 换成 `world`：

```shell
$ printf 'hello sed\nhello world\n' | sed 's/hello/world/'
world sed
world world
```

这条命令包含三部分：

- `sed`：程序名。
- `'s/hello/world/'`：**脚本**(script)，这里只有一条替换命令 `s`。
- 管道送来的内容：输入。没有指定文件时，`sed` 从标准输入读。

`s/hello/world/` 默认只替换每行的**第一个** `hello`。要替换一行里的全部匹配，需要加 `g` 标志：

```shell
$ printf 'hello hello\n' | sed 's/hello/world/'
world hello
$ printf 'hello hello\n' | sed 's/hello/world/g'
world world
```

## 工作模型：一行、两个缓冲区、一个循环

### 一次循环发生了什么

`sed` 重复执行下面这套动作，直到输入结束：

1. 从输入读入下一行，去掉行尾换行符，放进 **模式空间**(pattern space)。
2. 按顺序执行脚本中所有地址匹配当前行的命令。
3. 如果没有用 `-n` 禁止 **自动打印**(auto-print)，也没有被 `d` 删除，就把模式空间的内容写到标准输出，并补一个换行符。
4. 清空模式空间，回到第一步读下一行。

“读一行、处理、输出、再读下一行”这一整套动作叫一个 **循环**(cycle)。理解循环之后，很多现象就能解释：为什么 `d` 后面的命令不执行、为什么 `n` 会提前读下一行、为什么 `q` 只输出到某一行。

用一个删除第二行的例子对照：

```shell
$ seq 3 | sed '2d'
1
3
```

- 第 1 行进入模式空间，地址 `2` 不匹配，`d` 不执行，自动打印 `1`。
- 第 2 行进入模式空间，地址 `2` 匹配，`d` 删除模式空间并立即开始下一个循环，所以这一行不会被自动打印。
- 第 3 行进入模式空间，不匹配，自动打印 `3`。

### 模式空间与保持空间

`sed` 有两个缓冲区：

| 缓冲区 | 作用 | 生命周期 |
| --- | --- | --- |
| **模式空间**(pattern space) | 当前正在处理的内容，所有普通命令都作用于它 | 每个循环重新装入一行，循环结束时清空 |
| **保持空间**(hold space) | 辅助存储，用来跨行暂存内容 | 从 `sed` 启动到结束一直存在，初始为空 |

普通命令只碰模式空间。只有 `h`、`H`、`g`、`G`、`x` 这几个命令会在两个空间之间搬运内容，具体用法见 [多行处理与流程控制](06-进阶@多行处理与流程控制.md)。

### 三个常见误解

- **“`sed` 默认会改文件”**：不会。默认只把结果写到标准输出，原文件不变；直接修改必须加 `-i`。
- **“`s/foo/bar/` 会替换整行”**：不会。它只替换匹配到的那一段文本；要替换整行用 `c` 命令，见 [插入、追加与整行替换](05-常用命令@增删改查与文件读写.md#插入追加与整行替换)。
- **“模式空间里永远只有一行”**：默认是一行，但 `N` 可以把下一行追加进来，`D` 又会只保留第一段。多行处理正是靠这两个命令，见 [进阶](06-进阶@多行处理与流程控制.md)。

## 调用语法

完整形式可以写成：

```bash
sed [选项] '脚本' [输入文件...]
```

各部分的作用：

| 部分 | 是否必需 | 说明 |
| --- | --- | --- |
| `sed` | 必需 | 程序名 |
| 选项 | 可选 | 改变读入、输出、正则方言或文件处理方式，如 `-n`、`-i`、`-E` |
| 脚本 | 通常必需 | 一条或多条 `sed` 命令，通常用单引号包住 |
| 输入文件 | 可选 | 可以给多个；不给或给 `-` 时从标准输入读 |

最常见的几种调用方式：

```bash
# 从文件读，结果写到终端
sed 's/foo/bar/' input.txt

# 从标准输入读，结果写到终端
cat input.txt | sed 's/foo/bar/'

# 从文件读，结果写到另一个文件（原文件不变）
sed 's/foo/bar/' input.txt > output.txt

# 直接修改原文件，并保留 .bak 备份
sed -i.bak 's/foo/bar/' input.txt
```

`input.txt` 放在脚本前面还是后面？脚本必须在输入文件之前。写成 `sed input.txt 's/foo/bar/'` 时，`input.txt` 会被当成脚本，`'s/foo/bar/'` 会被当成文件名，通常直接报错。

如果输入文件名以 `-` 开头（例如 `-myfile.txt`），`sed` 可能把它当成选项。用 `--` 表示“选项到此结束”，后面的参数按脚本和文件解释：

```bash
sed -- 's/foo/bar/' -myfile.txt
```

### 单引号还是双引号

脚本用单引号包住最省心，因为 shell 不会展开里面的 `$`、反引号和反斜杠：

```shell
$ name=world
$ echo hello | sed 's/hello/$name/'
$name
```

需要把 shell 变量的值放进脚本时，才用双引号：

```shell
$ name=world
$ echo hello | sed "s/hello/$name/"
world
```

双引号里 `$` 会被 shell 展开，反斜杠也可能被 shell 处理。脚本里既要变量、又要正则转义时，先确认 shell 实际传给了 `sed` 什么，再排查正则，能少走很多弯路。

## 脚本从哪里来

### 直接写在命令行

短脚本直接放在单引号里：

```bash
sed -n '2,4p' file.txt
```

### 用 -e 组合多条命令

`-e` 每出现一次就追加一段脚本，多段脚本按出现顺序拼接执行：

```shell
$ printf 'foo bar\n' | sed -e 's/foo/baz/' -e 's/bar/qux/'
baz qux
```

等价于用分号或换行把两条命令写在一起：

```shell
$ printf 'foo bar\n' | sed 's/foo/baz/; s/bar/qux/'
baz qux
```

### 用 -f 从文件读脚本

脚本较长、需要复用或需要保留注释时，写成 `.sed` 文件更清楚：

```bash
# 把脚本写进文件
cat > clean.sed <<'EOF'
# 删除空行
/^$/d
# 去掉行尾空白
s/[[:space:]]*$//
EOF

# 用 -f 读取脚本
sed -f clean.sed input.txt
```

`-e` 和 `-f` 可以混用，最终脚本按命令行中出现的顺序拼接。

### 使用 -e 或 -f 后，位置参数的含义会变

这是初学者最容易踩的坑之一。规则是：

- 没有 `-e`、`-f` 时，第一个非选项参数是脚本，后面的非选项参数是输入文件。
- 一旦用了 `-e` 或 `-f`，所有非选项参数都被当作输入文件。

所以下面这条命令不会执行两段脚本，而是把 `'s/c/d/'` 当成文件名：

```shell
$ printf 'a\n' > demo.txt
$ sed -e 's/a/b/' 's/c/d/' demo.txt
sed: can't read s/c/d/: No such file or directory
```

第二段脚本也必须用 `-e` 给出：

```shell
$ sed -e 's/a/b/' -e 's/c/d/' demo.txt
b
```

### 脚本里的注释与 #n

`#` 开始一条注释，直到行尾。脚本第一行的前两个字符如果是 `#n`，会强制启用 `-n`（禁止自动打印）。这个写法在旧的 sed 脚本里能看到，自己写脚本时更推荐显式写命令行选项 `-n`。

## 常用选项

先掌握最常用的几个，其余按需查。

| 选项 | 作用 | 初学者最需要记住的点 |
| --- | --- | --- |
| `-n` | 禁止自动打印模式空间 | 常与 `p` 搭配，只输出明确要求打印的行 |
| `-e 脚本` | 追加一段脚本 | 用了它之后，所有非选项参数都当输入文件 |
| `-f 文件` | 从文件读取脚本 | 适合较长或需要复用的脚本 |
| `-i[后缀]` | 就地编辑文件 | 直接改原文件；后缀用于备份；细节见下一节 |
| `-E` / `-r` | 使用扩展正则表达式(ERE) | 推荐统一用 `-E`，更易读、更可移植 |

### -n：只输出你要求的内容

默认情况下，每一行处理完都会自动打印。`-n` 关闭这个行为，只有显式执行 `p` 才会输出：

```shell
$ seq 3 | sed '2p'
1
2
2
3
$ seq 3 | sed -n '2p'
2
```

第一条命令里，第 2 行先被 `p` 打印一次，循环结束时又被自动打印一次，所以出现两个 `2`。这也是“为什么我的输出重复了”的常见原因。

### -E：换成扩展正则

基本正则(BRE)里，`+`、`?`、`|`、`()`、`{}` 要加反斜杠才有特殊含义；扩展正则(ERE)里直接写即可：

```shell
$ echo 'aaa' | sed 's/a\+/X/'
X
$ echo 'aaa' | sed -E 's/a+/X/'
X
```

两种写法都对，但 `-E` 通常更接近你在其他语言里见到的正则。GNU sed 和 BSD/macOS sed 都支持 `-E`，写跨平台脚本时优先用它。

### 其他选项

| 选项 | 作用 |
| --- | --- |
| `-s` / `--separate` | 把多个输入文件当作独立文件：行号、`$`、范围都不跨文件 |
| `-z` / `--null-data` | 用 NUL 字节而不是换行符分隔记录，常配合 `find -print0`、`sort -z` |
| `-u` / `--unbuffered` | 尽量减少缓冲，适合 `tail -f` 这类实时输入 |
| `-l N` | 设置 `l` 命令换行显示的长度，`0` 表示不换行 |
| `--debug` | 打印规范化后的脚本，并逐条显示执行过程 |
| `--posix` | 关闭 GNU 扩展，按 POSIX 行为运行 |
| `--sandbox` | 沙箱模式，禁用 `e`、`r`、`w` 等能访问外部文件的命令 |
| `--follow-symlinks` | 配合 `-i`，修改符号链接指向的目标，而不是替换链接本身 |
| `-b` / `--binary` | 二进制模式；只在区分文本/二进制的平台（如 Windows、Cygwin）生效 |
| `--help`、`--version` | 查看帮助和版本 |

`-z` 的一个例子：

```shell
$ printf 'a\0b\0' | sed -z 's/a/X/' | od -c
0000000   X  \0   b  \0
0000004
```

普通模式下 `sed` 按换行符切行；`-z` 改成按 NUL 切分，所以整个 `a\0b\0` 里的 `a` 被替换，NUL 保留。

## 就地编辑与备份

### -i 做了什么

`-i` 是 **就地编辑**(in-place editing)，不是“边读边写同一个文件”。GNU sed 的做法是：

1. 创建一个临时文件；
2. 把处理结果写到临时文件；
3. 处理结束后，用临时文件替换原文件；
4. 如果给了备份后缀，先把原文件改名成备份，再完成替换。

这带来两个直接后果：

- 处理过程中原文件仍然完整，即使命令中途失败，也不容易得到半个文件；但临时文件需要磁盘空间。
- `-i` 会 **隐含 `-s`**：多个文件按独立文件处理，行号、`$` 和范围不跨文件。

### 不备份、加后缀、加前缀

```shell
# 直接覆盖，不留备份
sed -i 's/foo/bar/' file.txt

# 保留 file.txt.bak
sed -i.bak 's/foo/bar/' file.txt

# 后缀里带 *：* 会被替换成当前文件名（GNU）
# 结果得到 bak_file.txt，相当于加了前缀
sed -i'bak_*' 's/foo/bar/' file.txt
```

GNU sed 只要使用了备份后缀，即使没有任何行被修改，也会生成备份文件：

```shell
$ printf 'abc\n' > same.txt
$ sed -i.bak 's/zzz/yyy/' same.txt
$ ls same.txt*
same.txt  same.txt.bak
```

### 警告：-i 不要和 -n 随意组合

`-n` 禁止自动打印，`-i` 又把输出写回文件。两者组合时，如果没有为每一行显式执行 `p`，临时文件就是空的，替换后原文件也会变成空文件：

```shell
$ printf 'foo\n' > danger.txt
$ sed -ni 's/foo/bar/' danger.txt
$ wc -c < danger.txt
0
```

这不是 bug，而是两个选项作用的直接结果。要么去掉 `-n`，要么确保脚本对每一行都有明确的输出路径；不确定时先不加 `-i`，把结果打到终端确认。

### 警告：-i 的可选参数会吃掉后面的选项字母

`-i` 的后缀是可选的，所以 `-i` 后面紧跟的短选项会被当成后缀：

```shell
# 正确：-E 和 -i 分开，-i 不带备份后缀
sed -Ei 's/foo/bar/' file.txt

# 危险：等价于 --in-place=E，会生成 file.txtE 备份
sed -iE 's/foo/bar/' file.txt
```

写多个短选项时，把 `-i` 放在最后，或者把 `-i` 和它的后缀单独写清楚。

### 符号链接与 macOS 的差异

- GNU sed 的 `-i` 默认会替换符号链接本身，而不是修改它指向的文件；需要改目标时加 `--follow-symlinks`。
- macOS 自带的 BSD sed 要求 `-i` 必须带一个参数，不备份也要写空字符串：`sed -i '' 's/foo/bar/' file`。直接写 `sed -i 's/foo/bar/' file` 会报错。详见 [跨平台差异](08-排错@编码控制字符与跨平台差异.md#gnu-与-bsdmacos-的主要差异)。

## 多文件与 -s

默认情况下，`sed` 把多个输入文件看成一条连续的长流。行号连续累加，`$` 只指最后一个文件的最后一行，范围也可以跨文件：

```shell
$ printf 'a\nb\n' > one.txt
$ printf 'c\nd\n' > two.txt
$ sed -n '=' one.txt two.txt
1
2
3
4
$ sed -n '$p' one.txt two.txt
d
```

加 `-s` 后，每个文件独立处理：

```shell
$ sed -s -n '=' one.txt two.txt
1
2
1
2
$ sed -s -n '$p' one.txt two.txt
b
d
```

`-i` 隐含 `-s`，所以 `sed -i` 处理多个文件时，每个文件的行号都从 1 开始。

## 退出状态

`sed` 的退出状态可以用于脚本判断：

| 状态码 | 含义 |
| --- | --- |
| `0` | 成功 |
| `1` | 命令、语法或正则表达式无效；或在 `--posix` 下使用了 GNU 扩展 |
| `2` | 有一个或多个输入文件打不开，但其他文件仍继续处理 |
| `4` | 发生 I/O 错误或严重的运行时错误，`sed` 立即中止 |

`q` 和 `Q` 还可以返回自定义退出码（GNU 扩展）：

```shell
$ printf 'a\nb\n' | sed 'q42'
a
$ echo $?
42
```

`q42` 表示处理完当前行后退出，并把 42 作为 `sed` 的退出码；`Q42` 则不打印当前模式空间。

## 第一次完整练习

下面用一份 nginx 配置片段，把匹配到的 `include` 行注释掉，并在修改前保留备份。

```bash
cat > demo.conf <<'EOF'
# demo.conf
include /www/server/nginx/conf/cf-realip.conf;

# 仅特殊解析服务器使用
# include real_cdn_ip.conf;
EOF

# 先确认能匹配到哪一行
sed -n '\|include /www/.*/cf-realip.conf;|p' demo.conf

# 原地修改，保留 demo.conf.bak
sed -i.bak '\|include /www/.*/cf-realip.conf;| s/^/# /' demo.conf

# 对比修改前后
diff -u demo.conf.bak demo.conf
```

预期结果：

```shell
$ diff -u demo.conf.bak demo.conf
--- demo.conf.bak
+++ demo.conf
@@ -1,5 +1,5 @@
 # demo.conf
-include /www/server/nginx/conf/cf-realip.conf;
+# include /www/server/nginx/conf/cf-realip.conf;

 # 仅特殊解析服务器使用
 # include real_cdn_ip.conf;
```

这条命令里有两个新东西：

- `\|regex|` 是自定义分隔符的地址，用来避免在包含 `/` 的路径里大量转义。规则见 [分隔符](03-正则@BRE与ERE@分隔符.md#分隔符与转义)。
- `s/^/# /` 只替换行首的空位置，相当于在行首插入 `# `，不是替换整行。

## 自测

先自己回答，再对照下面的答案。

- `seq 5 | sed -n '3,4p'` 输出什么？
- 为什么 `seq 3 | sed '2p'` 会输出两个 `2`？
- `sed -ni 's/a/b/' file` 为什么可能把文件清空？
- 在 macOS 上，`sed -i 's/a/b/' file` 为什么会报错？

答案：

- 输出 `3` 和 `4`；`-n` 关闭自动打印，只有地址选中的行被 `p` 打印。
- 第 2 行被 `p` 打印一次，循环结束时的自动打印又输出一次；加 `-n` 可去掉重复。
- `-n` 禁止自动打印，脚本里又没有 `p`，写回文件的临时内容为空，替换后原文件变成空文件。
- macOS 的 BSD sed 要求 `-i` 带参数；`-i` 后面的 `'s/a/b/'` 会被当成备份后缀，真正的脚本位置就错位了。应写成 `sed -i '' 's/a/b/' file`。
