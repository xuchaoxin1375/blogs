## 🧠 什么是 JOIN？

在关系型数据库中，数据通常存储在多个表中。为了获取完整的数据信息，我们经常需要将多个表“连接”在一起进行查询。这就是 `JOIN` 的作用。

---

## 🔗 JOIN 的基本语法

```sql
SELECT 表1.列名, 表2.列名...
FROM 表1
JOIN 表2 ON 表1.列名 = 表2.列名;
```

---

## ✅ 常见的 JOIN 类型

| 类型                              | 描述                                         |
| --------------------------------- | -------------------------------------------- |
| `INNER JOIN`                      | 内连接，只返回两个表中匹配的行               |
| `LEFT JOIN` / `LEFT OUTER JOIN`   | 左连接，返回左表所有记录，即使右表没有匹配项 |
| `RIGHT JOIN` / `RIGHT OUTER JOIN` | 右连接，返回右表所有记录，即使左表没有匹配项 |
| `FULL JOIN` / `FULL OUTER JOIN`   | 全连接，返回左右表的所有记录（MySQL 不支持） |
| `CROSS JOIN`                      | 交叉连接，返回两表的笛卡尔积                 |
| `SELF JOIN`                       | 自连接，把一个表与自身连接                   |

---

## 📚 示例说明

假设有两个表：

### 表1：`Customers`

| CustomerID | CustomerName |
| ---------- | ------------ |
| 1          | Alice        |
| 2          | Bob          |
| 3          | Charlie      |

### 表2：`Orders`

| OrderID | CustomerID | OrderAmount |
| ------- | ---------- | ----------- |
| 101     | 1          | 100         |
| 102     | 2          | 50          |
| 103     | 4          | 200         |

---

### 1️⃣ INNER JOIN（内连接）

只返回两个表中匹配的记录。

```sql
SELECT Customers.CustomerName, Orders.OrderAmount
FROM Customers
INNER JOIN Orders
ON Customers.CustomerID = Orders.CustomerID;
```

**结果：**

| CustomerName | OrderAmount |
| ------------ | ----------- |
| Alice        | 100         |
| Bob          | 50          |

---

### 2️⃣ LEFT JOIN（左连接）

返回左表所有记录，即使右表没有匹配项。

```sql
SELECT Customers.CustomerName, Orders.OrderAmount
FROM Customers
LEFT JOIN Orders
ON Customers.CustomerID = Orders.CustomerID;
```

**结果：**

| CustomerName | OrderAmount |
| ------------ | ----------- |
| Alice        | 100         |
| Bob          | 50          |
| Charlie      | NULL        |

---

### 3️⃣ RIGHT JOIN（右连接）

返回右表所有记录，即使左表没有匹配项。

```sql
SELECT Customers.CustomerName, Orders.OrderAmount
FROM Customers
RIGHT JOIN Orders
ON Customers.CustomerID = Orders.CustomerID;
```

**结果：**

| CustomerName | OrderAmount |
| ------------ | ----------- |
| Alice        | 100         |
| Bob          | 50          |
| NULL         | 200         |

---

### 4️⃣ FULL JOIN（全连接）

返回左表和右表的所有记录（MySQL 不支持，可以用 `LEFT + UNION + RIGHT` 实现）。

```sql
SELECT Customers.CustomerName, Orders.OrderAmount
FROM Customers
LEFT JOIN Orders ON Customers.CustomerID = Orders.CustomerID
UNION
SELECT Customers.CustomerName, Orders.OrderAmount
FROM Orders
LEFT JOIN Customers ON Customers.CustomerID = Orders.CustomerID;
```

**结果：**

| CustomerName | OrderAmount |
| ------------ | ----------- |
| Alice        | 100         |
| Bob          | 50          |
| Charlie      | NULL        |
| NULL         | 200         |

---

### 5️⃣ CROSS JOIN（交叉连接）

返回两个表的笛卡尔积（即所有组合）。

```sql
SELECT Customers.CustomerName, Orders.OrderAmount
FROM Customers
CROSS JOIN Orders;
```

**结果：**

| CustomerName | OrderAmount |
| ------------ | ----------- |
| Alice        | 100         |
| Alice        | 50          |
| Alice        | 200         |
| Bob          | 100         |
| Bob          | 50          |
| Bob          | 200         |
| Charlie      | 100         |
| Charlie      | 50          |
| Charlie      | 200         |

---

### 6️⃣ SELF JOIN（自连接）

一个表自己和自己连接，比如查找员工的上级。

```sql
SELECT e1.EmployeeName AS Employee, e2.EmployeeName AS Manager
FROM Employees e1
LEFT JOIN Employees e2
ON e1.ManagerID = e2.EmployeeID;
```

---

当然可以！下面是一个清晰的 **`SELF JOIN`（自连接）** 例子，帮助你理解它在实际场景中的应用。

---

## 🧠 什么是 SELF JOIN？

`SELF JOIN` 是一种特殊的 `JOIN`，它将一个表与它自己进行连接。通常用于查询具有层级关系或父子关系的数据，例如：

- 员工和其上级之间的关系
- 地区之间的归属关系（省、市、区）
- 分类的父子结构（如商品分类）

由于 SQL 中不能直接“连接自己”，所以需要为同一个表取两个不同的别名来进行连接。

---

#### 👨‍👩‍👧‍👦 示例：员工与经理的关系

#### 表结构：`Employees`

| EmployeeID | Name    | ManagerID |
| ---------- | ------- | --------- |
| 1          | Alice   | NULL      |
| 2          | Bob     | 1         |
| 3          | Charlie | 1         |
| 4          | David   | 2         |
| 5          | Eve     | 2         |

说明：

- 每个员工有一个 `ManagerID`，表示他的直属上级。
- `ManagerID` 的值对应的是 `EmployeeID`。
- Alice 是老板，没有上级（`ManagerID = NULL`）。

---

#### ✅ 使用 SELF JOIN 查询每个员工及其经理的名字

```sql
SELECT 
    e.Name AS EmployeeName,
    m.Name AS ManagerName
FROM 
    Employees e
LEFT JOIN 
    Employees m
ON 
    e.ManagerID = m.EmployeeID;
```

#### 📊 查询结果：

| EmployeeName | ManagerName |
| ------------ | ----------- |
| Alice        | NULL        |
| Bob          | Alice       |
| Charlie      | Alice       |
| David        | Bob         |
| Eve          | Bob         |

---

#### 📌 关键点解释：

- `e` 是 `Employees` 表的第一个别名，代表“员工”
- `m` 是 `Employees` 表的第二个别名，代表“经理”
- 连接条件是 `e.ManagerID = m.EmployeeID`
- 使用 `LEFT JOIN` 可以保留没有上级的员工（比如 Alice）

---

#### 💡 其他应用场景举例：

| 场景     | 自连接用途                         |
| -------- | ---------------------------------- |
| 分类树   | 查询父分类名称                     |
| 地址信息 | 查询城市所属省份                   |
| 订单系统 | 查询订单状态变更记录               |
| 社交网络 | 查询用户的好友关系（如果用一张表） |

#### 🧪 拓展练习题（可选）

假设你有如下表结构：

表：`Categories`

| CategoryID | CategoryName | ParentID |
| ---------- | ------------ | -------- |
| 1          | 电子产品     | NULL     |
| 2          | 手机         | 1        |
| 3          | 笔记本       | 1        |
| 4          | 苹果手机     | 2        |
| 5          | 华为手机     | 2        |

请写出一个 SQL 查询，显示每个分类及其父分类名称。

✅ 答案示例：

对于链接查询(包括自连接),习惯上用两个表名(即便实际上是同一个表),为同一个表Categories取两个别名(c,p)

```sql
SELECT 
    c.CategoryName AS ChildCategory,
    p.CategoryName AS ParentCategory
FROM 
    Categories c
LEFT JOIN 
    Categories p
ON 
    c.ParentID = p.CategoryID;
```

---

查询运行结果如下：

| ChildCategory | ParentCategory |
| ------------- | -------------- |
| 电子产品      | NULL           |
| 手机          | 电子产品       |
| 笔记本        | 电子产品       |
| 苹果手机      | 手机           |
| 华为手机      | 手机           |

## 🎯 使用场景总结

| 场景                     | 推荐 JOIN 类型 |
| ------------------------ | -------------- |
| 只要匹配的数据           | `INNER JOIN`   |
| 要保留左表全部数据       | `LEFT JOIN`    |
| 要保留右表全部数据       | `RIGHT JOIN`   |
| 要所有数据               | `FULL JOIN`    |
| 获取所有组合             | `CROSS JOIN`   |
| 查询层级结构（如上下级） | `SELF JOIN`    |

---

## 🛠 小贴士

- 多个表连接时可以使用多个 `JOIN`。
- 注意性能问题，大表连接可能会很慢。
- 为连接字段添加索引可以提高效率。
- `USING (column)` 简化写法适用于两个表有相同列名的情况。
