## 公网服务器上运行deepseek harness 并使用webui

**最适合的是 SSH 本地端口转发（`-L`）：WebUI 继续只监听服务器本机，你通过自己电脑的浏览器访问，不必把 WebUI 端口开放到公网。** 这正是上一条 SSH 隧道的实际用途。

以下按**官方 DeepSeek Harness（`dsh`）、直接运行在服务器上**说明。

### 服务器上：确认 WebUI 已启动

官方默认地址是 **`127.0.0.1:3080`**。如果已经启动了 WebUI，**跳过这一步，不要重复启动**；否则在服务器上执行：

```bash
npx @deepseek-ai/dsh web --no-open
```

如果你是源码安装，在仓库目录使用 `pnpm dsh web --no-open`。`--no-open` 表示不尝试在服务器上打开浏览器。

### 自己电脑上：建立 SSH 隧道

**另开一个本地终端，不是在已经登录服务器的远程终端里执行。** 本机装有 OpenSSH 即可使用下面的命令：

```bash
ssh -N -o ExitOnForwardFailure=yes -L 127.0.0.1:3080:127.0.0.1:3080 user@YOUR_SERVER_IP
```

把 `user` 和 `YOUR_SERVER_IP` 换成你的 SSH 用户名和服务器公网 IP；如果 SSH 使用其他端口，例如 `2222`，在 `ssh` 后加 `-p 2222`。这条命令的含义是：

| 参数部分                | 含义                         |
| ----------------------- | ---------------------------- |
| 第一个 `127.0.0.1:3080` | **你自己电脑**上的监听地址   |
| 第二个 `127.0.0.1:3080` | **服务器**上的 WebUI 地址    |
| `-N`                    | 只建立转发，不启动远程 shell |

**保持这个终端运行。连接后没有远程命令提示符是正常的。** `ExitOnForwardFailure=yes` 会在本地监听端口等转发设置失败时退出，但它不保证服务器上的 WebUI 已经可用。

### 自己电脑上：用浏览器打开启动链接

访问入口是 **`http://127.0.0.1:3080`**，不是服务器公网 IP。

**关键：首次访问，请复制服务器启动时 `dsh web:` 后面打印的完整 URL，到你自己电脑的浏览器打开。不要删掉其中的访问令牌（token）。** 当前官方文档说明，启动链接携带进程令牌，浏览器通过它取得认证 cookie；仅手动输入根地址可能未完成认证。上述本地、远端端口相同，因此默认启动链接可以原样使用。**不要把完整令牌链接公开分享。**

### 本地 `3080` 被占用怎么办？

只把**本地端口**改成 `13080`，远端仍然用 `3080`：

```bash
ssh -N -o ExitOnForwardFailure=yes -L 127.0.0.1:13080:127.0.0.1:3080 user@YOUR_SERVER_IP
```

然后把启动链接中的 `127.0.0.1:3080` 改成 **`127.0.0.1:13080`**，其余路径、参数和令牌全部保留。

---

**安全提醒：不建议为了打开页面直接把 Harness 暴露到公网。** 官方说明它仍处于开发预览、尚未经过安全审计，而且能够执行命令、访问文件及凭据；建议以最小权限在专用环境运行。

如果你是 **Docker 部署**，或者照做后仍打不开，贴出你的**启动命令和具体报错**即可；**API Key、token 请打码**。
