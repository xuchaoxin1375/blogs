## 一、查看分支（检查可用分支）

### 1. 本地分支
```bash
# 查看所有本地分支（当前分支带 *）
git branch

# 查看本地分支 + 最后一次提交信息
git branch -v

# 查看本地分支 + 上游分支关系
git branch -vv
```

## 二、从远程拉取分支

### 1. 拉取所有远程分支信息（不合并）
```bash
# 更新远程跟踪分支（不改变本地代码）
git fetch origin

# 获取所有远程仓库的更新
git fetch --all

# 获取并清理已删除的远程分支引用
git fetch --prune origin
# 或简写
git remote prune origin
```

### 2. 拉取并合并当前分支（git pull）
```bash
# 相当于 fetch + merge
git pull origin main

# 拉取当前分支的上游分支
git pull

# 使用 rebase 方式拉取（保持线性历史）
git pull --rebase origin main
```

### 3. 拉取远程的**所有**分支到本地
```bash
# 方法1：直接拉取所有（只更新远程跟踪，不创建本地分支）
git fetch --all

# 方法2：批量拉取并创建本地分支（慎用）
git branch -r | grep -v '\->' | while read remote; do 
    git branch --track "${remote#origin/}" "$remote" 2>/dev/null || true
done

# 方法3：更现代的方式（Git 2.0+）
git fetch --all
git pull --all  # 会尝试拉取所有分支（但只合并当前分支）
```

## 三、切换到指定分支

### 1. 切换到已存在的本地分支
```bash
# 切换到分支
git checkout feature/login

# 或使用 switch（Git 2.23+，推荐）
git switch feature/login
```

### 2. 创建并切换到新分支
```bash
# 基于当前分支创建并切换
git checkout -b feature/payment

# 使用 switch（推荐）
git switch -c feature/payment

# 基于指定分支创建
git checkout -b feature/payment develop
git switch -c feature/payment develop

# 基于远程分支创建
git checkout -b feature/payment origin/feature/payment
git switch -c feature/payment origin/feature/payment
```

### 3. 切换到远程分支（自动创建本地跟踪分支）
```bash
# 方法1：直接 checkout（自动创建同名本地分支）
git checkout origin/feature/login
# 或者
git checkout feature/login  # 如果本地没有，会自动创建并关联

# 方法2：显式创建跟踪分支
git checkout -b feature/login origin/feature/login

# 方法3：使用 switch（推荐）
git switch feature/login  # 如果本地没有，自动从远程创建

# 方法4：设置上游分支
git branch -u origin/feature/login
```

### 4. 切换到上次分支
```bash
# 回到上一个分支
git checkout -

# 或
git switch -
```

## 四、合并指定分支到主分支

### 1. 标准合并流程（最常用）

```bash
# 1. 切换到主分支
git checkout main
# 或
git switch main

# 2. 确保主分支最新
git pull origin main

# 3. 合并目标分支
git merge feature/payment

# 4. 如果有冲突，解决后提交
git add .
git commit -m "Merge feature/payment into main"

# 5. 推送到远程
git push origin main
```

### 2. 合并后删除分支
```bash
# 合并并删除本地分支
git merge feature/payment --delete
# 或分两步
git merge feature/payment
git branch -d feature/payment

# 删除远程分支
git push origin --delete feature/payment
# 或
git push origin :feature/payment
```

### 3. 使用 rebase 合并（保持线性历史）
```bash
# 1. 切换到目标分支
git checkout feature/payment

# 2. 变基到 main
git rebase main

# 3. 切回 main
git checkout main

# 4. 快速合并
git merge feature/payment

# 5. 推送
git push origin main
```

### 4. 合并策略选择

| 策略         | 命令                       | 场景                               |
| ------------ | -------------------------- | ---------------------------------- |
| **普通合并** | `git merge --no-ff`        | 保留分支历史（推荐）               |
| **快进合并** | `git merge --ff-only`      | 线性历史，无分叉                   |
| **压缩合并** | `git merge --squash`       | 合并为一个提交（用于功能分支合并） |
| **变基**     | `git rebase` + `git merge` | 保持干净的线性历史                 |

```bash
# 强制非快进合并（保留分支信息）
git merge --no-ff feature/payment

# 仅当可以快进时才合并
git merge --ff-only feature/payment

# 压缩合并（把多个提交压成一个）
git merge --squash feature/payment
git commit -m "Add payment feature"
```

### 5. 合并冲突处理
```bash
# 查看冲突文件
git status

# 手动编辑解决冲突后
git add <冲突文件>
git commit -m "Resolve merge conflict"

# 或使用工具
git mergetool  # 打开配置的合并工具

# 放弃合并
git merge --abort
```

## 五、完整工作流示例

### 场景：开发新功能并合并

```bash
# 1. 从主分支创建功能分支
git checkout main
git pull origin main
git checkout -b feature/user-profile

# 2. 开发过程中定期提交
git add .
git commit -m "Add user profile API"
git add .
git commit -m "Add profile UI"

# 3. 定期拉取主分支更新（避免最后冲突）
git fetch origin
git rebase origin/main  # 或 git merge origin/main

# 4. 推送功能分支到远程（备份/协作）
git push -u origin feature/user-profile

# 5. 功能完成，合并到主分支
git checkout main
git pull origin main
git merge --no-ff feature/user-profile

# 6. 推送并清理
git push origin main
git branch -d feature/user-profile
git push origin --delete feature/user-profile
```

## 七、常见问题处理

### 1. 不小心在错误分支上开发了
```bash
# 方法1：Cherry-pick（推荐）
git checkout feature/correct
git cherry-pick <commit-hash>  # 一个个搬

# 方法2：Stash 切换
git stash push -m "WIP on wrong branch"
git checkout feature/correct
git stash pop

# 方法3：Rebase（高级）
git rebase --onto feature/correct feature/wrong feature/wrong
```

### 2. 合并后想撤销
```bash
# 撤销合并但保留更改
git reset --hard HEAD~1
git reset --soft HEAD@{1}  # 保留改动

# 撤销合并并丢弃所有更改
git reset --hard HEAD~1
```

### 3. 删除远程已不存在的本地跟踪分支
```bash
# 查看并清理
git remote prune origin

# 删除所有已合并到 main 的本地分支（慎用）
git branch --merged main | grep -v "\*\|main" | xargs -n 1 git branch -d
```

## 八、推荐的分支管理规范

### 分支命名规范
```bash
feature/xxx      # 新功能
bugfix/xxx       # 修复bug
hotfix/xxx       # 紧急修复（直接基于main）
release/xxx      # 发布分支
chore/xxx        # 维护性工作
docs/xxx         # 文档
```

### 保护分支策略（GitHub/GitLab）
- **main/master**：保护分支，禁止直接推送
- **develop**：开发主线
- **feature/**：功能分支，完成后合并到 develop
- **hotfix/**：紧急修复，合并到 main 和 develop

### 标准 Git Flow
```bash
# 开发新功能
main ← develop ← feature/login

# 发布版本
main ← release/v1.0 ← develop

# 紧急修复
main ← hotfix/critical (同时合并到 develop)
```

---

**一句话总结**：
- 用 `git branch -a` 看所有分支
- 用 `git fetch --all` 拉取所有分支信息（不合并）
- 用 `git switch -c <分支名>` 创建并切换
- 用 `git merge --no-ff <分支名>` 合并到主分支（保留历史）
- 用 `git branch -d` 和 `git push --delete` 清理分支
