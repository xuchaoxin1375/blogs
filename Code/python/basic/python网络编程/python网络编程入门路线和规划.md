## 阶段详解

### 阶段 1：`socket` —— 打地基

| 项目             | 说明                                                         |
| ---------------- | ------------------------------------------------------------ |
| **学什么**       | TCP/UDP 通信、客户端-服务端模型、阻塞与非阻塞                |
| **为什么先学**   | 所有上层库都是对 socket 的封装。理解它就理解了网络通信的**本质** |
| **学到什么程度** | 能写一个 TCP 回显服务器 + 客户端即可，**不需要精通**         |
| **建议时间**     | 1～2 天                                                      |

```python
# 你的第一个目标：理解这 5 行在干什么
s = socket.socket(socket.AF_INET, socket.SOCK_STREAM)  # 创建 TCP 端点
s.connect(('example.com', 80))   # 三次握手
s.sendall(b'GET / HTTP/1.1\r\nHost: example.com\r\n\r\n')  # 发送原始 HTTP
print(s.recv(4096))              # 接收响应
s.close()                        # 断开
```

> 💡 做完这个练习你会深刻理解：**HTTP 不过是在 TCP 上发送特定格式的文本**。

---

### 阶段 2：`requests` + `Flask` —— 能干活

#### requests（客户端）

| 项目               | 说明                                                       |
| ------------------ | ---------------------------------------------------------- |
| **学什么**         | GET/POST、请求头、JSON、Session、错误处理                  |
| **为什么紧接着学** | 实际工作中 80% 的网络操作就是「调接口」，requests 一步到位 |
| **建议时间**       | 1～2 天                                                    |

```python
# 对比 socket 阶段的 5 行代码，同样的事只需 1 行
resp = requests.get('https://example.com')
```

> 从 socket 到 requests 的对比，让你直观感受**封装的价值**。

#### Flask（服务端）

| 项目                            | 说明                                   |
| ------------------------------- | -------------------------------------- |
| **学什么**                      | 路由、请求/响应、JSON API、模板渲染    |
| **为什么选 Flask 而非 FastAPI** | 同步思维更直觉，概念更少，出错更好排查 |
| **建议时间**                    | 2～3 天                                |

```python
# 5 行代码启动一个 Web 服务
from flask import Flask
app = Flask(__name__)

@app.route('/')
def hello():
    return {'msg': 'Hello World'}
```

> 🎯 **阶段 2 的里程碑**：用 Flask 写一个 API，再用 requests 调用它。客户端和服务端都是你写的——**闭环了**。

---

### 阶段 3：`asyncio` + `httpx` + `FastAPI` —— 进入现代化

| 先后 | 库             | 理由                                                     |
| :--: | -------------- | -------------------------------------------------------- |
|  ①   | `asyncio` 基础 | 理解事件循环、`async/await`，这是后续一切的前提          |
|  ②   | `httpx`        | 用法几乎等同 requests，但多了异步能力和 HTTP/2           |
|  ③   | `FastAPI`      | 在 Flask 基础上跨越到异步 + 类型驱动，提升不大但收益极高 |

```python
# 体会异步的威力：10 个请求并发，总耗时 ≈ 1 个请求
import asyncio, httpx

async def main():
    async with httpx.AsyncClient() as client:
        tasks = [client.get(f'https://httpbin.org/delay/1') for _ in range(10)]
        results = await asyncio.gather(*tasks)  # 并发执行

asyncio.run(main())  # 约 1 秒完成，而非 10 秒
```

> 💡 先在阶段 2 用同步方式做过同样的事，才能真正体会**异步解决了什么问题**。

## 为什么是这个顺序？三条核心理由

```
理由 1：从底向上，建立心智模型
━━━━━━━━━━━━━━━━━━━━━━━━━━━
  socket → 知道网络通信的本质
  requests → 知道 HTTP 协议的封装
  asyncio → 知道并发模型的原理
  
  跳过 socket 直接学 requests = 知其然不知其所以然
  跳过 requests 直接学 asyncio = 还没学走就想跑

理由 2：先同步后异步，降低认知负担
━━━━━━━━━━━━━━━━━━━━━━━━━━━
  同步代码：一行一行往下执行 → 符合直觉
  异步代码：事件循环 + 挂起恢复 → 需要新思维模型
  
  先用 requests/Flask 把"网络通信"搞明白
  再用 httpx/FastAPI 把"异步"搞明白
  一次只学一个新概念

理由 3：每个阶段都能产出可运行的成果
━━━━━━━━━━━━━━━━━━━━━━━━━━━
  阶段1 → TCP 聊天室小程序
  阶段2 → 一个完整的 REST API + 客户端调用
  阶段3 → 高并发爬虫 / 异步 Web 服务
  
  持续正反馈，不会"学了很久还什么都做不了"
```

## 极简路线图（一页总结）

```
  ┌──────────┐
  │  socket  │  ← 1-2天：理解本质，不求精通
  └────┬─────┘
       ▼
  ┌──────────┐   ┌───────┐
  │ requests │ + │ Flask │  ← 3-5天：能调能写，形成闭环
  └────┬─────┘   └───┬───┘
       ▼             ▼
  ┌──────────┐   ┌─────────┐
  │  httpx   │ + │ FastAPI │  ← 1-2周：进入异步世界
  └────┬─────┘   └───┬─────┘
       ▼             ▼
  ┌────────────────────┐
  │  按需：WS/gRPC/... │  ← 用到再学
  └────────────────────┘
```

> **最重要的一条**：每学一个新库，先问自己「它比上一个解决了什么新问题？」——带着问题学，效率最高。
