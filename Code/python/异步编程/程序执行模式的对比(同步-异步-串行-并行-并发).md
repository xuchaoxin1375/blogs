## abstract

在 Python 中，`asyncio` 追求的是 **“异步 + 并发”**，而 `multiprocessing` 追求的是 **“同步 + 并行”**。

- **同步**：发起一个操作后，**必须等它完成**，才能继续往下做。
- **异步**：发起一个操作后，**不用等它完成**，先去做别的，完成后再通知你。
- **串行**：多个任务**一个接一个**执行。
- **并行**：多个任务**同一时刻真正同时**执行。
- **并发**：多个任务**在一段时间内交替推进**，看起来像同时进行，不一定是真同时。

| 概念 | 关注点             | 含义                                           | 是否“同时” |
| ---- | ------------------ | ---------------------------------------------- | ---------- |
| 串行 | 执行顺序           | 一个任务完成后再做下一个                       | 否         |
| 同步 | 调用方式(执行机制) | 调用后要**等待结果**(独占执行流)               | 不一定     |
| 异步 | 调用方式(执行机制) | 调用后**不等待结果**(共享执行流)               | 不一定     |
| 并发 | 任务组织           | 多个任务在同一时间段内都在推进(通常是交替推进) | 不一定     |
| 并行 | 执行状态           | 多个任务在同一时刻执行                         | 是         |

异步的最大价值在于并发,即便是单线程也可以并发;

异步的强大之处，不在于它能让**一个**串行任务线变快，而在于它能让**成千上万个**串行任务在同一个线程里并发

## 常见组合

| **组合模式**    | **执行逻辑 (微观视角)**   | **调用方状态**                                     | **适用场景**                                             | **核心痛点**                                   |
| --------------- | ------------------------- | -------------------------------------------------- | -------------------------------------------------------- | ---------------------------------------------- |
| **同步 + 串行** | `A -> B -> C`             | **死等**。必须拿完结果才走。                       | 脚本工具、简单顺序逻辑。                                 | 简单但是效率最低，一个环节卡死全线崩溃。       |
| **同步 + 并行** | `A // B // C` (多核同时)  | **阻塞等全集**。主线程在 `join()` 处等待。         | CPU 密集型计算（如多个核心同时进行大型矩阵运算）。       | 开销比单线程异步大,并发能力不如异步。          |
| **异步 + 串行** | `A(挂起) -> B(挂起) -> C` | **非阻塞等顺序**。逻辑有依赖，但执行时不占死 CPU。 | 有先后顺序的 API 调用（如：登录后获取 Token 再查数据）。 | 虽然不阻塞，但总时长仍是各任务之和。           |
| **异步 + 并发** | `A, B, C` 同时发出请求    | **非阻塞等回调**。谁先好谁先回。                   | 高并发爬虫、Web 服务器、实时聊天应用。                   | 代码逻辑复杂度高（回调地狱或复杂的异常处理）。 |

### 异步串行

 **“异步串行”** 存在的意义，不在于缩短一组任务的**绝对执行时间**，而在于**提升整个系统(多任务线)的吞吐量和响应能力**。

> 在和同步串行相比,异步串行中的串行不是所有任务完全串行的情况下才有优势(存在互不干扰的多个任务线时);
>
> 例如代码分为多步骤主线任务和支线任务(主线和支线任务可以并发(交替推进));
>
> 主线任务的多个步骤之间有前后顺序,需要串行执行(但是代码要写成异步代码,否则支线任务就无法在主线任务等待的过程中执行)

释放调用者（主线程），避免“假死”

**同步串行**：主线程被死死卡住。如果是桌面软件或手机 App，用户会发现界面完全无法点击（假死）；如果是 Web 服务器，这个工作线程在等待期间无法接收任何新请求。

**异步串行**：在 `await` 等待期间，**主线程是自由的**。它可以去处理用户的点击事件、更新进度条，或者处理其他并发的任务。

| **特性**               | **同步串行 (Sync Serial)** | **异步串行 (Async Serial)**           |
| ---------------------- | -------------------------- | ------------------------------------- |
| **单组任务耗时**       | $T1 + T2$                  | $T1 + T2$                             |
| **主线程状态**         | 阻塞（卡死）               | **空闲（可处理其他事）**              |
| **系统能支撑的并发量** | 受限于线程数（极低）       | **受限于内存（极高）**                |
| **典型案例**           | 简单的 Python 打印脚本     | 手机 App 登录（先验证账号再获取头像） |

```python
import asyncio
import time

# 定义2个有顺序依赖的协程函数
async def step_1_async():
    await asyncio.sleep(1)  # 异步等待，释放 CPU
    print("【异步】验证成功，得到用户ID: 123")
    return 123


async def step_2_async(user_id):
    await asyncio.sleep(1)
    print(f"【异步】获取权限成功，用户 {user_id} 是管理员")

# 支线任务
async def other_task():
    """模拟在等待登录时，程序还能处理其他事情（如界面动画或接收消息）"""
    for i in range(4):
        print(f"  [后台] 正在处理其他小任务... {i}")
        await asyncio.sleep(0.5)


async def main_async():
    print("--- 异步流程开始 ---")
    start = time.perf_counter()

    # 我们通过 create_task 让直线任务 other_task 并发跑起来(而不是主线任务的登录验证)
    background_job = asyncio.create_task(other_task())

    # 关键点：这里的代码依然是串行的，必须等 1 完再跑 2
    uid = await step_1_async()
    await step_2_async(uid)

    await background_job  # 等待后台任务收尾
    print(f"--- 异步流程结束，总耗时: {time.perf_counter() - start:.2f}s ---")


asyncio.run(main_async())

```

上例中,支线任务中安排了有4个小任务,每个任务耗时0.5秒,总耗时共计2秒;

> 主线任务的两个步骤有顺序要求,第二个步骤要等待第一个步骤的结果,这看起来像是"同步"的特点;
>
> 但是为了让支线能够和主线并发运行,都要用异步的方式写;
>
> 但在等待这个顺序实现的过程中，不卡死整个程序，这才是 **“异步”** 的核心价值。

```text
 python .\async_serial.py         
--- 异步流程开始 ---
  [后台] 正在处理其他小任务... 0
  [后台] 正在处理其他小任务... 1
【异步】验证成功，得到用户ID: 123
  [后台] 正在处理其他小任务... 2
  [后台] 正在处理其他小任务... 3
【异步】获取权限成功，用户 123 是管理员
--- 异步流程结束，总耗时: 2.04s ---
```

可见主线任务和支线任务各自耗时约2秒的情况下,在异步模式运行下,总耗时约2秒,而不是完全串行(将会是4秒)

**异步串行**并没有缩短登录所需的 2 秒钟。

它的伟大之处在于：它把原本被浪费掉的、卡死的 2 秒钟，**还给了**程序的其他部分。

这就是为什么异步 Web 服务器能同时处理成千上万个请求，而同步服务器早早就把线程耗尽了。
