# 线程同步与锁的基本理论和概念

## 线程同步概述

线程同步是多线程编程中的核心概念，用于**协调多个线程对共享资源的访问，防止数据竞争和不一致的问题**。

当多个线程同时访问和修改共享数据时，如果没有适当的同步机制，可能会导致不可预测的结果。

### 为什么需要线程同步

1. **数据竞争**：多个线程同时读写共享数据时可能导致**数据不一致**
2. **竞态条件**：程序的行为依赖于**线程执行的相对时序**
3. **可见性问题**：一个线程对共享变量的修改可能对其他线程不可见

## 常见的同步机制

### 1. 互斥锁 (Mutex)

互斥锁是**最基本的同步机制**，用于**确保同一时间只有一个线程可以访问共享资源**。

**特点**：

1. 一个线程获取锁后，其他尝试获取该锁的线程会被阻塞
2. 释放锁后，其他线程才能获取
3. 防止多个线程同时进入临界区

**伪代码示例**：
```c
lock(mutex) {
    // 临界区代码
    // 访问共享资源
}
unlock(mutex);
```

### 2. 读写锁 (Read-Write Lock)

读写锁允许多个读操作同时进行，但写操作需要独占访问。

**特点**：
- 读锁：共享锁，多个线程可同时持有
- 写锁：独占锁，一次只允许一个线程持有
- 适合读多写少的场景

### 3. 条件变量 (Condition Variable)

条件变量用于线程间的通信，允许线程在某些条件不满足时挂起等待。

**典型使用模式**：
1. 获取互斥锁
2. 检查条件
3. 条件不满足时，等待条件变量（自动释放锁）
4. 条件满足或被唤醒后，重新获取锁
5. 执行操作
6. 释放锁

### 4. 信号量 (Semaphore)

信号量是一种计数器，用于控制对共享资源的访问。

**类型**：
- 二进制信号量：值只有0和1，类似于互斥锁
- 计数信号量：可以有多个许可

**操作**：
- P操作（wait/proberen）：获取许可，计数器减1
- V操作（signal/verhogen）：释放许可，计数器加1

### 5. 自旋锁 (Spinlock)

自旋锁是一种忙等待的锁，线程在获取锁失败时会不断尝试，而不是被挂起。

**适用场景**：
- 锁持有时间非常短
- 不希望线程被挂起（避免上下文切换开销）

## 同步问题与解决方案

### 1. 死锁 (Deadlock)

四个必要条件：
1. 互斥条件
2. 占有并等待
3. 非抢占条件
4. 循环等待条件

**预防策略**：
- 锁排序：所有线程按相同顺序获取锁
- 锁超时：尝试获取锁一段时间后放弃
- 死锁检测与恢复

### 2. 活锁 (Livelock)

线程不断改变状态但无法继续执行，类似于"过于礼貌"的线程。

### 3. 饥饿 (Starvation)

某些线程长时间无法获取所需资源。

## 最佳实践

1. **最小化临界区**：只将必要的代码放在锁内
2. **避免嵌套锁**：容易导致死锁
3. **使用高阶同步工具**：如并发集合、原子操作等
4. **考虑锁的粒度**：粗粒度锁简单但并发性低，细粒度锁复杂但并发性高
5. **优先使用不可变对象**：避免同步需求

## 现代同步机制

### 1. 原子操作

CPU提供的不可中断的指令，如CAS (Compare-And-Swap)

### 2. 无锁编程 (Lock-Free)

基于原子操作实现的数据结构和算法，避免显式锁的使用

### 3. 软件事务内存 (STM)

将数据库事务的概念引入内存操作

理解这些基本概念和机制是编写正确、高效多线程程序的基础。在实际应用中，应根据具体场景选择合适的同步策略。
